# E22 規格 v1（2026-11-12 使用者確認 Q1–Q4；先於實作與執行 commit）：同窗雙掛規則（H_i-D3 錨點矛盾）

> 2026-11-12。來源：E21-S0（`E21_relaxable_component_spec.md` §8 推論 3、§8.2）發現被攻陷之 DU 可把「只在錨點」之真 UE 加進自己的報表（攻擊 A3），C_i 不變（聯集不變）、D1 證據反而減少，目前只有 D2 偶然接住一部分（攻擊窗 D2 違反 0.227／0.554）。本規則補上此缺口。
> **主結果不變**：規則以旗標啟用（預設關閉），第四章凍結之註記與數字不受影響（檢查 E22-0）。

## 1. 規則代碼與層級

| 項目 | 定義 |
|---|---|
| 證據名稱 | **H_i-D3 錨點矛盾**（成員關係證據之第三項，與 D1、D2 並列） |
| 判定 | 窗 t 中，UE i 同時出現在 LTE 錨點（CellId 1）之報表與 mmWave cell j 之報表 → 對節點 j 記 `violated`，證據 = {矛盾之 IMSI 清單} |
| 歸屬 | 只歸屬於**報表含該 UE 之 mmWave 節點 j**（錨點為信任根，矛盾由 j 負責）；同窗多個 j 各自判定 |
| 規則代碼 | **`R1_D3_VETO`**，層級 **L1（硬否決）**，判定 **rejected**；於規則表中排在 `R1_D2_VETO` 之後 |
| 持續性 | 無（L = 1）：矛盾在單窗內即為確定事實；不跨窗繼承（每窗重判） |
| 融合順序 | severity 模式下自然取 rejected；first-match 模式下 `R1_CI_PENDING`（low-trust）會先返回，故 `EXPECTED_SEVERITY_DIFF` 須新增 (`R1_CI_PENDING`, `R1_D3_VETO`) |
| 啟用 | 環境變數 `ZT_D3=on`；預設 off（行為逐位不變） |

**為何選 L1 rejected**：與 D2 同類——是報表與信任根之間的**確定矛盾**，不是統計偏差；乾淨資料中為 0（§3）。若改為 L2 low-trust，在 restrict_annotated 下 A3 仍會被准入（只加註記），補不上缺口。

## 2. 適用條件（本規則只在此條件下成立）

- **成立之前提**：D-30 中 LTE 錨點**只回報 anchor-only 之 UE**——錨點報表所列 UE 與 mmWave 報表所列 UE 從不重疊。這是 ns-O-RAN MC 設定下 RLC 報表之**報表層級歸屬**（v11 4.8.1：「LTE-only」為報表層級、對應 mmWave 鏈路劣化），不是 3GPP 之一般性質。
- **不可外推**之情形：EN-DC split bearer 或其他使錨點與 mmWave 同時承載同一 UE 下行流量之設定；報表粒度或歸屬方式不同之實作；換手期間兩邊同時有流量之系統。在這些情形下本規則會在乾淨資料上觸發，**不得啟用**。
- **啟用前之部署檢查**：於乾淨校準期量測「錨點 ∩ mmWave」之 UE-窗數，**為 0 才啟用**（與 D2 之情境特定規則同一處理方式）。
- 1 秒窗內換手：D-30 中即使 UE 於窗內轉換，亦未出現雙掛（§3）；其機制**未由 ns-3 原始碼確認**，只有觀測。

## 5. 不在本規格範圍（列出供決定）

- **兩個 mmWave cell 同窗雙掛**（A4：宣稱 peer 之 UE）：乾淨資料亦為 0（§3），技術上可做同類規則；但**無法判斷誰在說謊**（兩個節點都不是信任根），歸屬給雙方會使誠實節點被一併否決。建議另案討論。
- E19 賽局環境：攻擊者只改延遲、成員關係證據預先計算，本規則不影響 E19／E21-S4 之結果，不需更新。
- A2（k-for-k 替換）：本規則無作用（假 ID 不在錨點報表），仍為盲點。

**判讀**
1. 在 D-30 之錨點語意下，D3 以**零乾淨誤拒**完全關閉 A3（任一准入政策、規則版或 B-off 皆漏放 0）。偵測率 1.0 為**依構造**之結果（A3 必然使同一 UE 同時出現於錨點與 j），其實證意義為「規則行為正確、乾淨資料不誤觸」，不是偵測能力之統計估計。
2. 對 E21 之影響：E21-S1／S3 中 B-off 之主要代價在 A3（0.42 → 0.75）；加入 D3 後 A3 之代價消失。B-off ＋ D3 之剩餘代價只在 ×0.6 與漂移（E21-S1：0.019 → 0.055、0.100 → 0.202），以及 E21-S4 待回答之學習型攻擊者。
