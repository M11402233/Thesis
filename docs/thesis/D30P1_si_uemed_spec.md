# D-30P1：S_i 改為 UE 層級（中位數）規格 v0（2026-11-22；事後修正，結果出來前寫定）

> 本規格是**看過 D-30P1 步 2 結果之後**才寫的修正，正文必須揭露為事後修正。
> 修正前的結果（cell 平均版）保留原樣，記錄於 `D30P1_step345_stop_record.md`，不得刪除或覆寫。

## 1. 背景（數字皆為腳本輸出）

- D-30P1 步 2（`d30p1_delay_percell`，r11 有效延遲樣本）：spatial 乾淨誤報 0.406、temporal 0.364、延遲 CV 中位數 1.486、E9b 校準後乾淨誤報 0.719（`~/zt_dev/decomp/delay_decomposition.json`，新機器）。
- 步 3–5 停在 `4e_fusion`：`delay_drift` 情境 z = 0.95 < τ_S，內建一致性檢查不符（見停止紀錄）。
- 原因分析（唯讀，2026-11-21／22）：
  - 延遲分佈（8 seed，percell）：中位數 8.4 ms、平均 1,437 ms、p99 25,273 ms、最大 290,768 ms；13.9 % 樣本 > 1 s。D-30P 同版本最大值為 4 ms。
  - seed 4200 之 UE 15（cell 4）與 UE 10（cell 5）整段 300 s 之下行 TB 損壞率 ≥ 95 %（SINR 約 −14 至 −40 dB、MCS 0），RRC 仍為已連線（NoAuto，無換手）。鏈路偶爾恢復時，RLC AM 之舊 PDU 一次送達；模式 1 沿用首次傳送時間戳，延遲即為卡住時間（數秒至數十秒）。
  - ns-3 之 RLC AM 達 `m_maxRetxThreshold`（= 5）時只寫 log，不通知上層、不丟棄（`src/lte/model/lte-rlc-am.cc:606–609`；TS 38.322 §5.3.2 規定須通知上層）。**待驗證假說（2026-11-22 使用者要求降級）**：尾巴與此處理有關；尚未證明因果，亦未核對上層處理路徑（見 §8）。
  - S_i 之 cell 代表值為該 cell 各 UE 延遲之**平均**，單一中斷 UE 即可支配；MAD 尺度只反映多數 UE（約 10 ms）。

## 2. 使用者決定（2026-11-22）

1. S_i 改成 UE 層級。
2. 中斷 UE 於資料層標記或排除。
3. 停住之步 3–5 作成紀錄。

## 3. 決定 1 之定義（本規格實作者）

- **cell 代表值**：cell j 於窗 k 之值 = 該 cell 當窗**各 UE 區間延遲之中位數**（原為平均）。UE 區間延遲本身不變（r11 有效樣本：ΔdelaySumEff ÷ ΔnEff）。
- 不變者：參照（同窗 peer cell 代表值之中位數）、尺度公式（各腳本原定義之 1.4826·MAD，套用於各自原本使用之量：xApp 之 `TrustAnchor` 仍用逐 UE 值；E9 族之 `global_scale` 用 cell 代表值）、τ_S = 4、MIN_PEER = 2、注入方式與參數、LOSO 摺法、C_i、H_i。
- 實作：`ZT_DELAY_SOURCE=percell_uemed`（commit ef72a88）。資料讀取同 `percell`；cell 代表值經 `interval_source.node_value`／`median_valid` 改為中位數。改動處：`interval_source.cell_delay_means`、`zt_kpm_xapp.verify_si`、`cv_interval.py`、`run_E11_transitions.py`（偽成員延遲與 S_i 判定）、`run_E11b_pulses.py`、`run_RQ3_decision_replay.py`（真實延遲）、`run_E21_S0_membership.py`、`run_E26_ci_collateral.py`。其餘 mode 走原式，逐位不變。
- 輸出目錄：`data/results/d30p1_delay_percell_uemed/`；回歸基準以 SETBASE=1 新建（註記「未經作者審閱」）。
- 事前已知之限制（腳本輸出，D-30P1 percell，16,414 個 (cell, 窗)）：有效 UE 數 1 者 6.1 %、2 者 19.6 %、3 者 31.3 %、≥ 4 者 43.0 %。**UE 數 ≤ 2 之 25.7 % 窗，中位數 = 平均，無抗離群效果。**

## 4. 決定 2 之驗證結果：建議暫不實作（待使用者確認）

以 `RxPacketTrace` 之 PHY 真值（8 seed、240 條 mmWave 連結 × 300 窗）檢查中斷判定能否乾淨定義：

| 項目 | 腳本輸出 |
|---|---|
| 連結-窗之平均 SINR < −8 dB（3GPP Qout 之常用近似） | 25.0 %（各 seed 19.0–32.9 %） |
| 至少一窗 SINR < −8 dB 之連結 | 218 ／ 240（91 %）；首次發生窗之中位數 = 第 6 窗 |
| 延遲 > 1 s 之樣本落在「從未失步」之連結 | 1 ／ 8,409 |

遮蔽規則（連結自失步窗起遮蔽，連續 hold 窗同步後解除）之結果：

| 規則 | 遮蔽之連結-窗 | 保留樣本 | 保留中 > 1 s | 保留中最大 |
|---|---|---|---|---|
| 不遮蔽 | 0 | 60,556 | 13.9 % | 290,768 ms |
| SINR < −8，hold 0 | 25.0 % | 53,402 | 9.5 % | 220,779 ms |
| SINR < −8，hold 3 | 41.3 % | 41,990 | 2.0 % | 24,500 ms |
| TB 損壞率 ≥ 0.5，hold 3 | 54.6 % | 32,588 | 0.4 % | 7,404 ms |
| 首次失步即永久釋放（RLF 無重新加入） | 82.8 % | 12,348 | 0.3 % | 2,812 ms |

判斷：
- 「少數中斷 UE」之前提只在 seed 4200 成立；8 seed 合計，中斷是普遍現象。
- 遮蔽無法同時保留多數資料又去掉尾巴，因為舊 PDU 在鏈路**恢復之後**才送達。結果強烈取決於規則選擇（0.3 %–9.5 %），屬事後可調之自由度，與「不調參數」原則衝突。
- 可採之替代（須使用者決定，未實作）：(a) ns-3 r12：依 TS 38.322 §5.3.2 於 maxRetx 時通知上層或丟棄，重收 D-30P1（約 19 h ＋ 驗證）；(b) 改用含換手之資料；(c) 不遮蔽，將普遍中斷寫為情境限制。

## 5. 驗收（任一失敗即停，不調參數）

- R-1 回歸：新程式以 `percell` 重跑步 2（E9b 除外，約 65 分）與融合層 6 支，輸出與正式 `d30p1_delay_percell` 除時間／主機欄外逐值相同。
- R-2 單元：`node_value` 於 uemed 時取中位數、其餘時呼叫原式；`median_valid` 空集合回傳 None。
- 步 2、步 3–5 各自之內建檢查照舊；`4e_fusion` 若再失敗，同樣停止並紀錄。
