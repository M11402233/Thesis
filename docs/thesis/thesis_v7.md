## 第一部分：動機

### 1.1 驅動 RIC 決策的 KPM，本身從未被驗證可信度

Near-RT RIC 透過 E2SM-KPM 收集 E2 節點（O-DU）的量測資料，並以此驅動排程、負載平衡、流量導向。整個閉迴路有一個從未被挑戰的前提：通過 E2 Setup 認證的節點，它上報的 KPM 數值是可信的。

在 NPN 場域（工廠、醫院、校園），這個前提不成立。邊緣節點實體可達、缺乏機房級保護，易遭物理入侵或供應鏈底層竄改。被滲透的節點可在不破壞 TLS、完全符合 E2AP 格式下，持續上報微幅偏移的假 KPM——虛報低負載吸引流量造成壅塞，或虛報高負載驅離流量。RIC 照單全收，因為它信任所有通過認證的 E2 連線。本研究驗證的是 **E2 量測資料的可信度**（KPM 數值是否與物理世界相容），而非 RU 的真實無線數據——後者超出一般模擬與設備能處理的範圍。

### 1.2 為什麼現有 ZTA 與既有偵測機制擋不住

現有 O-RAN 零信任聚焦身分認證、存取控制、傳輸加密（mTLS/IPsec/OAuth），但這些邊界防護隱性假設「通過認證的元件在執行期持續遵守規範」，造成執行期可信度無從驗證的盲點。身分合法不代表數值合法。而近期針對 KPM 數值的偵測工作主要採單節點時序異常偵測（LSTM），其結構性弱點是：緩慢漸進的資料毒化會被模型逐步學成正常，刻意模仿正常時序的攻擊也能規避。只看時間軸的方法，看不出「這個數值與周遭物理世界是否相容」。

### 1.3 切入點：物理約束無法被單點偽造

在固定拓樸的 NPN 中，相鄰 cell 的 KPM 受同一群裝置的移動與封閉場域裝置總數約束。一個被攻陷的節點即使能讓自己的時序看起來正常，也很難讓數值同時與「鄰節點觀測」「跨小區 UE 流量守恆」「場域裝置守恆」三者一致，除非同時攻陷多個地理分離的節點。物理一致性是單點攻擊者繞不過的信任錨點——這是本研究的核心命題，也是現有時序型、組態型、協定型方法都未觸及的維度。

## 第二部分：威脅模型與範圍

**部署場景**：固定拓樸工業/校園 NPN，單一 Near-RT RIC 管轄多個 O-DU（覆蓋相鄰 cell），共用 SMO 協調，SNPN 配置。鄰居關係與場域邊界已知。

**聚焦的單一威脅**（依評審建議，砍成一個端點、一個議題）：

| 威脅 | 攻擊樣態 | 受影響 |
|---|---|---|
| **E2 節點 KPM 偽造（false data injection）** | 被滲透/竄改的 O-DU 通過 E2 Setup 後，持續上報偏移的假 KPM（含緩慢漂移、模仿時序、捏造/丟棄 UE 紀錄等隱蔽變體） | E2SM-KPM 量測資料可信度、RIC 決策正確性 |

**攻擊者定位（本版明確鎖定，不再含糊）**：攻擊發生於**受攻擊 O-DU（E2 節點）組裝 KPM indication 的環節**——即量測已在節點內部收集完成、E2 編碼上報之前的資料組裝點。這不是 RU/PHY 無線層攻擊（不在範圍內），也不是核網 UPF 攻擊（UPF 非 E2 節點、不參與 E2SM-KPM 上報，故從威脅模型中排除）。詳細攻擊流程見第四部分附圖。

**範圍內**：E2 Terminator ↔ RAN（E2 節點）這一個端點的 KPM 量測資料可信度驗證。**範圍外（誠實聲明）**：不處理 xApp 越權（控制面、另一議題）、不處理 E2AP 封包格式攻擊（已有文獻解）、不碰 PHY/RU 無線層與核網（含 UPF）。**不採用拜占庭容錯框架**——定位是零信任的「持續資料可信度驗證」，而非分散式容錯聚合。

## 3.3 Stage 2：物理一致性三殘差（核心貢獻，對齊實測 RLC 欄位）

### 3.3.0 方法論定調：三種驗證證據，而非三個異常偵測器

本研究不將三殘差視為三個獨立的異常偵測器，而是零信任「持續驗證」框架中，對一份 KPM 量測
的三種**相互獨立的驗證證據**。其共同邏輯是**證偽（falsification）而非證明**：不試圖證明
一份量測為真，而是尋找它與封閉 NPN 物理／架構約束不一致的反證；找不到反證則「尚未被否證」、
於當前窗暫可採信，任一證據找到反證即降權或拒絕。這對應零信任的核心信條——**信任不是預設，
而是每個 granularity window 重新贏得、可被任一獨立證據推翻的暫時狀態**。

三種證據取自不同觀測維度，故單點攻擊者難以同時滿足：

| 殘差 | 驗證的問題 | 證偽的不變量 | 判定型態 |
|---|---|---|---|
| **C_i** 場域守恆 | 量測是否仍描述同一封閉母體？ | N_total = N_known | 近確定性斷言 |

| **S_i** 跨節點佐證 | 其他節點是否支持此節點觀測？ | delay 符合場域即時共識 | robust 統計殘差 |
| **H_i** 成員轉移 | UE 移動歷史是否符合物理？ | 成員轉移時空連續 | 非參數檢定 + 確定性斷言 |

### 3.3.1 觀測基礎：實測 RLC 欄位（取代 PDCP 假設）

先前版本假設 KPM 建立於 PDCP 層四項欄位（`DRB.PdcpSduVolumeDl` 等）。實測發現此假設在 MC
（Multi-Connectivity）雙連結架構下不成立——ns-O-RAN 的 PDCP 錨點固定聚在 LTE eNB
（`DlE2PdcpStats.txt` 的 CellId 全部 = 1），無 per-gNB 資料，S_i／H_i 需要的跨節點比對因而
失去意義。改用 **RLC 層 trace（`DlE2RlcStats.txt`）**——各 mmWave gNB 各自統計，具完整
per-cell（CellId 1–8）資料，方能支撐跨節點驗證。**此為本研究方法論最重要的實測修正。**

**實測可得欄位**（前 11 欄；第 12 欄後有黏欄 bug，parse 時忽略）：

```
start, end, CellId, IMSI, RNTI, LCID, nTxPDUs, TxBytes, nRxPDUs, RxBytes, delay
```

`IMSI` 對應 UE 識別（跨 cell 一致、可追蹤，語意等同 `amf_ue_ngap_id`）。

**觀測粒度（全章一致）**：E2SM-KPM indication 週期與分析窗均為 1 秒，二者對齊，每模擬秒
一個聚合窗。由 per-UE 量測聚合出 cell 級觀測量（per window, per cell j）：

```
U_j   = | { 該 cell 該窗上報的相異 IMSI } |          （Active UEs）
DLY_j = mean_UE delay                               （cell 平均延遲）
TP_j  = (8/Δt) · Σ_UE ΔRxBytes                      （cell DL 吞吐量）
```

> **吞吐量前處理注意**：`RxBytes`／`TxBytes` 為累積 counter，非每窗流量，故 TP_j 須以視窗差分 ΔRxBytes 計算。`delay` 為每窗獨立量測值、非累積。本研究的 S_i 建於 delay，不受累積 counter 問題影響。

### 3.3.2 (A) S_i：跨節點空間一致性殘差（延遲場域共識）

S_i 驗證「此節點的觀測是否被同一時刻的其他節點支持」。經對實測資料的訊號探勘，選定**延遲**
為偵測維度：延遲的場域自然變異極小（變異係數 CV ≈ 0.12），是物理上緊約束的量；吞吐量自然
變異大且無 PRB／CQI 硬約束（見 3.3.5），UE 數則屬 C_i 的守備範圍。**此維度選擇由資料的
經驗可觀測性決定，而非預設攻擊落於延遲。**

對受測 cell j 於窗 t：

```
中心   c_j(t) = median{ DLY_k(t) : k 為同窗其他活躍 mmWave cell }     （同一時刻跨節點共識）
尺度   s      = 1.4826 · MAD_global                                  （乾淨訓練資料，全域穩定）
殘差   z_j(t) = | DLY_j(t) − c_j(t) | / s
判定   S_i violated  ⟺  z_j(t) > τ_z^reject          （τ_z^reject = 3；FPR–偵測率掃描選定）
```

- **（空間性）** 中心取自同一時刻其他 cell，故 z_j(t) 度量節點 j 對場域即時共識的偏離——
  此為跨節點空間一致性，非節點自身的時間基準。
- **（尺度穩定）** 因同窗活躍 cell 數少（N ≤ 7），即時 MAD 有小樣本高變異問題（推升誤報率
  至 0.14–0.20），故尺度改由乾淨資料全域估計（pooled/shrinkage scale）。1.4826 使 MAD 成為
  常態下標準差的漸近一致估計量。
- **（每窗獨立）** 每窗獨立對照固定尺度與同窗中心，不累積歷史殘差。
- **（S_i unavailable）** 當同窗活躍 cell < 2 時無 peer 可比，S_i 判 **unavailable →
  low-trust／abstain，不得視為可信**。實測 88.5% 的窗有 ≥2 活躍 cell；其餘 11.5% 進 abstain。
  此確保「證據不足」不等於「證據支持」——零信任的體現。

**尚待實作**：`config/topology.yaml` 鄰接矩陣（依 `configuration=2` 新座標重算）用於 S_i 的
拓樸加權強化與 H_i D2 的次要佐證，非 S_i 主判據前提。

### 3.3.3 (B) H_i：跨小區 UE 成員轉移一致性殘差（消失 + 瞬移）

H_i 驗證「UE 的出現、消失、移動是否符合封閉 NPN 的物理與架構約束」，補上 C_i 的涵蓋邊界
（C_i 只驗基數守恆、不驗成員組成）。經探勘確立兩個性質不同的維度：

**D1 成員消失（非參數統計檢定）**

實測顯示 UE 掛 LTE-only（回落錨點）的停留時間呈**雙峰重長尾**分布，且對幾何等單一參數族
的卡方適合度檢定顯著不符（χ² ≫ 臨界值），故採不需分布假設的非參數方法。對每個 UE x，由
乾淨資料建 Hampel identifier 與經驗分布：

```
z_d(x,t) = ( d(x,t) − median_x ) / ( 1.4826 · MAD_x )       （Hampel robust z；d = 連續 LTE-only 停留窗數）
p_emp(x,t) = P( 乾淨停留(x) ≥ d(x,t) )                       （經驗 p 值，非參數）
D1 violated ⟺ z_d > τ_z^reject                              （或 p_emp < α，可取聯集/交集）
```

per-UE 基線的必要性：UE 分「常駐 mmWave」與「結構性訊號差的 edge UE」兩群，全域單一門檻會
系統性誤判 edge UE。**基線由乾淨資料一次估計、永不線上更新**——否則攻擊者可緩慢養高某 UE
停留以撐大門檻（即 LSTM adaptive baseline 的同一弱點）。

**D2 成員瞬移（近確定性斷言）**

MC 雙連結架構下，UE 換 mmWave cell **必經 LTE 錨點過渡**。實測（10 seed 全部轉換）「不經
LTE 的直接 mmWave→mmWave 跳轉」出現 **0 次**，故：

```
teleport(x,t) := (x 於 t−1 掛 mmWave A) ∧ (x 於 t 掛 mmWave B≠A) ∧ (中間無 LTE-only 過渡窗)
D2 violated ⟺ ∃x: teleport(x,t)
```

乾淨基線為 0，故任何 teleport 即結構性違反、無需閾值。此對應攻擊表 type C（謊報位置/瞬移）：
攻擊者將 UE 偽造至非當前服務 cell，若未同時偽造合法 LTE 過渡窗（且過渡須與不可控的 LTE
錨點一致）即觸發 D2。

> **（先前「LTE 回落」定義問題已解決）** 早期版本標記「UE 回落 LTE 不應判為瞬移，此定義
> 問題尚未實作」。此問題**已於 D2 定義中解決**：LTE 錨點即為合法過渡節點，D2 僅在「無 LTE
> 過渡的直接跳轉」時觸發，實測乾淨基線為 0、注入瞬移偵測率 100%。

**（移除流量守恆）** 早期版本的 H_i 含「跨小區流量守恆 Σ ΔU_j ≈ 0」。因吞吐量為累積 counter
且缺 PRB 硬約束（3.3.5），此守恆在 RLC-only 資料上無法穩健成立，故自 H_i 移除；H_i 聚焦
成員轉移（消失 + 瞬移）兩維度。

### 3.3.4 \(C) C_i：場域 UE 基數守恆驗證（已實作、已實證）

C_i 驗證「量測是否仍描述同一封閉裝置母體」。依 Alpern & Schneider 的分類，此為 safety
property，其違反可由單一窗即刻觀察，故為布林斷言而非連續分數：

```
N_total(t) = | ∪_all-cells { IMSI }(t) |          （全場域相異 UE 總數，含 LTE 錨點）
conserved(t) := ( N_total(t) = N_known )          （N_known = 7）
C_i violated ⟺ N_total(t) ≠ N_known
```

**（布林斷言，非容忍帶）** 採嚴格相等而非 [N_lo, N_hi] 容忍帶：N=7 時 5% 帶等同零容忍
（7×0.95=6.65，少 1 即出界），故不設容忍帶；若需吸收重連瞬態，改採多窗持續條件（連續 2 窗
N_total≠N_known 才升級 rejected）。

**（虛減偵測的條件性）** C_i 對單一 O-DU 虛減的偵測是條件性的：實測僅 56.6% 的 (窗,UE)
同時掛 LTE 錨點；受害 UE 當下未雙掛 LTE 時，刪除使全域聯集淨減、C_i 偵測（100%）；同時掛
LTE 時錨點仍上報、C_i 無法察覺（須 H_i 補）。此與守恆式串謀盲點共同構成 C_i「必要非充分」
的能力邊界。

### 3.3.5 涵蓋範圍與 PRB 定位

三殘差涵蓋基數（C_i）、跨節點延遲一致（S_i）、成員轉移（H_i）。**純吞吐量竄改不在涵蓋範圍**：
RLC-only 資料無 PRB/CQI，吞吐量缺乏物理硬約束，本研究實測多種途徑均無法穩健偵測。純吞吐量
竄改若伴隨延遲異常則落入 S_i、伴隨 UE 數異常則落入 C_i，其未涵蓋角落限縮於「純數值、無
副作用」之低衝擊攻擊。PRB 利用率（`RRU.PrbUsedDl` 等）為**標準 E2SM-KPM 量測項目——屬同一
Service Model 下目前未解碼的項目，非另建 SM**，ns-O-RAN 現行 KPM 清單未接出，列為未來延伸。

### 3.3.6 為什麼能抓到時序方法抓不到的攻擊

緩慢漸進的假 KPM 能騙過單節點時序 LSTM——因其線上更新的基準會將漸進偏移逐步學成正常
（adaptive blind spot）。三殘差以**固定的物理／空間參照**約束之，不隨假資料「適應」：漂移
偏離同窗共識即被 S_i 捕捉（固定共識參照不線上重學）；偽造成員的瞬移或超時消失破壞 H_i；
改變基數者破壞 C_i。**此優勢來自參照機制的不同（固定 vs 自適應），而非更強的模型**——是相對
Alimohammadi 等人自適應時序方法的核心增量。唯守恆式串謀（維持基數）需 S_i/H_i 交叉補足，
非 C_i 單獨可及。

## 3.4 信任決策：階層式證據融合與最小權限執行

三殘差性質不同（C_i 近確定性斷言、S_i／H_i 連續統計殘差），若以線性加權
`T = w_S·S + w_H·H + w_C·C` 整合，會使硬違反被統計證據稀釋——例如 C_i 違反守恆（應立即
拒絕）但 S、H 正常時，加權平均仍可能落在可信區。故本研究採**階層式規則融合**，更符合零信任
的 fail-closed 精神：

```
第一層 — 硬否決（hard veto → rejected）：任一成立即拒絕，不進入後續判斷
   · C_i 確定違反（N_total ≠ N_known）且完成節點歸因
   · H_i D2 teleport（架構不變量違反）
   · Stage-1 身分／格式驗證失敗

第二層 — 統計證據（無硬否決時）：綜合
   · S_i 空間 robust z（τ_z^reject / τ_z^warn = 3 / 2）
   · H_i D1 經驗 p 值 / robust z
   · 多窗累積證據
   → 分為 trusted 或 low-trust

第三層 — 證據不可得（abstain）：
   · S_i unavailable（同窗 < 2 活躍 cell）、LTE 錨點 KPM 遺失、窗無法對齊
   → 不視為 trusted，而是 low-trust / abstain，要求後續佐證
```

**最小權限執行（拒絕採信，非容錯聚合）**，以信任分級門檻 τ_T 分流：

```
trusted（τ_T ≥ τ_T^high，預設 0.90）：KPM 正常納入 RIC 決策輸入
low-trust（τ_T^low ≤ · < τ_T^high，0.50–0.90）：RC xApp 降權使用或要求鄰節點佐證
rejected（< τ_T^low，或觸發第一層硬否決）：排除於決策輸入 + 寫入驗證日誌 + 觸發 SMO 告警
```

**符號約定**：信任分級門檻為 **τ_T^high / τ_T^low**（0.90 / 0.50）；z 分數門檻為
**τ_z^reject / τ_z^warn**（3 / 2）。二者為不同尺度，不共用同一符號。

此三層對應零信任「多獨立證據、fail-closed、never trust on missing evidence」。相對於拜占庭
容錯的**容錯聚合**（在假資料中求共識），本研究採**拒絕採信**：驗證失敗的 KPM 被排除於決策
之外並告警，而非被平均進聚合結果——這是零信任「持續資料可信度驗證」與 BFT 的根本差異。

### 3.4.1 評估範式（非 ROC）

三殘差採**證偽／runtime verification 範式**評估，非統計異常偵測的 ROC 範式：確定性斷言
（C_i、H_i D2）以證偽測試（在多條獨立軌跡上尋找反例）評估；統計殘差（S_i、H_i D1）報
FPR／TPR，並以 **seed（獨立執行軌跡）為統計單位**報信賴區間（同 seed 內相鄰窗相關，不作為
獨立樣本）。門檻 τ_z 以 FPR–偵測率掃描選定操作點，非 ROC-AUC 最佳化。

## 4.1 攻擊架構與注入點定位

本研究之威脅為一個**身分合法、但資料造假**的內部 O-DU 節點。攻擊者不破壞 E2 介面之 IPsec、不偽造 E2AP 格式、不碰無線層——竄改發生於**量測收集完成後、E2SM-KPM indication 編碼前**的資料組裝環節，使上報之數值或 IMSI 偏離物理真實。此威脅已由 O-RAN WG11 點名為 Key Issue #14「Malicious E2 Node」：惡意行為者可濫用已正確完成認證之被攻陷 E2 節點，送出變造與誤導性資料（xApp-TR §5.15）。E2 路徑上之傳輸與身分保護（IPsec ESP 與 IKEv2 憑證認證；E2GAP §7.3）對此無效，現行之單值範圍檢查（SRCS SEC-CTL-NEAR-RT-17）亦無法偵測落在合法範圍內之偽造值，此即需要跨來源一致性驗證之根本原因（呼應第一章）。

**注入點排除說明**：
- **O-RU／PHY 無線層**：研究範圍外。本研究驗證 E2 量測資料之可信度，而非真實無線訊號。
- **UPF／核網（N3/N6）**：研究範圍外。UPF 非 E2 節點、不參與 E2SM-KPM 通訊。
- **O-DU（E2 節點）KPM 組裝點**：**本研究攻擊面**。ns-O-RAN 單體 gNB 架構下 CU/DU 未實際物理切分，攻擊點準確描述為「E2 節點內、量測聚合完成至 E2SM-KPM indication 編碼之間」之資料層。

> 威脅模型之**概念注入點**位於 O-DU KPM 組裝點；**本章實驗以離線後處理修改該點可控欄位、等價模擬其輸出效果，尚未完成 runtime E2SM-KPM indication hook**（見 4.2.5）。本章所有攻擊實驗均屬此離線注入層級。

**完整攻擊流程**：

```
攻擊者取得邊緣節點控制權
  → 完成 E2 Setup（節點身分認證通過，IPsec／E2AP 格式完好）
  → 選擇竄改注入點：O-DU KPM 組裝點（本研究攻擊面）
  → 注入攻擊型態（見 4.5.1）
  → 編碼為合法 E2SM-KPM indication（格式合規、身分合法、數值落於合法範圍）
  → 週期上報 Near-RT RIC
  → ① Detection xApp：計算三類一致性證據（C_i／S_i／H_i）
  → ② Trust Assessment xApp：階層式融合 → trusted / low-trust / rejected / abstain
  → ③ Policy Enforcement xApp：allow / restrict / exclude / defer → policy-admitted KPM
  → 合作之消費端（RC xApp）僅取用 policy-admitted KPM
```

## 4.2 工具鏈、資料集與實驗方法

### 4.2.1 平台與場景

**平台**：ns-O-RAN（ns-3.42 + mmWave module + `oran-interface` E2 termination）。場景建立 **7 個 gNB + 1 個 LTE eNB** 之 MC 雙連結拓樸，提供跨節點空間驗證所需之多 cell 觀測。ns-O-RAN 具備 E2 termination 能力（RAN Function ID 2，ORAN-E2SM-KPM），惟**本研究之資料收集採其離線檔案記錄模式（`enableE2FileLogging=true`），未經由 Near-RT RIC 之 E2 indication 路徑**；E2 runtime 整合之嘗試與受阻點見 4.2.5。

**場景**：`scratch/scenario-three.cc`，`configuration=1`（3.5 GHz／20 MHz／isd = 1000 m／單天線）。

> **註**：ns-O-RAN 將節點命名為「mmWave gNB」，係沿用其 MC 雙連結架構之命名慣例；於 `configuration=1` 下實體載波為 sub-6 GHz。S_i 建立於 delay 之跨節點一致性，與載波頻段無關，此命名不影響方法有效性。

### 4.2.2 觀測粒度

記錄週期與分析窗均為 **1 秒**（`indicationPeriodicity=1.0`），二者對齊，每模擬秒產生一個聚合窗。全章所有「窗」均指此 1 秒聚合窗。

**定案參數**（兩批資料集共用，僅 `SIMTIME` 與 seed 數不同）：

```bash
CONFIG=1          # 3.5 GHz / 20 MHz / isd=1000m
UES=1             # 每 cell 1 UE × 7 cell = N_known=7
SIMTIME=60        # D-C（D-SH 用 300）
PERIOD=1.0        # 1 秒觀測窗
MINSPEED=3
MAXSPEED=10
HEURISTIC=-1      # 不啟用節能 heuristic
```

### 4.2.3 資料集

| 代號 | 規模 | 窗數 | 用途 |
|---|---|---:|---|
| **D-C** | 10 seed（RngRun 4200–4209）× 60 s | 600 | C_i 之 E0–E8 |
| **D-SH** | 4 seed（RngRun 4200–4203）× 300 s | 1,200 | S_i、H_i、E9、E10、C-ZT 之決策分布與運算開銷、對抗性分析、決策重放（4.12） |

### 4.2.4 威脅注入方法論

本章所有攻擊樣本均依以下原則產生，確保注入與偵測之獨立性：

1. **乾淨 trace 永不修改**：ns-3 產出之 RLC trace 為唯一真值來源，所有注入於其副本上進行。
2. **注入為獨立程式**：注入程式僅修改可控欄位（IMSI 集合、CellId↔IMSI 對應、delay），不讀取偵測器之門檻或內部狀態。
3. **偵測器不知情**：偵測器以同一介面、同一組固定門檻處理乾淨與注入樣本，不接收任何標籤。

**結構性佐證**：注入套件包含守恆式替換函式（E3、E7），而偵測器對其如實回報「未偵測」（0/600）。一個為保證偵測而設計之注入套件不會包含此函式——其存在與其結果，構成注入與偵測相互獨立之證據。

### 4.2.5 E2 runtime 整合之嘗試與限制

本研究曾嘗試將 ns-O-RAN 接上 FlexRIC 作為 Near-RT RIC。**E2 Setup 已成功**：FlexRIC 於本機迴路（127.0.0.1:36421）收到 E2 節點之 E2 SETUP REQUEST，並接受其宣告之 RAN Function。然而於 RIC Indication 之產生路徑上，依序遭遇協定版本不一致、ASN.1 標頭路徑、API 更名、未實作函式、缺漏模組與方法、函式庫版本不相容等問題，最終阻滯於 RIC Indication Header 之 ASN.1 PER 編碼階段，且錯誤發生於 codec 內部。經評估其修復已超出本研究時程之可控範圍，遂停損。

**對本研究之影響**：驗證邏輯之輸入改由離線 trace 提供（見 4.9.1 之 `IndicationSource` 抽象層）。兩條路徑承載之數值出自同一封包級模擬，**未經驗證者為傳輸路徑，而非驗證邏輯本身**；惟端到端 E2 訊息處理延遲、runtime 注入 hook 與實際 RIC 決策之影響，均因此無法量測，列為後續工作。

## 4.3 KPM 解碼擴充與資料前處理

### 4.3.1 KPM 解碼擴充

實測出現 "Measurement Name not yet supported"——測量值已在 indication message 內，但解碼器尚未映射部分名稱。本研究擴充 KPM parser 將可用欄位解析為數值。**因原始值已在訊息中，此為有界之解析擴充，而非從零自製 KPM mapping。**

### 4.3.2 資料源與欄位

資料源為 **RLC 層 trace（`DlE2RlcStats.txt`）**（非原先假設之 PDCP 層——PDCP 錨點在 MC 架構下全聚於 LTE eNB，無 per-gNB 資料，無法支撐跨節點比對）。可用欄位（前 11 欄）：

```
start, end, CellId, IMSI, RNTI, LCID, nTxPDUs, TxBytes, nRxPDUs, RxBytes, delay
```

RLC trace **不含 PRB 使用率與 CQI**。PRB 相關量測定義於 3GPP TS 28.552，可經 E2SM-KPM REPORT Style 1 訂閱（E2SM-KPM §1、§7.4.2）；E2SM-KPM 本身並未列舉 `RRU.PrbUsedDl`。ns-O-RAN 現行 KPM 清單未接出此類量測，列為未來延伸。

### 4.3.3 吞吐量的差分前處理

`RxBytes`／`TxBytes` 為累積 counter，非每窗區間流量，故 cell 級吞吐量須先做視窗差分：

$ΔRxBytes(u,t) = RxBytes(u,t) − RxBytes(u,t−1)$
$TP_j(t) = (8/Δt) · Σ_{u ∈ cell j} ΔRxBytes(u,t)$

第一窗、缺窗、cell change 或 counter reset 造成之不可比差分標為 missing、不納入計算。**delay 為每窗獨立量測值、非累積**，S_i 不受此影響。

### 4.3.4 場域基數必含 LTE 錨點

C_i 之全域聯集**必須包含 LTE 錨點 cell（CellId=1）**：含 LTE 時 N_total(t) 每窗恆為已知母體數；若只計 mmWave，N_total 會因 UE 正常回落 LTE 而浮動（非攻擊訊號）。

## 4.4 驗證哲學與階層式證據融合

### 4.4.0 信任狀態之定義與判定規則

#### （一）信任狀態之語意

本研究之驗證層對每一個 (節點, 觀測窗) 產出一個信任狀態 $D_i(t) \in \{\text{trusted},\ \text{low-trust},\ \text{rejected},\ \text{abstain}\}$。四者之語意、對應之 Policy Enforcement 動作，以及**明確排除之誤解**定義如下：

| 狀態 | 語意 | Policy Enforcement 動作（4.9.3） | 明確不代表 |
|---|---|---|---|
| **trusted** | 本窗未觀察到任何反例，且驗證所需證據充足 | **allow**：納入 policy-admitted KPM | 不代表該量測已被證明為真；僅代表未發現反例（4.4.1） |
| **low-trust** | 存在至少一項需交叉佐證之證據，未達可直接採信之標準 | **restrict**：依准入政策限制其使用——附註記後納入，或自決策輸入排除（本章評估之兩種設定見 4.12.3） | **不代表該量測為偽造**；不應解讀為誤報率 |
| **rejected** | 存在確定性違反，或多項統計證據指向同一對象 | **exclude**：該筆量測不進入 policy-admitted KPM；寫入 execution record | **不代表該節點被判定為攻擊者**；拒絕對象為該筆 KPM，非該節點之身分 |
| **abstain** | 驗證所需證據不可得，無法作成判定 | **defer**：當窗不進入 policy-admitted KPM；fallback 政策另行定義，且不使該筆量測回到 admitted view（4.9.3） | **不代表可信**；證據不足永遠不等於證據支持 |

**嚴重度序**：$\text{trusted} \prec \text{abstain} \prec \text{low-trust} \prec \text{rejected}$。此序用於同窗多項證據並存時之彙總，以及跨節點之窗層級呈現。

**不繼承原則**：信任狀態並非節點之屬性，而是每個觀測窗針對每個 (節點, 窗) 重新產生之驗證狀態。前一窗之 trusted 不對後一窗構成任何預設；前一窗之 rejected 亦不使該節點於後續窗永久失信。過去狀態僅在明文定義之多窗持續性規則中作為證據（見下表 `R1_CI_VETO` 之持續窗條件）。由此導出之狀態轉移與恢復條件見（四）。

#### （二）階層式融合規則

三項殘差之性質互異——$C_i$ 與 $H_i$-D2 為近確定性斷言，$S_i$ 與 $H_i$-D1 為統計殘差。若以加權分數融合，確定性之違反將被正常之統計讀數稀釋（論證見 4.4.3）。故採**階層式規則融合**，依 NIST SP 800-207 §3.3.1 之分類屬 criteria-based 信任演算法。

**判定輸入**：本窗之證據組 $E_i(t) = \langle\, C_i,\ r_C,\ S_i,\ \text{D2},\ \text{D1},\ \text{ev}_{\text{D1}},\ j \,\rangle$，其中 $r_C$ 為 $C_i$ 連續違反窗數，$\text{ev}_{\text{D1}}$ 為 D1 證據之歸屬節點——於定案之 uebound 政策下為觸發該證據之 UE **消失前之 serving mmWave cell**；於 window 對照政策下為該 UE 當窗掛載之 cell 集合（4.9.6.5），$j$ 為受測節點。

**判定對象之範圍**：信任狀態僅對當窗有上報之 mmWave 節點產生。LTE 錨點（CellId 1）為驗證用之輔助輸入（$C_i$ 之聯集、$H_i$ 之過渡判定），不在本次准入政策之作用範圍內。當窗無任何活躍 mmWave 節點時，該窗之處理狀態記為 `n/a`（reason = `no_active_mmwave_node`），不產生節點信任註記、准入動作或准入量測；`n/a` 為窗之處理狀態，**不是第五種信任狀態**。

**規則表**（依序評估，先匹配者生效）：

| 層 | 代碼 | 條件 | 狀態 |
|---|---|---|---|
| L1 | `R1_CI_VETO` | $C_i$ violated 且 $r_C \geq L_C$ | **rejected** |
| L1 | `R1_CI_PENDING` | $C_i$ violated 且 $r_C < L_C$ | **low-trust** |
| L1 | `R1_D2_VETO` | $H_i$-D2 violated（觀測層級瞬移斷言） | **rejected** |
| L1 | `R1_STAGE1` | 身分前提不成立（節點身分認證由 RIC 平台於 E2 Setup 完成，本層僅取用其結果；本章實驗未觸發） | **rejected** |
| L2 | `R2_SI_D1_BOUND` | $S_i$ violated 且 D1 = strong 且 $j \in \text{ev}_{\text{D1}}.\text{cells}$ | **rejected** |
| L2 | `R2_SI_D1_UNBOUND` | $S_i$ violated 且 D1 = strong 但 $j \notin \text{ev}_{\text{D1}}.\text{cells}$ | **low-trust** |
| L2 | `R2_SI_ALONE` | $S_i$ violated，D1 無 strong 證據 | **low-trust** |
| L2 | `R2_D1_STRONG` | D1 = strong（$z_d \geq \tau_H^{\text{reject}}$）且歸屬於節點 $j$，$S_i$ 未違反 | **low-trust** |
| L2 | `R2_D1_WEAK` | D1 = warning（$\tau_H^{\text{warn}} \leq z_d < \tau_H^{\text{reject}}$）且歸屬於節點 $j$ | **low-trust** |
| L3 | `R3_ABSTAIN` | $S_i$ unavailable（同窗 peer 數 < MIN_PEER）、LTE 錨點 KPM 遺失、或窗無法對齊 | **abstain** |
| L0 | `R0_CLEAN` | 以上皆不成立 | **trusted** |

#### （三）三項設計約束之說明

**約束一：硬違反優先，且不被統計證據稀釋。** L1 條件一旦成立即直接產出判定，不再評估 L2 與 L3。$C_i$ 違反但持續窗數未達 $L_C$ 者降為 low-trust 而非 trusted——**違反之觀察與拒絕之執行為不同層級**，前者為 property 判定，後者為 enforcement 決策（4.6.1）。

**約束二：單一統計證據不構成硬否決；交叉佐證須指向同一對象。** $S_i$ 或 $H_i$-D1 單獨違反僅得 low-trust。二者同窗並存時，**須進一步檢查兩項證據是否指向同一節點**方可升級為 rejected（`R2_SI_D1_BOUND`）；若指向不同對象（`R2_SI_D1_UNBOUND`），則視為兩個無關告警同時出現，不構成互相印證。

此綁定要求源自實作稽核（4.9.6）。$H_i$-D1 依定義量測 UE 之 LTE-only 停留窗數，觸發 D1 之 UE 必然掛載於 LTE 錨點。**若以「當窗掛載之 cell」為歸屬依據（window 對照政策），D1 證據與 $S_i$ 受測之 mmWave 節點在結構上不相交，`R2_SI_D1_BOUND` 不存在合法觸發路徑。** 定案之 uebound 政策改以「該 UE 消失前之 serving mmWave cell」為歸屬依據，使此規則首次具有合法觸發路徑；其於乾淨資料上之觸發為 6 筆，均為誤拒事件（4.9.6.5）。

**約束三：證據不可得永不等同於證據支持（fail-closed）。** L3 成立時，系統不放行該筆量測而判為 abstain，避免攻擊者藉由壓制鄰居節點上報、或利用離峰空窗使 $S_i$ 無法取得比對對象而「預設通過」。

評估順序之一項後果：L3 位於 L2 之後，故當同窗另有 $H_i$-D1 證據時，L2 先行觸發 low-trust，該窗雖屬 $S_i$ 證據不可得，卻不呈現為 abstain。**因此 abstain 之決策比例並非證據不可得率**，二者須分別陳述（實測見 4.9.6.4）。此順序之理由為：abstain 較 low-trust 為輕，當已有其他證據足以降級時採較嚴之判定，符合 fail-closed。

#### （四）狀態轉移與恢復條件

因採不繼承原則，狀態之進入與離開均由當窗證據決定。由（二）之規則表可直接導出各狀態之離開條件：

| 進入之規則 | 進入條件 | 離開條件（次窗重新判定） |
|---|---|---|
| `R1_CI_PENDING` → `R1_CI_VETO` | $N_{\text{total}} \neq N_{\text{known}}$；連續達 $L_C$ 窗時升級為 rejected | 首個 $N_{\text{total}} = N_{\text{known}}$ 之窗，$r_C$ 歸零 |
| `R1_D2_VETO` | 當窗出現瞬移事件 | 瞬移為單窗事件；次窗若無新事件即離開 |
| `R2_SI_ALONE` | $z_j > \tau_S$ | 首個 $z_j \leq \tau_S$ 之 full-consensus 窗 |
| `R2_D1_STRONG`／`R2_D1_WEAK` | 歸屬於節點 $j$ 之 UE 其 $z_d \geq \tau_H$ | 該 UE 之連續 LTE-only 停留結束（$d$ 歸零） |
| `R3_ABSTAIN` | 證據不可得 | 證據恢復可得 |

此表為規則之邏輯後果，非實測結果。其兩項意涵須明言：

1. **恢復為即時且無記憶**：觸發條件消失之次窗，該節點之量測即回到 trusted，系統不保留「曾被拒絕」之狀態。此與「拒絕對象為該筆量測而非節點」一致，但亦意謂間歇性攻擊者於每次停手後立即恢復。
2. **持續性升級僅有一條**：唯一之持續性升級為 $C_i$ 之 $L_C$。$S_i$ 之持續違反恆為 low-trust（`R2_SI_ALONE`）。統計證據升級為 rejected 之唯一路徑為同窗之交叉佐證（`R2_SI_D1_BOUND`），且僅於 uebound 政策下可觸發（約束二）；window 政策下統計證據不存在升級為 rejected 之路徑。其下游後果見 4.12.5（三）。

RQ2 所問之轉移延遲、恢復延遲，以及持續性政策對重複短違反之效果，其量測為【待填：E11／E11b 之結果】；統計證據之持續性升級規則（候選 `R2_SI_PERSIST`）為【待填：E12 之設計與結果；未實作前不列入（二）之規範性規則表】。

### 4.4.1 從認證到持續驗證

Near-RT RIC 現況隱含「認證即可信」之假設：E2 上認證即授權（ZTA-TR §7.3.4 NOTE 3），O-RAN 零信任研究亦將經 E2 傳送之資料判定為無缺口（ZTA-TR §7.3.4）。NIST SP 800-207 則明言，不應因主體通過基本認證即假設其後續請求同樣有效；O-RAN WG11 之研究報告亦指出，即使 E2 被視為具備機密性、完整性與雙向認證，RIC 仍不應假設收到之資料有效且可信（xApp-TR §6.17）。

    傳統：  measurement → authenticated? → trust
    本研究：measurement → authenticated? → VERIFY → trust decision

信任不是預設，而是**每個 granularity window 重新產生之驗證狀態**。本研究借用「**未發現反例不等於證明為真**」之共同判斷原則（統計證偽、runtime verification 與零信任共有），不宣稱四者具完全相同之認識論骨架。

### 4.4.2 三種驗證證據

| 殘差 | 驗證的問題 | 證偽的不變量 | 判定型態 |
|---|---|---|---|
| **C_i** 場域守恆 | 量測是否仍描述同一封閉母體？ | N_total = N_known | 近確定性斷言 |
| **S_i** 跨節點佐證 | 其他節點是否支持此節點觀測？ | delay 符合場域即時共識 | robust 統計殘差 |
| **H_i** 成員轉移 | UE 移動歷史是否符合物理？ | 成員轉移時空連續 | 非參數檢定 + 確定性斷言 |

三者取自不同觀測維度（空間聚合／空間並置／時間連續），**互補但非統計獨立**（皆依賴 IMSI/cell 上報，LTE 錨點缺報會同時影響 C_i 與 H_i）。其防禦價值在於：攻擊者要同時不被三者否證，需讓偽造資料同時滿足多種不同約束——這需要同時控制多個地理分離之節點並協調上報。

此跨來源佐證之原則並非全新範式：3GPP 於假基站偵測中已載明，多個 UE 之量測報告可用於過濾單一惡意 UE 之錯誤報告（TS 33.501 Annex E §E.2）。本研究將其移植至 E2 介面與內部威脅方向。

### 4.4.3 融合結構之設計理由：為何不採線性加權

> 本節說明 4.4.0 規則結構之設計理由；規則本身見 4.4.0。

#### （一）加權平均會使確定性證據被稀釋

三項殘差之性質並不對等。$C_i$ 為布林斷言（Alpern & Schneider 意義下之 safety property）；$H_i$-D2 為觀測層級之架構斷言；$S_i$ 與 $H_i$-D1 則為統計殘差，其輸出為連續偏離量。

若以線性加權合成單一信任分數，某窗之 $C_i$ 確定違反（分數為 0）而 $S_i$ 與 $H_i$ 均正常（分數接近 1）時，合成分數仍可能落於可信區——**以最弱之證據稀釋最強之證據**。

此問題不能以調整權重解決。提高 $C_i$ 之權重至足以單獨主導判定時，該權重在數學上已等價於一條硬否決規則，惟表達較不明確、門檻與權重之交互作用難以稽核。**既然目標行為是一票否決，直接表達為規則較表達為權重更誠實且可驗證。**

#### （二）此選擇對應 criteria-based 信任演算法

NIST SP 800-207 將信任演算法區分為 criteria-based（一組合格條件全數滿足方予放行）與 score-based（加權信賴分數比門檻）。本研究屬前者。以 KPM 為輸入之零信任框架多採 score-based 設計——例如 i-ZTA 之信任評估引擎輸出 0 至 1 之連續信賴度量（Ramezanpour & Jagannath, 2022）。該設計適用於證據性質同質之情形；當證據中同時包含確定性斷言與統計殘差時，分數化會抹除二者在認識論上之差異。

#### （三）三項行為承諾

1. **硬違反優先**：確定性證據一旦成立即直接產出判定。
2. **單一統計證據不冒進**：$S_i$ 或 $H_i$-D1 單獨違反僅得 low-trust，其必要性由 4.8.6 之 edge UE 誤報率實證。
3. **fail-closed**：證據不可得不得視為證據支持。

上述三項行為於 4.11 之規則回放中逐一檢驗。

#### （四）拒絕採信，而非容錯聚合

拜占庭容錯框架之目標為在部分節點惡意之情形下**仍產出可用之聚合結果**；零信任之目標為**在採信前逐份驗證，證據不足時拒絕採信**。前者以可用性為優先並容忍受污染輸入，後者以正確性為優先並接受可用資料量之減少。本研究採後者，其代價（可直接採信之比例下降、可用資源減少）於 4.9.6 與 4.12 揭露。

## 4.6 C_i：場域基數守恆驗證

### 4.6.1 形式定位與定案參數

依 Alpern & Schneider，場域基數守恆屬 **safety property**：違反可由單一窗即刻觀察，故為布林斷言。

```
N_total(t) = | ∪_all-cells { IMSI }(t) |          （含 LTE 錨點）
conserved(t) := ( N_total(t) = N_known )          （N_known = 7）
C_i violated ⟺ N_total(t) ≠ N_known
```

**布林斷言，非容忍帶**：N = 7 時 5% 容忍帶等同零容忍（7×0.95 = 6.65，少 1 即出界），故採嚴格相等；重連瞬態以持續窗條件吸收（連續 L_C 窗違反方升級 rejected）。

| 參數 | 值 | 理由 |
|---|---|---|
| `N_known` | **7**（ues=1 × 7 cell） | 原設計 35 因 MC 候選 cell 評估於高 UE 密度下成本超線性、無法穩定長跑；7 為實測可長跑之規模。此為場域規模之實驗限制，其對運算開銷之意涵見 4.9.5 |
| 判定 | 嚴格相等 | safety property，零閾值布林斷言 |
| L_C | 2 | 吸收斷線重連瞬態（代價見 4.6.7） |

> **範式說明**：C_i 不採 ROC/AUC/閾值掃描（布林斷言無閾值可調），改採**證偽測試**——於多條獨立軌跡上尋找 conserved(t) = False 之正常窗格。
>
> **違反觀察與執行決策之區分**：單窗 N_total ≠ N_known 即構成 *invariant violation observed*；是否升級為 rejected 由 L_C 政策決定（4.4.0 `R1_CI_VETO`／`R1_CI_PENDING`）。

### 4.6.2 E0：不變量成立性之證偽測試

**設定**：D-C 資料集，10 個獨立 seed，各 60 窗，共 600 窗。逐窗計算含 LTE 錨點之全 cell 相異 IMSI 聯集。

| 統計量 | 值 |
|---|---|
| 總窗數 | 600 |
| N_total 分布 | 全部 = 7 |
| mean / std | 7.000 / 0.000 |
| 反例數 | **0** |

**論述**：N_total 於 600 窗、10 種獨立隨機性下未觀察到任何反例。此為**本 ns-O-RAN MC 組態與觀測條件下之架構不變量，而非一般封閉 NPN 中無條件成立之物理定律**——真實 NPN 仍可能因 UE 關機、睡眠、暫時 detach、KPM 遺失、解碼失敗、窗未對齊、UE 重連換 ID、維護期裝置增減而破壞此恆定（見 4.6.9）。結果為確定性（std = 0），不宣稱統計顯著性。

### 4.6.3 E1：灌水偵測邊界與幅度不變性

| 灌水數 k | N_total | 斷言 |
|---|---|---|
| 0（baseline） | 7 | conserved |
| +1 | 8 | **violated** |
| +2 ～ +6 | 9 ～ 13 | violated |

任何 |k| ≥ 1 → violated。N_known = 7 下偵測邊界為 +1 UE（每筆偽造佔母體 1/7 ≈ 14.3%）。

**幅度不變性**：於固定注入起點施加 k = 1…5，10 個 seed 之偵測延遲均為 **0 窗**（圖 4-1）——k 僅改變偏離量，不影響觸發時機。此為單窗即決斷言之必然結果。與統計型偵測器相對：後者需累積證據方能跨越門檻，偵測延遲隨攻擊幅度遞減。

**規模關係（分析性）**：偵測邊界 |k| ≥ 1 與 N_known 無關。隨 N_known 改變者為**相對衝擊比例** k/N_known（N = 7 時 14.3%、N = 35 時 2.9%），不影響斷言判定，但決定下游決策之實質偏誤程度。

### 4.6.4 E7：守恆式繞過的精確性要求

攻擊者欲繞過 C_i，須使全域聯集之**淨變化恰為零**。此可透過等量替換達成（同窗刪除 k 個既有 IMSI、新增 k 個假 IMSI），**不必然需要知道 N_known 之絕對值**；但攻擊者須確保被刪之 IMSI 未同窗出現於其他 cell、假 IMSI 不與既有母體重複，且替換須不破壞成員轉移之連續性（H_i）。以 D-C（600 窗）逐窗注入各種增刪組合：

| 注入組合（假/真） | 淨變化 | 偵測率 |
|---|---:|---:|
| +2/−2、+3/−3、+1/−1、+4/−4 | 0 | **0 / 600 = 0%** |
| +2/−1、+3/−2、+1/−0 | +1 | **600 / 600 = 100%** |
| +1/−2、+2/−3、+0/−1 | −1 | **600 / 600 = 100%** |

**完美二分**：淨變化為零者全數繞過，任何 |淨變化| ≥ 1 者全數偵測。C_i 並非提高攻擊成本之統計門檻，而是**不容許任何近似之離散約束**——攻擊者之配平容錯空間為 **0**。

### 4.6.5 E8：單一 O-DU 虛減之攻擊面

**觀測前提**：本研究資料中，UE 於任一窗僅出現於單一 cell——12,600 個 (窗, UE) 樣本中，**同窗同時掛載 LTE 錨點與 mmWave cell 者為 0**（mmWave-only 42.3%、LTE-only 57.7%）。故「UE 雙掛使單點刪除不改變全域聯集」之遮蔽情境於本組態下不存在。

單一受攻擊 O-DU 之虛減能力因此受兩重結構限制：

1. **僅能抹除當窗掛載於其上之 UE**——未掛載於該 cell 之 UE 不在其上報範圍內。
2. **此類抹除必然造成全域聯集淨減**（無其他 cell 同時持有該 IMSI）。故**於可發動虛減之窗（該 O-DU 當窗至少掛載 1 UE）中，C_i 之條件偵測率為 100%**；無可攻擊目標之窗代表攻擊無從發動，不納入偵測率分母。

**攻擊面量化**（圖 4-4）：全場域每窗掛載於 mmWave 之 UE 數 mean = 2.96（1.5% 之窗為 0）；逐 O-DU 差異顯著：

| O-DU | 每窗可抹除 UE 數 (mean) | 無可攻擊目標之窗比例 |
|---|---:|---:|
| cell 2 | 0.89 | 33.3% |
| cell 3 | 0.52 | 54.5% |
| cell 4 | 0.45 | 59.8% |
| **cell 5** | **0.04** | **96.2%** |
| cell 6 | 0.36 | 70.2% |
| cell 7 | 0.28 | 71.8% |
| cell 8 | 0.42 | 66.0% |

**意涵**：虛減方向之攻擊幅度存在結構性上限（受該 O-DU 當窗掛載數限制），灌水方向則無此限制。cell 5 於 96.2% 之窗無可抹除目標，即使被完全攻陷亦多數時間無法發動虛減。

> **與 E2a 全域壓制之區分**：若攻擊者能同時竄改 LTE 錨點與所有 mmWave 節點之上報，N_total 亦淨減、同樣 100% 觸發；惟該能力超出單一 mmWave O-DU 之威脅模型。

### 4.6.6 E3：守恆式串謀盲點（核心涵蓋邊界）

| 攻擊 | N_total | 斷言 |
|---|---|---|
| 守恆式串謀（+2 假 / −2 真） | 7 | conserved（繞過 C_i） |

**這不是 C_i 之缺陷，而是攻擊滿足了被監控之性質。** 完整性 R(t) = P ⟹ |R(t)| = |P|，反向不成立，故基數守恆為完整性之**必要非充分條件**。此邏輯地推導出其他殘差之必要性：

- 被替換 UE 憑空增減 → 無合法成員轉移軌跡 → 破壞 **H_i**（守恆式替換之**主要防線**）。
- **僅當**替換同時造成被攻擊節點之 delay 偏離同窗共識時，才被 **S_i** 捕捉——S_i 只看 delay，偽造 IMSI 若使用正常 delay 未必破壞 S_i，故 S_i 為條件性佐證（此為 4.11 融合回放中「守恆式替換 S_i = normal」之依據）。

此結構與電力系統狀態估計中之不可觀測偽資料注入（unobservable false data injection）同構：滿足系統約束之注入可繞過殘差檢測。圖 4-2 視覺化此盲點。

### 4.6.9 歸因、複雜度與有效性威脅

**第一層歸因**：`new_imsi = 場域聯集 − known_population`；`candidate_cells = {j : reported(j) ∩ new_imsi ≠ ∅}`。灌水可鎖定嫌疑 cell；虛減無法反查（須 H_i 佐證）。灌水之識別機制與身分偽造（Sybil attack）偵測同構。

**有效性威脅**：
- **建構有效性**依賴窗對齊（缺對齊緩衝會產生假性違反，屬工程問題非不變量缺陷）。
- **E8 之攻擊面刻畫**受本組態之 MC 連結行為影響——若真實部署中 UE 確實同窗雙掛，遮蔽情境可能重新出現，屆時 C_i 對單點虛減之偵測率將低於 100%。
- **L_C 政策脆弱性**（E6）：跨窗累計政策尚未評估（【待填：E11b】）。
- **外部有效性**限於封閉、母體固定之 SNPN；600 窗不構成全域證明。

## 4.7 S_i：跨節點同時態共識驗證

### 4.7.1 定位與資料可觀測性

S_i 驗證「此節點之觀測是否被同一時刻之其他節點支持」。

**為何以延遲為偵測維度**：同窗跨 cell 之延遲變異係數中位數為 **0.052**（n = 1,086 窗），而 per-UE 差分後吞吐量之變異係數中位數為 **0.77**（n = 56），離散度相差一個數量級以上。延遲於同一時刻之跨 cell 分布緊密，可作為共識參照；吞吐量過於分散，且缺 PRB/CQI 之硬約束。UE 數則屬 C_i 之守備範圍。**此維度選擇由資料之經驗可觀測性決定，而非預設攻擊落於延遲。**

**證據可用性**：跨節點共識需要同窗至少有其他活躍節點可比。以 D-SH 中至少一個 mmWave cell 活躍之 1,190 窗為分母：

| 同窗活躍 mmWave cell 數 | 受測節點之 peer 數 | 層級 | 窗數 | 比例 |
|---|---|---|---:|---:|
| 1 | 0 | unavailable | 137 | 11.5% |
| 2 | 1 | weak evidence | 401 | 33.7% |
| ≥ 3 | ≥ 2 | full consensus | 652 | 54.8% |

即 88.5% 之窗至少具備 weak evidence，但僅 **54.8%** 具備 full consensus。

### 4.7.2 S_i 定義

設同窗活躍 mmWave cell 集合為 $\mathcal{A}(t)$，受測節點為 $j$。

**中心共識估計**（同一時刻其他節點之即時共識，排除受測節點本身）：

$$c_j(t) = \operatorname{median}_{\,k \in \mathcal{A}(t)\setminus\{j\}} \big\{ \mathrm{delay}_k(t) \big\}$$

**全域尺度因子**（由訓練 seed 之乾淨軌跡估計，LOSO 下不含 held-out seed）：

$$s = 1.4826 \cdot \mathrm{MAD}_{\text{global}}$$

**共識殘差與判定**：

$$z_j(t) = \frac{\big|\, \mathrm{delay}_j(t) - c_j(t) \,\big|}{s}, \qquad S_i \text{ violated} \iff z_j(t) > \tau_S \;\;(\tau_S = 4)$$

- **（空間性）** 中心取自同一時刻其他 cell，故 $z_j$ 度量節點對場域即時共識之偏離，非對自身歷史之偏離。
- **（尺度固定、中心動態）** 尺度與門檻由乾淨資料一次估計後固定；中心每窗即時計算。因中心不含受測節點，單點漂移無法拖動參照。
- **（尺度穩定）** 同窗活躍 cell 數少（N ≤ 7），即時 MAD 有小樣本高變異問題，故尺度由全域乾淨資料估計；1.4826 使 MAD 成為常態標準差之漸近一致估計量。
- **（每窗獨立）** 不累積歷史殘差。

**證據不可得之處置**：本研究以 MIN_PEER = 2 為判定門檻，即僅於 full-consensus 窗判定 S_i；weak evidence（peer = 1）與 unavailable（peer = 0）均視為證據不可得，依 4.4.0 判為 abstain（`R3_ABSTAIN`）；若同窗另有其他殘差之證據，則依規則順序由 L1 或 L2 先行判定。**abstain 為「暫緩採信」而非「預設通過」**，避免攻擊者利用離峰空窗或壓制鄰居 cell 以規避 S_i；C_i 之基數守恆為不依賴 peer 之防線，不受此影響。

> **定位收斂**：延遲之低離散度僅證明各 cell 數值相近，不直接證明受單一共同物理因素約束。S_i 定位為**場域即時共識殘差（field-wide contemporaneous consensus residual）**，其偵測效力由實驗支持，不對物理詮釋作過度宣稱。

### 4.7.3 核心論證：參照機制之轉換

> 時序偵測器問：「此節點是否與**自己的過去**一致？」
> S_i 問：「此節點是否與**此刻其他節點的共識**一致？」

S_i 之貢獻不在 median、MAD 或 τ_S 之選擇，而在**把異常偵測之參照基準，從節點自身之時間歷史換成同一時刻其他節點之空間共識**。

**為何滑動更新之自我參照對緩慢漂移失效**：以自身近期觀測為參照、且參照隨新觀測滑動更新時，足夠緩慢之偏移會被逐步納入參照本身——漂移成為新的局部常態，殘差因而始終落在門檻內。須限定：此論證適用於**隨近期觀測滑動更新之局部自我參照**；採凍結之長期基線、變點偵測（如 CUSUM）或雙時間尺度設計之偵測器不必然受此限，本研究未對其進行評估。

**為何同時態空間參照不受此限**：S_i 之參照取自同窗其他節點，不隨受測節點之漂移移動。偏移對著一條由誠實鄰居構成之基準累積，終將跨過 τ_S。漂移速率越低，此對比越明顯。

此主張於 4.7.4 以受控消融檢驗，並於 4.7.5 延伸至既有工作之攻擊模型。

### 4.7.4 主實驗：參照機制受控消融

**設計動機**：若以不同模型（如 LSTM）作為時序對照，偵測率差異可能同時源自參照機制、模型能力與資料條件，無法歸因。本實驗採**受控消融**：固定資料、尺度、門檻與攻擊，**僅變動參照中心一個變數**。

| 控制變數 | 設定 |
|---|---|
| 資料 | D-SH 之 mmWave cell delay，LOSO |
| 尺度 $s$ | 同一 global MAD（僅由 training seeds 估計） |
| 門檻 | 同為 τ_S = 4 |
| 攻擊 | 同一組 delay 線性漂移，序列中點注入 |
| 評估範圍 | 僅 full-consensus 窗（peer ≥ 2） |
| **評估區間** | **序列後半段（注入區間）；乾淨與注入於同一窗子集上比較** |
| **唯一差異** | **中心 = 同窗其他 cell 中位數　vs　自身前 10 窗中位數** |

兩種參照使用**相同之統計量與計算複雜度**（皆為中位數），故偵測率差異不可歸因於模型能力。

**結果**：

| 漂移速率（%/窗） | 空間共識參照 | 時間自我參照 | 差值 |
|---:|---:|---:|---:|
| **乾淨序列 FPR（注入區間）** | **0.037** | **0.014** | — |
| 0.1 | 0.04 | 0.01 | +0.03 |
| 0.2 | 0.09 | 0.01 | +0.08 |
| 0.5 | 0.26 | 0.01 | +0.25 |
| 1.0 | **0.54** | 0.01 | **+0.53** |
| 2.0 | **0.74** | 0.01 | **+0.72** |
| 4.0 | 0.86 | 0.14 | +0.72 |
| 8.0 | 0.93 | 0.92 | +0.01 |
| 15.0 | 0.96 | 0.95 | +0.01 |

**評估區間之界定**：漂移於序列中點注入，故乾淨與注入之偵測率均於序列後半段評估，以確保二者落在同一窗子集、可直接相減。乾淨誤報率 0.037 為此區間之數值（16 組 (seed, cell) 之 macro 平均，1,073 個 full-consensus 窗）。若改以全序列為分母，同一實作之空間參照誤報率為 0.070——此差異源自延遲離散度之啟動暫態，非實作不一致（見 4.7.7）。4.9 之 xApp 於全序列評估，其 S_i 誤報率（0.075）與本節分母不同，不可直接對照。

**核心發現**：

1. **低速區之分離**：於 ≤ 2%/窗之區間，時間自我參照之偵測率恆為 0.01（等同其誤報水準，即實質失效），空間共識參照達 0.26–0.74。此即 APT low-and-slow 規避之操作區。
2. **高速區之收斂**：≥ 8%/窗時兩者皆達 0.92 以上、差距降至 +0.01。時間參照之失效**並非全面性**，而集中於低速區。
3. **非門檻校準假象**：時間自我參照之乾淨誤報率（0.014）**低於**空間參照（0.037），故其低偵測率不能歸因於門檻過嚴——在更保守之誤報水準下仍幾乎無法偵測低速漂移，反證失效源於參照機制本身。

**攻擊動機**：RIC 依 KPM 進行負載平衡與換手決策，受攻擊 O-DU 持續灌高自身回報延遲可誘使流量導離，灌低則吸引流量至受控節點。理性攻擊者若採 low-and-slow 策略規避時序偵測，恰好落入空間共識參照仍有效之區間。

**樣本結構**：16 組 (seed, cell) 非獨立樣本（同 seed 內 cell 共用軌跡與共識參照），95% CI 以 seed 為 cluster 單位。（腳本 `run_Si_reference_ablation.py`）

### 4.7.5 E9：既有工作之攻擊模型下的操作區對照

**動機**：既有之 KPM 中毒偵測以學習式時序建模為主。Alimohammadi 等人提出 KPI 中毒攻擊並以 LSTM 偵測，自報偵測率介於 62% 至 99%，且放大倍數越大越易偵測（FNWF 2024）；其後續多層防禦框架之評估採放大因子 1.2／1.3／1.4／1.5 之階躍注入，報告攻擊偵測率 ≥ 97.9%，並自承可能漏掉緩慢隱蔽之中毒模式（arXiv:2512.01596）。4.7.4 顯示時間自我參照之失效集中於低速漂移區間——**本實驗檢驗：既有工作之評估是否恰好落在兩種參照皆有效之高幅度區間**。

**設計**：沿用 4.7.4 之全部控制變數（資料、尺度、門檻、評估範圍、評估區間），僅擴充攻擊族：

| 攻擊族 | 注入方式 | 參數 |
|---|---|---|
| **階躍放大**（既有工作之攻擊模型） | 注入起點後，受測 cell 之 delay 乘以放大因子 AF | AF ∈ {1.2, 1.3, 1.4, 1.5} |
| **漸進漂移**（本研究，同 4.7.4） | 注入起點後，偏移每窗遞增 r% | r ∈ {0.1, 0.2, 0.5, 1, 2, 4, 8, 15} |

**指標**：注入區間偵測率；階躍族另報 onset 命中率（注入後前 5 窗內是否至少觸發一次），用以區分「起始點被捕捉後遭吸收」與「起始點即未被捕捉」。

### 4.7.7 有效性威脅

- **門檻選擇層級之洩漏**：τ_S = 4 之操作點由全體 seed 掃描選定，非 per-fold 校準；尺度 $s$ 已隔離 held-out seed，惟門檻本身未納入 LOSO，屬初步實驗限制。

## 4.8 H_i：跨小區成員轉移一致性驗證

> **定位**：H_i 負責**成員轉移可信度**之驗證，補上 C_i 之涵蓋邊界（4.6.6 守恆式串謀）。D1 以 Hampel identifier 之 robust z 量化證據強度，D2 為架構斷言；二者之輸出經 4.4.0 之規則映射為信任狀態。

### 4.8.1 兩個維度與乾淨基線

| 維度 | 乾淨基線（實測） | 判定型態 |
|---|---|---|
| **D1 成員消失** | UE 掛 LTE-only 之停留呈雙峰：97% ≤ 12 窗，長尾集中於 edge UE；所有事件最終回歸 | 非參數（Hampel robust z） |
| **D2 成員瞬移** | UE 之 serving mmWave cell 於單次執行內皆維持固定；任何跨 mmWave cell 轉移（含經 LTE 者）於 D-SH 全部執行中皆未發生 | 架構斷言 |

### 4.8.2 D1：為何非參數

卡方適合度檢定比對停留時間與幾何分布：常駐群 χ² = 38.5、邊緣群 χ² = 58.1、全體 χ² = 191.4，均遠超臨界值（≈ 13）——分布因雙峰重長尾顯著偏離單一參數族，故採非參數方法。

### 4.8.3 D1：Hampel identifier

**（a）Hampel identifier**（Hampel, 1974；Leys et al., 2013）：

    z_d(x,t) = ( d(x,t) − median_x ) / ( 1.4826 · MAD_x )

$d(x,t)$ 為當前連續 LTE-only 停留窗數。$z_d$ 即 robust z（與 S_i 同一統計量，門檻各自校準）。MAD = 0 時尺度取 1 窗之下限。

**基線**：採 **per-UE-index 基線**——跨 run 以 IMSI 編號彙整停留事件（同號 UE 於不同 run 之位置不同，故非部署意義下之個別裝置基線）；事件數 < 8 時退回 resident／edge 群層級經驗分布。基線由乾淨資料一次估計、**永不線上更新**——否則攻擊者可緩慢養高某 UE 之停留以撐大門檻，此即 4.7.3 所述滑動更新參照之同一弱點。此需 clean bootstrap（信任根）假設。

**（b）經驗 p 值**：

    p_emp(x,t) = ( 1 + |{ d' ∈ 乾淨停留(x) : d' ≥ d }| ) / ( n + 1 )

採 (1+·)/(n+1) 避免有限樣本得 0。$p_{\text{emp}}$ 作為事後解釋性統計（其隨注入強度單調下降），**不參與 4.8.5 之證據分級**；z 與 p 之聯合決策為實作已支援之設定，列為後續敏感度分析。

### 4.8.4 D2：觀測層級之瞬移斷言

```
teleport(x,t) := (x 於 t−1 掛 mmWave A) ∧ (x 於 t 掛 mmWave B≠A) ∧ (中間無 LTE-only 過渡窗)
D2 violated ⟺ ∃x: teleport(x,t)
```

此判準於身分安全領域稱為 impossible travel detection：同一身分於時間上不可能之位置轉移。

**乾淨基線與其限制**：D-SH（4 seed × 300 s，1,200 窗，28 個 UE-run）中跨 mmWave cell 之轉移為 0；D-C（10 seed × 60 s）亦為 0。**須誠實指出：合法之跨 cell 轉移本身即未發生**，故乾淨基線為 0 屬 vacuous，「必經 LTE 錨點」之規則未曾經合法換手檢驗。注入瞬移（28 個 UE-run，目標 cell 以確定性公式指定）得 TPR = 100%、FPR = 0，**屬設計必然（by construction）**。

### 4.8.5 D1 與 D2 於融合規則中之角色

> 信任狀態之定義與判定條件見 4.4.0，此處不重複定義。

#### （一）證據強度與規則代碼之對應

$H_i$-D1 之輸出為**證據強度**，而非信任狀態：

| $H_i$ 輸出 | 條件 | 於 4.4.0 中觸發之規則 | 單獨成立時之狀態 |
|---|---|---|---|
| D2 violated | 存在瞬移事件 | `R1_D2_VETO`（L1） | rejected |
| D1 = strong | $z_d \geq \tau_H^{\text{reject}}$ | `R2_D1_STRONG`（L2） | low-trust |
| D1 = strong，且 $S_i$ 同窗違反並指向同一節點 | — | `R2_SI_D1_BOUND`（L2） | rejected |
| D1 = strong，且 $S_i$ 同窗違反但指向不同對象 | — | `R2_SI_D1_UNBOUND`（L2） | low-trust |
| D1 = warning | $\tau_H^{\text{warn}} \leq z_d < \tau_H^{\text{reject}}$ | `R2_D1_WEAK`（L2） | low-trust |
| D1 = none | $z_d < \tau_H^{\text{warn}}$ | 不觸發 | 由其他殘差決定 |

**D1 本身不產出信任狀態**。最右欄為該證據於其他殘差均無異常時經 4.4.0 所得之結果；同窗若另有 $C_i$ 違反或 D2 瞬移，則 L1 優先。D1 單獨成立時僅影響其所歸屬之節點（UE 綁定，4.9.6.5）；無節點可歸屬之 D1 證據留存為 UE 層級紀錄，不改變任何節點之信任狀態。

#### （二）D2 為硬否決、D1 不為硬否決之理由

**D2 為架構斷言**：UE 更換 serving mmWave cell 必經 LTE 錨點過渡，「前一窗掛 A、當窗掛 B、中間無錨點過渡」構成結構上不應出現之觀測，其判定不依賴可調門檻，故與 $C_i$ 同置於 L1。

**D1 為統計推論**：判定結果依賴 $\tau_H$ 與基線品質。更關鍵者為裝置並非同質——結構性訊號較差之 UE 長時間掛載於錨點屬其正常移動性行為，其誤報率顯著高於常駐 UE（4.8.6）。**若允許 D1 單獨硬否決，此類正常行為將直接導致誤拒。** 4.8.6 之 edge UE 高誤報率並非對本設計之否定，而正是本設計之依據。

#### （三）交叉佐證之綁定要求及其限制

`R2_SI_D1_BOUND` 要求兩項證據指向同一節點。然 D1 量測**連續 LTE-only 停留窗數**，觸發 D1 之 UE 必然掛載於 LTE 錨點。**若以「當窗掛載之 cell」為歸屬依據（window 對照政策），該規則不存在合法觸發路徑**（實測見 4.9.6.2）。定案之 uebound 政策以「UE 消失前之 serving mmWave cell」為歸屬依據，同時適用於 D1 單獨成立與交叉佐證兩種情形；此修正使交叉佐證首次可觸發，代價為乾淨資料上出現 6 筆誤拒（4.9.6.5）。

- **D2 之粒度依賴**：1 秒粒度下成立；粒度遠小於換手歷程時退化，須改鄰接矩陣判據。
- **D2 之合法過渡規則未經檢驗**：本場景缺乏跨 cell handover，真實移動性下之誤報率未驗證。
- **per-UE-index 基線**：LOSO 下無法對齊 held-out seed 之 UE 個體身分，屬 LOSO 架構之固有限制；部署上宜於冷啟動時採群組基線、累積乾淨歷史後切換為裝置層級基線。
- **clean bootstrap 假設**。
- **edge UE 敏感度**：須交叉佐證；分群門檻之穩健性待敏感度分析。
- **證據綁定粒度**：D1 證據以 UE 為單位，註記以 (節點, 窗) 為單位。本研究定案採 UE 綁定（4.9.6.5），其代價為 76.9% 之 D1 告警無節點可歸屬而僅留存為 UE 層級紀錄；以「UE 消失前之 serving cell」為歸屬依據使 D1 與 S_i 之交叉佐證可觸發，於乾淨資料上產生 0.19% 之誤拒（4.9.6.5）。
- **樣本規模與外部有效性**：4 seed CI 寬；外部有效性限於封閉 NPN、固定拓樸、MC 架構。

## 4.9 C-ZT 三 xApp 架構、動作模式與運算開銷

### 4.9.1 定位與實作層級

本節將三類一致性證據與階層式融合組織為三個職責分離之 xApp——Detection、Trust Assessment、Policy Enforcement（合稱 C-ZT）——並量測其運算開銷。E2 Termination、Subscription Management 與 shared data service 為 Near-RT RIC 平台之既有功能，非本研究之貢獻。

**實作層級之誠實聲明**：

- 三個模組之邏輯（逐窗對齊、三類證據之計算、階層式融合、依信任狀態產生准入動作）已實作並於重放 trace 上執行。三者目前於同一行程（`zt_kpm_xapp.py`）內依 P1→P2→P3 依序執行，模組間之 evidence record、trust state 與 admitted view 以行程內資料結構傳遞，未經 RIC 之 shared data service 與訊息匯流排。故本章所驗證者為各模組之邏輯及其介面內容，而非三個獨立部署之 xApp 間之通訊。
- **資料入口為 trace replay，E2 訂閱綁定尚未完成**（見 4.2.5）。程式以 `IndicationSource` 抽象層隔離資料來源，將 `TraceReplaySource` 替換為 `E2SubscriptionSource` 即可接上 live RIC，驗證邏輯無須改動。
- Policy Enforcement 對合作消費端之效果以離線決策重放評估（4.12），未涉及 runtime 控制。
- 運算開銷量測反映驗證層之計算成本，**不含 E2SM-KPM 解碼與 SCTP 傳輸延遲**。

### 4.9.2 模組定義與程序

![C-ZT 架構圖](【待填：新版三 xApp 架構圖之連結】)

| xApp | 職責 | 輸入 | 輸出 |
|---|---|---|---|
| **① Detection** | 將各 E2 節點（含 LTE 錨點）之上報對齊至 1 秒窗；計算 C_i、S_i、H_i-D1、H_i-D2；記錄每項證據之適用對象（場域／cell／UE）與可得性 | E2SM-KPM 上報（REPORT style，granularity period = 1 s）；已知 UE 母體；凍結基線 | evidence record |
| **② Trust Assessment** | 套用 4.4.0 之階層式規則、交叉佐證之綁定檢查與持續窗條件 | evidence record | 逐 (節點, 窗) 之信任狀態、觸發規則代碼與佐證證據 |
| **③ Policy Enforcement** | 依設定之准入政策將信任狀態轉為 allow／restrict／exclude／defer，並發布 policy-admitted KPM | 信任狀態；准入政策設定 | policy-admitted KPM、註記與 execution record |

**程序**：

| 程序 | 內容 |
|---|---|
| 初始化 | 載入已登記之節點身分、已知 UE 母體（N_known）、凍結基線（S_i 之全域尺度 $s$、H_i-D1 之停留基線）與政策設定（τ_S、τ_H、L_C、MIN_PEER、准入政策） |
| **P1** 證據偵測 | 對齊上報；計算一致性證據及其適用對象與可得性 |
| **P2** 信任評估 | 套用融合規則與狀態轉移條件，產出信任註記 |
| **P3** 政策執行 | 套用准入政策，發布 policy-admitted KPM 並記錄執行結果 |
| 平行評估 | Resource-policy evaluation：以資源准入決策與容量參考評估保留之可用容量（離線，見 4.12） |

**evidence record 之欄位**：C_i 之 `n_total` 與嫌疑 cell；S_i 之 $z$ 值與 peer 數；D2 之瞬移 IMSI 與來源／目的 cell；D1 之 $z_d$ 值、對應 UE 及其歸屬節點（4.9.6.5）。每筆信任註記含決策、觸發規則代碼與上述證據欄位；證據隨決策一併發布，使消費端與稽核者可追溯判定依據。

**execution record 之欄位**：逐窗記錄 allow／restrict／exclude／defer 之節點、准入之節點（admitted）、defer 之 fallback 設定、`out_of_scope`（LTE 錨點）、`unannotated`（應受判定之 mmWave 節點卻缺少註記者，用於發現實作缺漏），以及窗之處理狀態（`processed` 或 `n/a`）。

**execution-status 回饋**：架構圖中由 Policy Enforcement 回送 Detection 之 execution status（目前生效之限制）為**提出之介面**，本研究未實作亦未評估；現行之證據計算與判定均不依賴此回饋。

### 4.9.3 動作模式：對合作消費端之准入，而非攔截

**權限邊界**：O-RAN 架構下各 xApp 獨立向 Near-RT RIC 訂閱 E2 資料，由平台之 subscription management 管理並執行授權（xApp-TR §4.2【核對：簡報 R5 另引 RICARCH v08 §6.2.2，該條尚未列入 Citation Map v2】）；C-ZT **無權阻斷其他 xApp 之訂閱或攔截 KPM 資料流**。四種可能之動作模式比較如下：

| 模式 | 機制 | 標準相容性 | 代價 | 本研究 |
|---|---|---|---|---|
| 註記型 | 發布信任狀態與證據至共享資料層 | 相容（需消費端配合） | 保護效果取決於消費端是否採用註記 | **✓**（Trust Assessment 之輸出） |
| 中介型（限合作消費端） | Policy Enforcement 發布 policy-admitted KPM，合作之消費端改讀此視圖 | 相容（需改變該消費端之資料來源） | 增加一跳延遲；Policy Enforcement 成為該消費端之單點故障與新攻擊目標；未合作之 xApp 不受保護；時間敏感 xApp 需保留直接存取路徑 | **✓ 採用**（離線評估，4.12） |
| 攔截型 | 攔在 KPM 流前，僅轉發 trusted 資料 | 非標準（O-RAN 無此角色） | 需平台層權限 | ✗ |
| 告警型 | 僅寫日誌，不介入決策 | 完全相容 | 保護力最弱 | 併入 execution record |

中介型之一例為 Alimohammadi 等人之框架：其中毒偵測 xApp 將驗證後之 KPM 存入共享資料庫，其他 xApp 改由資料庫取用，並保留超時間敏感 xApp 之直接存取路徑（arXiv:2512.01596）。本研究與之同屬此類，差異在於准入之依據為 4.4.0 之信任狀態及其可追溯之證據。

**信任狀態與動作之對應**：

| 信任狀態 | 動作 | 於 policy-admitted KPM 中之處置 |
|---|---|---|
| trusted | **allow** | 原值納入，附註記 |
| low-trust | **restrict** | 依准入政策設定：`strict` 自決策輸入排除；`restrict_annotated` 附限制註記後納入。兩種設定之下游差異見 4.12 |
| rejected | **exclude** | 該 (節點, 窗) 之量測不納入；寫入 execution record |
| abstain | **defer** | 於任何准入政策下皆不進入 policy-admitted KPM，待後續窗重新判定。fallback 政策（例如消費端改採其他資料來源）另行定義，且**不得使該筆量測回到 admitted view**；本章評估之 fallback 為 `none`，即消費端當窗不取得該節點之輸入 |

**准入政策**：`strict` 僅准入 allow；`restrict_annotated` 准入 allow 與 restrict（restrict 附限制註記）。exclude 與 defer 於兩者下皆不准入。實作以不變式檢查之：strict 下非 allow 之准入為 0 筆，restrict_annotated 下 defer／exclude 之准入為 0 筆。

**LTE 錨點**：LTE 錨點之 KPM 為驗證用之輔助輸入，不在本次准入政策之作用範圍內，於 execution record 記為 `out_of_scope`。其未進入 admitted view 之原因為不在作用範圍，**不代表 rejected 或 defer**。

**作用範圍**：Policy Enforcement 僅作用於合作消費端（本研究以 RC xApp 為例）之 KPM 輸入。C-ZT 不下達 E2SM-RC control、不阻斷其他 xApp 之訂閱，亦不對 E2 節點採取任何動作。rejected 之精確語意為**該筆量測不進入 policy-admitted KPM 並留存執行紀錄**，非判定該節點為攻擊者。驗證服務與政策設定假設位於攻擊者控制之外。向管理面之通報不在本研究之架構範圍內。

### 4.9.4 唯讀信任根

Detection xApp 之基線——per-UE-index 停留分布（H_i-D1）與全域尺度 $s$（S_i）——於**啟動時由乾淨資料載入後永不線上更新**。須區分：S_i 之**尺度與門檻**固定，**中心**則每窗由同窗其他節點即時計算；後者屬同時態參照，非固定參照。

**設計理由**：若基線隨線上資料更新，攻擊者可藉緩慢注入逐步養高門檻，使後續大幅偏移仍落於「正常」範圍——此即 4.7.3 所述滑動更新參照之結構性弱點。凍結基線使此規避路徑失效，代價為需要 **clean bootstrap 假設**。4.7.7 之非穩態結果顯示，基線與判定均不宜於場域啟動暫態期間取得或投入。

原始 mean 之跨 seed 差異為 2.56 倍；以每次 full-consensus 判定攤提後降至 **1.19 倍**，故差異源自各 seed 之活躍節點數與 S_i 提早返回比例，非量測不穩。

**成本模型與擴展性外推**：以同機器、同程序下兩個操作點（逐節點評估：每窗 0.303 ms／1.84 次 full-consensus 判定；單節點評估：0.127 ms／0.54 次）解聯立：

$$t_{\text{window}} \approx F + S \cdot n_{\text{full}}, \qquad F \approx 53\ \mu s,\quad S \approx 135\ \mu s$$

$F$ 為每窗固定成本（C_i 聯集比對、H_i-D1、H_i-D2、聚合），$S$ 為每受測節點之 S_i 共識計算成本。將提早返回節點之成本納為第三參數掃描（0–20 μs）時，$F$ 於 47–53 μs、$S$ 於 130–136 μs 間變動，分解對建模假設不敏感。外推（保守假設全節點均達 full consensus）：

| 節點數 N | 每窗開銷估計 | 佔 1 秒 granularity |
|---:|---:|---:|
| **7（本研究）** | **0.87 ms** | **0.087%** |
| 20 | 2.63 ms | 0.263% |
| 50 | 6.69 ms | 0.669% |
| 100 | 13.47 ms | 1.347% |

N = 7 之外推值（0.87 ms）與實測 P99（0.837 ms）一致，可作為模型之內部檢核。

**延遲分布之雙峰結構**（圖 4-14）：低峰對應 S_i 證據不可得而提早返回之情形，高峰對應完整執行三殘差者，與 $S \gg F$ 相符——S_i 之共識計算為主要成本項，且僅於證據充足時發生。

**範圍界定**：數值**僅涵蓋驗證層之計算成本**，不含 E2SM-KPM ASN.1 解碼、SCTP 傳輸與共享資料層寫入。外推另有三項限制：中位數運算為 $O(N \log N)$ 而非嚴格線性，大 N 之估計偏樂觀；C_i 之 O(M) 成本隨 UE 數成長，本外推固定 M = 7；單機離線量測未模擬 RIC 之併發負載。

### 4.9.6 融合規則稽核與乾淨資料上之決策分布

> 規則定義見 4.4.0，本節報告該定義之實作稽核結果。

#### 4.9.6.1 規則稽核之儀器化

為檢驗融合實作是否與 4.4.0 一致，xApp 加入規則稽核儀器：每筆註記除決策外，另記錄**觸發規則代碼**、**各殘差之原始判定**與**證據之綁定對象**，使「決策 × 觸發規則」可直接與規則表對帳。

稽核發現前版實作於第二層有兩處與規則陳述不符：其一，交叉佐證收受 H_i-D1 之 warning 證據，與「rejected 須 $z_d \geq \tau_H^{\text{reject}}$」矛盾；其二，未檢查兩項證據是否指向同一節點。修正後之規則即 4.4.0 所載版本。

#### 4.9.6.2 證據綁定之結構性發現

於 window 政策下之 3,150 筆有效節點註記中，H_i-D1 給出證據且同窗有 S_i 受測節點者共 2,258 筆，其中**證據指向同一節點者為 0 筆**。觸發 D1 之 UE 當窗掛載之 cell 集合恆為 {LTE 錨點}——此為定義使然：D1 量測連續 LTE-only 停留，觸發者必掛於錨點，與 S_i 受測之 mmWave 節點不可能重合。

其後果為：**以「當窗掛載之 cell」為歸屬依據時，4.4.0 之 `R2_SI_D1_BOUND` 不存在合法觸發路徑**；前版實作因未檢查綁定，將此結構上不可能之配對誤判為互相印證，於乾淨資料上產生誤拒（見下節）。定案之 uebound 政策改以「UE 消失前之 serving mmWave cell」為歸屬依據（4.9.6.5）；於該政策下，D1 證據依定義歸屬於受測節點本身（425 筆皆為同節點），故同節點比例不再具診斷意義，應改看 `R2_SI_D1_BOUND` 之觸發與其證據。

#### 4.9.6.3 乾淨資料上之決策分布（window 政策，E10 之對照基線）

於**未注入任何攻擊**之資料上，以 window 註記政策執行。分母為有效 (節點, 窗) 註記 **3,150** 筆；另有 **10 個無活躍 mmWave 節點之窗**，處理狀態記為 `n/a`，不產生節點註記。定案之 uebound 政策結果見 4.9.6.5：

| 層級 | 決策 | 觸發規則 | 筆數 | 比例 |
|---|---|---|---:|---:|
| L2 | low-trust | `R2_D1_STRONG` | 1,851 | 58.8% |
| L0 | trusted | `R0_CLEAN` | 742 | 23.6% |
| L2 | low-trust | `R2_D1_WEAK` | 308 | 9.8% |
| L2 | low-trust | `R2_SI_ALONE` | 93 | 3.0% |
| L3 | abstain | `R3_ABSTAIN` | 83 | 2.6% |
| L2 | low-trust | `R2_SI_D1_UNBOUND` | 73 | 2.3% |

決策彙總：trusted 742（23.6%）、low-trust 2,325（73.8%）、abstain 83（2.6%）、**rejected 0（0%）**。

#### 4.9.6.5 E10：D1 證據之節點歸屬政策——消融與定案

**診斷**：window 政策下，low-trust 中 2,159 筆（92.9%）由 H_i-D1 觸發（strong 1,851 + warning 308），其 C_i 判定均為 conserved。此為 4.8.6 所述 edge UE 高誤報率在窗層級之累積——該政策以「場域內任一 UE 之 D1 證據」標記該窗全部節點之註記。**此為證據綁定粒度之錯配，非 D1 判定本身之錯誤**，與 4.9.6.2 同源。

**政策**：

| 政策 | D1 證據之節點歸屬 |
|---|---|
| window（前版，對照） | 場域內任一 UE 之 D1 證據，標記該窗全部受測節點；交叉佐證之綁定依據為該 UE 當窗掛載之 cell |

**乾淨資料上之 6 筆 rejected**：uebound 使 `R2_SI_D1_BOUND` 首次具有合法觸發路徑，於乾淨資料上觸發 6 筆。逐筆以原始 trace 回推，D1 證據 UE 消失前之 serving cell 均為受測節點，**綁定正確**；6 筆之 S_i 均於最低共識門檻（peer = 2）下判定違反（z = 4.04–13.03），其中 5 筆位於同一 seed（4203）之 cell 8。**此 6 筆應報為乾淨資料上之誤拒事件（0.19%），不得解讀為攻擊偵測成功。**

- 76.9% 之 D1 告警無節點可歸屬，僅留存為 UE 層級紀錄。D1 對節點層級判定之貢獻因此有限，其主要作用轉為 UE 層級之稽核線索。
- UE 綁定使同窗之候選集由「全有全無」變為部分候選，於乾淨資料上引入新的誤排除成本（見 4.12.5（四））。
- 交叉佐證之觸發使乾淨資料出現 0.19% 之誤拒（上段）；window 政策下為 0。

**持續性政策（消融結果）**：本研究保留 $L_H = 1$。於本次 E10 之資料（D-SH，4 seed）與注入設定（超時消失，每個強度 26 次）下，$L_H = 2$ 僅使 trusted 比例增加約 2 個百分點（uebound 57.2% → 59.2%；window 23.6% → 29.0%），卻使 z = 2.0 之注入完全漏偵（偵測率 1.00 → 0.00），且平均偵測延遲增加 1 窗（3.6 → 4.6）；$L_H = 3$（window）之漏偵延伸至 z = 2.5（0.08）與 z = 3.0（0.65）。此取捨僅就上述資料與注入設定成立，不外推至其他移動模型或攻擊型態。

**一致性檢查**：E10 之 P0 與 P3 須以相容模式重現前版計數（742／2,335／83／0 與 1,813／575／766／6，n = 3,160，含 10 筆 node = None 窗級註記），且其餘有效節點註記與現行版本逐筆一致，否則不採計。本次執行兩者皆通過。

**界定**：low-trust 應解讀為「存在至少一項需交叉佐證之證據」，而非「資料不可信」。於定案政策下，57.2% 之註記可直接採信；其餘註記之下游影響取決於 Policy Enforcement 對 low-trust 之 restrict 設定（4.12）。

## 4.10 對抗性分析：偽造信任證據所需之最小攻陷

### 4.10.1 方法論定位

採 **分析論證 + 單元件實測 + 多節點離線合成注入**，**非 N 節點端到端模擬**。多節點（m ≥ 2）為離線合成——將 active-cell set 中 m 個節點之 delay 設為同一偽造值以模擬協同上報，active cells < m 時該窗跳過。宣稱限定為組合下界。

### 4.10.2 攻擊者模型

控制 m 個 mmWave 節點（身分合法、可任意竄改），目標使偽造量測於 S_i fail-to-reject，白箱知識。**限制**：無法控制 LTE 錨點（信任根）、未攻陷節點與物理世界。定義：

$$m^*_{S,50} = \min\{\, m : P(\text{bypass} \mid \text{full consensus}) \geq 0.5 \,\}, \qquad m^*_{S,100} = \min\{\, m : P(\text{bypass} \mid \text{full consensus}) = 1 \,\}$$

### 4.10.3 抗串謀強度

攻擊者將 m 個節點之 delay 同步偽造為「場域共識 + 6σ」。以每個（窗, m-子集）為一次 trial，依受控目標 cell 之 peer 數分三層，分母嚴格分離；unavailable 屬證據不可得，不計入有效繞過：

| m | full-consensus trials (peer ≥ 2) | full-consensus bypass | weak (peer = 1) | unavailable (peer = 0) |
|---|---:|---:|---:|---:|
| 1 | 2,211 | 45（2.0%） | 28/802（3.5%） | 137/137 |
| 2 | 2,753 | 1,630（59.2%） | 401/401（100%） | 0 |
| 3 | 1,513 | 1,513（100%） | — | 0 |
| 4 | 351 | 351（100%） | — | 0 |

（τ_S = 4，全域尺度 s = 0.069 ms，D-SH；`run_adversarial_msweep.py` 可重現。）

**結果**：$m^*_{S,50} = 2$、$m^*_{S,100} = 3$；單點之殘餘繞過率為 2.0%。

**機制**：單點（m = 1）僅控制受測 cell，無法改變由其他 cell 構成之中心 $c_j$，故於 full-consensus 窗幾乎無法繞過（2.0% 殘餘來自 peer = 2 窗之邊界效應）。m = 2 起攻擊者開始毒化共識本身：於 3 個活躍 cell 之窗中控制 2 個，使目標之 median{其他} 由 1 假 + 1 真構成而被拉向偽造值，$z$ 由 6σ 腰斬至約 3σ < τ_S；m ≥ 3（達場域中位數）則完全操控共識。

### 4.10.4 收斂宣稱

在本文定義之攻擊類別、1 秒觀測粒度、LTE 錨點可信且持續可觀測、且不允許合法 IMSI 重放之條件下，**尚未發現**可由單一 O-DU 同時繞過全部三類證據之路徑。**此為具明確假設之組合下界，非一般性不可達證明。**

單點攻擊於不同類別下通常被至少一項**適用之**驗證證據否證，但不存在「任一單點攻擊必然被某驗證器抓到」之完整性保證——守恆式替換繞過 C_i、S_i 於證據不足窗無法判定、單窗脈衝不升級為 rejected、純吞吐量竄改不涵蓋。$m^*_{S,50}$ 與 $m^*_{S,100}$ 僅為繞過 S_i 之局部成本；同時通過三殘差之聯合下界 $m^*_{CSH}$ 尚未量化。

## 4.12 資源—政策評估：排除不可採信量測後之可用資源與決策品質

> **定位**：本節回答 RQ3，為離線決策重放，與 4.11 屬同一方法論層級；未涉及 runtime 控制，亦無閉迴路。

### 4.12.1 問題與量之定義

RQ3 問：於排除被判定為不可採信之量測後，尚餘多少可用資源；此准入政策之可用性代價為何；驗證之運算開銷為何。運算開銷見 4.9.5；本節定義並評估前二者，另以一個代理決策評估下游決策之品質。

**資源准入遮罩（eligibility mask）**：對每個 (節點 $j$, 窗 $t$)，若 Policy Enforcement 之動作屬准入集合則 $m_j(t) = 1$，否則為 0。准入集合由准入政策決定（4.12.3）。

**保留可用容量比**：

$$\rho = \frac{\sum_t \sum_{j \in \mathcal{A}(t)} m_j(t)\, K_j}{\sum_t \sum_{j \in \mathcal{A}(t)} K_j}$$

其中 $K_j$ 為 cell $j$ 之容量參考，取自 **resource inventory（場域組態）**，而非受測節點上報之 KPM。須說明兩點：

1. 此量描述「其量測被准入、因而可供消費端納入決策之節點，其組態容量之佔比」。它不是量測到之頻譜使用量，亦不能用以驗證吞吐量上報——純吞吐量竄改仍未涵蓋（4.5.2）。
2. 本場景（configuration 1）之七個 mmWave gNB 採同一載波設定（中心頻率 3.5 GHz、頻寬 20 MHz，由 `scenario-three.cc` 之全域預設設定，無逐 cell 覆寫），故 $K_j$ 相同。分母 $\mathcal{A}(t)$ 取**當窗有上報之 mmWave 節點**；LTE 錨點為驗證用輔助輸入，不在准入範圍內；無活躍 mmWave 節點之窗（`n/a`）不產生註記，亦不在評估之窗內。$K_j$ 相同時，$\rho$ 於上式之彙總定義下即等於**可用量測產出率**（准入之註記佔全部註記之比例）；4.12.4 所報者即此量。

**政策引致之可用性成本**：乾淨資料上之 $1 - \rho$，即無攻擊時因誤報與證據不可得而未被准入之比例。

### 4.12.2 代理決策

為評估准入政策對下游決策之影響，定義一個明確之消費端代理決策：於窗 $t$ 為一新流量選擇服務 cell，準則為**回報延遲最低者**：

$$j^*(t) = \arg\min_{j \in \mathcal{M}(t)} \widehat{\text{delay}}_j(t)$$

其中 $\mathcal{M}(t) = \{\, j \in \mathcal{A}(t) : m_j(t) = 1 \,\}$ 為准入後之候選集。

**關鍵設計**：攻擊者謊報延遲以吸引流量，但被導向之流量**實際承受的是該 cell 之真實延遲**。故決策之代價以**真值**計算：

$$\text{regret}(t) = \text{delay}^{\text{true}}_{j^*(t)}(t) - \min_{j \in \mathcal{A}(t)} \text{delay}^{\text{true}}_j(t)$$

此評估方式與資訊物理系統中評估偽資料注入影響之慣例一致：攻擊影響的是決策，其代價須以真實狀態衡量。

### 4.12.5 四項發現

**（一）未經驗證時，延遲壓低攻擊之誘導率為 94.5%–98.1%。** 決策之真值代價上升 2.5%–3.3%。此為第一章所述攻擊動機之量化佐證。

**（二）准入對足夠幅度之攻擊有效，但對門檻下之攻擊反而有害。** 定案政策下，×0.6 階躍之誘導率由 98.1% 降至 2.8%；漸進 1% 由 94.5% 降至 16.9%，漸進 2% 由 96.7% 降至 11.2%。然 ×0.8 階躍（壓低 20%）落於 $\tau_S$ 之下，攻擊者未被標記，誘導率仍為 76.8%；而嚴格准入於 52.9% 之窗中濾除了真值最佳候選，使 regret 由未驗證時之 2.5% **反升至 3.4%**（window 對照亦為 3.4%）。**此顯示誤報率不僅是可用性問題：當攻擊落於偵測門檻之下時，誤報會轉化為安全問題。**

**（三）僅附註記或僅排除 rejected 之准入政策幾無保護效果。** S_i 違反於 4.4.0 下產出 low-trust 而非 rejected。window 政策下 rejected 為 0，`C_notrej` 之各項指標與 `C_none` 相同；`C_restrict_annot`（restrict 附註記後納入）之誘導率為 94.6%–98.1%，與 `C_none`（94.5%–98.1%）幾無差別。uebound 政策下，交叉佐證使少數量測被拒絕，`C_notrej` 之誘導率為 88.9%–95.6%、`C_restrict_annot` 為 84.8%–92.7%，保護效果仍有限。其意涵為：restrict 若僅附註記而仍納入決策輸入，Policy Enforcement 之輸出對下游決策之影響甚小。欲使保護生效，須將 restrict 設定為自決策輸入排除（即 `C_strict`），或使持續之 S_i 違反升級為 rejected（4.4.0（四），【待填：E12】）。另須注意 `C_notrej` 准入 abstain，違反 defer 不准入之原則，僅作寬鬆對照。

**（四）可用資源之多寡取決於證據綁定粒度。** window 政策下決策可用率僅 19.7%；定案之 uebound 下為 54.9%，保護效果大致維持。惟 uebound 於乾淨資料上引入 0.5% regret 與 9.2% 誤選——window 政策為全有全無（整窗候選集要嘛完整、要嘛為空），不會濾掉最佳而留下次佳；uebound 產生部分候選集，因而可能濾除真值最佳者。**細粒度換得可用性，代價為新增之誤排除成本。**

### 4.12.6 界定

- 導向策略為本研究定義之**代理決策**（單一新流、以延遲為唯一準則），非真實 RIC 排程器；未建模負載回饋與換手成本。
- $\rho$ 之容量參考來自組態而非量測；以 PHY 排程資源計算之版本待補（4.12.1）。
- 若消費端之目標函數依賴未被驗證之量（如吞吐量，4.5.2 之 B2），C-ZT 無法提供保護。本實驗以延遲為準則，正因其為 S_i 所驗證之維度。
- 攻擊僅含延遲類；基數類與成員類攻擊對下游決策之影響未評估。
- 本節為離線決策重放；消費端於閉迴路中之行為未評估。

## 4.13 本章總結

本章提出並初步驗證 C-ZT：以 Detection、Trust Assessment、Policy Enforcement 三個 xApp，持續評估 E2 量測資料之可信度並對合作消費端執行准入。在本 ns-O-RAN MC 場景與 1 秒觀測粒度下，就三項研究問題之結果如下。

**RQ1：上報值何時構成違反**

- **C_i** 能證偽造成全域 UE 聯集淨變化之上報資料，單點虛減於可攻擊窗中之條件偵測率為 100%；但對守恆式替換存在明確能力邊界（配平容錯空間 0），持續窗政策下之單窗脈衝亦不升級為 rejected。
- **S_i** 於受控消融中顯示，同時態跨節點參照於低速漸進漂移區間（≤ 2%/窗）之偵測率顯著高於時間自我參照；於 AF ≥ 1.3 之階躍攻擊下，時間自我參照能捕捉起始點（onset 命中率 0.88–1.00）但無法持續標記（注入區間偵測率 0.08–0.11），同時態參照則於偏移存續期間持續給出違反（0.62–0.96）；AF = 1.2 時兩者皆弱（4.7.5）。其證據可用率（full consensus 54.8%）與多節點共識操縱（$m^*_{S,50} = 2$、$m^*_{S,100} = 3$）限制其偵測範圍。
- **H_i-D2** 於本文粒度下提供觀測層級之架構斷言，惟其合法過渡規則未經合法換手檢驗；**H_i-D1** 對明顯超時消失具偵測能力，但 edge UE 誤報率偏高。

**RQ2：何時拒絕、依何證據、能否恢復**

- 本章**定義**四種信任狀態與階層式融合規則（4.4.0），以規則稽核揭露交叉佐證之證據綁定缺口，並以規則回放檢驗其決策一致性；每筆判定攜帶其觸發規則與證據。
- D1 證據之節點歸屬定案採 UE 綁定（UE 消失前之 serving mmWave cell）：乾淨資料上可直接採信之註記由 23.6% 升至 57.2%（分母為 3,150 筆有效節點註記），偵測率與延遲不變，代價為 76.9% 之 D1 告警無節點可歸屬，以及交叉佐證於乾淨資料上之 6 筆誤拒（0.19%）。
- 依規則，恢復為即時且無記憶；統計證據升級為 rejected 之唯一路徑為同窗交叉佐證（僅 uebound 下可觸發），$S_i$ 之持續違反不升級。轉移與恢復延遲之量測、重複短違反之效果與持續性升級規則【待填：E11／E11b／E12 之一句結論】。

**RQ3：保留之可用資源與驗證開銷**

- 未經驗證時，延遲壓低攻擊之誘導率為 94.5%–98.1%。定案政策與嚴格准入下，×0.6 階躍降至 2.8%、漸進漂移降至 11.2%–16.9%；惟落於偵測門檻下之 ×0.8 階躍幾無保護，且 regret 反升。
- 乾淨資料上之保留可用容量比 $\rho$ 為 58.0%（可用性成本 42.0%），決策可用率 54.9%；僅附註記（`C_restrict_annot`）或僅排除 rejected（`C_notrej`）之准入政策幾無保護效果。
- 驗證層之運算開銷於 P99 為 0.837 ms，佔 1 秒量測週期之 0.084%【核對：定案組態重測後更新】。

上述結果支持 E2 量測資料持續零信任驗證之**初步方法可行性**。尚未完成者：三類證據之聯合端到端效能、live E2 綁定與端到端延遲、三個 xApp 之獨立部署與其間通訊、閉迴路下之決策保護效果、以 PHY 排程資源計算之可用容量，以及吞吐量之 PRB/CQI 佐證。

## 第六部分：研究貢獻

### C1（對應 RQ1）：以場域為參照之違反檢查

本研究以三類受測節點無法單方面設定之參照檢驗其上報：已登記之 UE 母體、同窗 peer 之共識，以及以錨點為中介之移動規則，並以具真值之攻擊注入評估之。

- 基數守恆於 600 個乾淨窗中無反例；守恆式替換可繞過之，攻擊者之配平容錯空間為 0。
- 同時態跨節點參照於 ≤ 2%/窗之低速漂移下偵測率為 0.26–0.74，時間自我參照為 0.01（受控消融，僅變動參照中心）。
- 使 peer 共識之繞過率過半需 2 個節點，完全操控需 3 個。

> **驗證層級**：各檢查分別評估，攻擊為離線注入；三類證據之聯合端到端效能未量測。H_i-D2 之乾淨基線為 vacuous，其偵測率屬設計必然。

### C2（對應 RQ2）：階層式融合與可追溯之信任轉移

本研究定義四種信任狀態與階層式規則：硬違反優先、統計證據須佐證或持續方升級、證據不可得時 abstain。每次判定均記錄其觸發規則與證據，使規則表可對日誌重放。

- 規則稽核發現，以「當窗掛載之 cell」為歸屬依據時，交叉佐證規則無合法觸發路徑；該組態（window）下乾淨資料之誤拒為 0。
- D1 證據之節點歸屬定案採 UE 綁定（UE 消失前之 serving mmWave cell），可直接採信之註記由 23.6% 升至 57.2%，偵測率與延遲不變；交叉佐證因此可觸發，於乾淨資料上產生 6 筆誤拒（0.19%），綁定經逐筆回推確認正確。

> **驗證層級**：融合以真實量測窗上之規則回放驗證其決策一致性。恢復條件由規則導出，轉移與恢復延遲未量測【待填：E11】。$S_i$ 之持續性升級規則未實作【待填：E12】。

### C3（對應 RQ3）：KPM 准入政策下之資源可用性

本研究量化准入政策下相對於基線之可用容量、政策引致之可用性損失，以及驗證延遲相對於 near-RT 預算之比例。

- 未經驗證時，延遲壓低攻擊之誘導率為 94.5%–98.1%；嚴格准入下 ×0.6 階躍降至 2.8%，漸進漂移降至 11.2%–16.9%。
- 落於偵測門檻下之 ×0.8 階躍幾無保護，且決策代價反升；僅附註記或僅排除 rejected 之准入政策幾無保護效果。
- 乾淨資料上之保留可用容量比 $\rho$ 為 58.0%，即可用性成本 42.0%。
- 驗證層之運算開銷於 P99 為 0.837 ms，佔 1 秒量測週期之 0.084%【核對：定案組態重測後更新】。

> **驗證層級**：離線決策重放，決策為本研究定義之代理決策。容量參考取自場域組態；以 PHY 排程資源計算之版本待補。閉迴路下之效果未評估。
