## C. 會議紀錄原文（使用者提供，2026-11-19）

### Abstract

原則上已具備碩士論文所需的貢獻程度，授權層每秒約一次的請求量被認為可以接受。第五章的研究重點應從追求 Nash 均衡，轉向展示學習型攻擊者與學習型偵測端如何在持續對抗中產生新的攻擊與防禦情境，並評估偵測機制對未知攻擊的適應能力。

### 一、討論重點

1. **共同指導安排**：RT 已提出共同指導邀請，並獲得正面回覆；後續由 RT 透過正式程序處理。
2. **研究問題與貢獻更新**：新增一項研究問題，延伸「提高攻擊者適應能力」之建議。建立學習型攻擊者與適應型偵測端之對抗環境：攻擊者以強化學習尋找不易被偵測之攻擊策略；偵測端學習攻擊行為、持續改善偵測策略；雙方反覆互動產生新攻防情境。攻擊目標為誘導系統錯誤決策，防禦目標為辨識攻擊並降低影響。
3. **研究貢獻與論文可行性**：對抗式學習構想並非全新概念，需釐清貢獻與驗證方式。在波蘭學術標準下已具碩士論文可行性；台灣學校要求須另行確認；期刊或會議發表價值尚無明確結論。
4. **OAuth 2.0 授權層與資源評估**：DU 進入其他驗證前先向授權伺服器申請 token（含 scope 與短 TTL）；完成授權才進入後續驗證；未登記或已撤銷之 DU 於此被拒；之後進行資源評估，量化攻擊後之剩餘可用資源。短 TTL 屬常見設計；需評估授權請求數量與系統負擔；初估約每秒一次，可接受；請求量提高須重評估。
5. **三類連續驗證機制**：UE 數量守恆、鄰近節點一致性、成員轉移合理性。
6. **動態門檻設計**：固定門檻可能被適應型攻擊者利用（在門檻下方逐漸增加偏移）。加入學習型偵測端並以強化學習建立攻防環境；實驗涵蓋穩定、學習、高變異三階段。建議：門檻不應完全固定；現有門檻無法識別攻擊時偵測端應能調整；偵測策略與門檻皆可依攻擊者及環境狀態動態更新；須評估動態門檻對偵測率、誤報率與系統穩定性之影響。
7. **第五章核心方向：由 Nash 均衡轉向持續攻防演化**：持續演化之攻防環境中追求固定均衡可能無法反映研究目標，不宜以 Nash 均衡為主要成功判準。建議目標：展示學習型攻擊者與學習型偵測端能持續產生新攻防情境，並驗證防禦機制對未知攻擊之適應能力（類比 GAN）。可考慮之成功判準：攻擊者是否找到先前未出現之有效攻擊；偵測端是否識別新攻擊；攻擊改變後偵測端能否逐步恢復；攻擊者能否持續找到有效攻擊。偵測端有效辨識新情境可作為零信任防禦有效性之證據之一；攻擊者無法持續找到有效攻擊也可能反映防禦提升，但須排除探索不足。會議提及 PHP 安全問題為機器學習發現新攻擊之案例，未查證。
8. **實作流程與初步實驗**（轉寫品質差）：提供訓練資料持續改善攻擊策略；目前以兩個獨立學習者建立攻防賽局與完整管線；後續補充其他攻擊情境；先明確定義目標，再以初步實驗觀察實際行為；pipeline 不是唯一重點；下次討論以具體初步實驗結果為基礎。

### 二、會議結論

1. 共同指導：已獲正面回覆，透過正式程序處理。
2. 論文貢獻：具碩士論文可行性，須確認台灣學校要求。
3. 授權負載：每秒一次可接受。
4. 動態門檻：學習型偵測端應能調整偵測門檻，而非僅改變策略。
5. 第五章：核心目標為展示持續演化之攻防情境，不以 Nash 均衡為主要成功判準。
6. 後續：優先完成初步實驗。

### 三、與現有論文之設計差異（紀錄原文要點）

1. PSRO／NashConv：可考慮將 PSRO 定位為策略池擴展與探索機制；新策略與新攻擊情境之產生能力列為核心指標；NashConv 改為輔助指標；保留受限賽局之近似均衡分析但不解釋為全域收斂保證。
2. 固定 vs 動態門檻：τ_S、τ_H、L_C 目前固定；須評估哪些適合動態調整、是否納入 RL 動作空間、如何避免誤報過高、如何比較三種偵測。
3. 成功判準：第五章可能由收斂導向改為適應能力與策略多樣性導向；正式修改前先確認目標、指標與可行性。
