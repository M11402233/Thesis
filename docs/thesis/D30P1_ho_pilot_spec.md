## 1. 要回答的問題

- Q-A（有效性）：r11（模式 1，有效延遲樣本）加上 `--handoverMode=FixedTtt` 是否仍能正確運作？即，輸出與正式 D-30H（r8d）之非延遲檔一致，觀測不改變行為。
- Q-B（早期效果）：在相同 seed、相同窗（0–29）下，換手是否降低封包層級之 > 1 s 延遲占比？
- 限制：31 s 只能看到 ≤ 31 s 之延遲；長期中斷下之行為須全長資料（第 3 步）。

## 4. 指標（`scripts/r9/analyze_r11c_ho.py`；HO 與 NoAuto 以相同程式、相同窗 0–29 計算）

- M-H1：mmWave（cell ≠ 1）有效封包樣本數；延遲 > 1 s 之占比 R（逐 seed、合併）；中位數、p99、最大值；依 0–9／10–19／20–29 窗之 R。
- M-H2（機制，只對 HO 組之 > 1 s 樣本）：
  - 其 [首傳, 送達] 區間內該 UE 有換手開始事件者之比例；
  - 服務 cell SINR < −8 dB 之時間 ≥ 一半者之比例。
- M-H3：換手次數、換手時間（End − Start）之中位數與 p99、有 Start 無 End 者之數量（逐 seed）。
- M-H4：(UE, 窗) 至少有 1 個有效樣本之比例；(mmWave cell, 窗) 之有效 UE 數分布。
- M-H5：緩衝區滿丟棄之 SDU 數；結束時殘留。**不報「送達比例」**：換手後 RNTI 與 SN 改變，無法以 PDU 鍵配對，不可靠。

## 5. 判定（事先寫定；門檻為本規格之選擇）

| 判定 | 條件 |

| 換手使長尾明顯縮小 | R_HO ≤ 0.2 × R_NoAuto |
| 換手使長尾變大 | R_HO ≥ 1.5 × R_NoAuto → **停止，回報** |
| 無明顯差異 | 其餘 |
