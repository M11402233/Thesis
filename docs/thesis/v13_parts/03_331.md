#### 3.3.1 觀測基礎：逐 cell 歸屬之 RLC 統計與有效延遲樣本

**為何用 RLC 層**：ns-O-RAN 之 MC（Multi-Connectivity）雙連結架構下，PDCP 錨點固定於 LTE eNB（`DlE2PdcpStats.txt` 之 CellId 全部為 1），無 per-gNB 資料，S_i／H_i 需要之跨節點比對無從建立；故以 RLC 層統計為主要 KPM 來源。

**最終採用之量測定義**（第二階段；修正之原因、逐封包驗證與適用限制見附錄 A）：本研究使用之 ns-3 為修正建置 r11（`~/ns-3-mmwave-oran-r11`，`ZT_R7_S2=1`、`ZT_R10_RETX_TAG=1`；二進位與修改之原始碼以 md5 鎖定，4.0.3）。驗證所用之觀測量取自以下輸出：

| 輸出 | 內容 | 使用者 |
|---|---|---|
| `DlE2RlcStats_percell.txt` | 依**事件實際發生之 cell** 分帳之 RLC 統計（每 (cell, IMSI, LCID) 一列；計數自 t = 0 起累計，使用時逐窗差分） | S_i、H_i-D1 |
| `DlE2RlcStats_r11eff.txt`（及 LTE 版） | 有效延遲樣本之累計數與累計延遲和（定義見下），依 cell 分帳 | S_i |
| `R9_enb_uemap.txt` | 各 eNB／gNB 於報表時點之 RRC 連線 UE 名單 | C_i、H_i-D2 |
| `EnbHandoverStartStats.txt`、`EnbHandoverEndStats.txt`、`UeHandover*Stats.txt` | 換手之起訖事件（source、target、IMSI、時間） | H_i-D2 |

**有效延遲樣本**：一筆下行 RLC 資料 PDU 之接收事件，同時滿足（1）帶來至少一個先前未收過之位元組；（2）接收端判定將之放入緩衝；（3）帶有效時間戳。延遲平均之分子與分母使用同一批有效延遲樣本；控制 PDU、空分段、重複接收與被接收端丟棄者皆不計入。延遲之起訖點為 RLC PDU 交給 MAC 時打時間戳、至 UE 端 RLC 收到為止；重傳之 PDU 沿用首次傳送之時間戳，故重傳之等待時間計入延遲。須揭露三點：（i）與已收位元組部分重疊之 PDU 整筆計入、不按位元組比例切分；（ii）延遲平均受分段方式影響；（iii）重疊之位元組仍可能重複貢獻其延遲。部分重疊占有效延遲樣本與延遲總和之比例於 D-50PH 上量化【待定】，量化前不宣稱其影響小。此量與 3GPP `DRB.RlcSduDelayDl`（RLC SDU 之佇列延遲）及 OAI 之 SDU 滯留時間**不是同一個量**，本文不宣稱二者同義。

**觀測粒度（全章一致）**：E2SM-KPM indication 週期與分析窗均為 1 秒，二者對齊，每模擬秒一個聚合窗。由逐 cell 分帳之統計聚合出 cell 級觀測量（per window t, per cell j）：

```
d_{x,j}(t) = ΔDelaySum_{x,j}(t) / ΔNeff_{x,j}(t)        （UE x 於 cell j、窗 t 之區間平均延遲；ΔNeff = 當窗有效延遲樣本數，> 0 時方有定義）
DLY_j(t)   = median{ d_{x,j}(t) : ΔNeff_{x,j}(t) > 0 }   （cell 值 = 當窗於 cell j 有有效樣本之 UE 之延遲中位數）
U_j(t)     = | { x : x 於 t 之報表時點在 cell j 之 RRC 連線名單 } |
```

cell 值取 UE 延遲之中位數而非平均：少數連線暫時中斷之 UE 於恢復時一次送達之舊 PDU 帶有數秒以上之延遲，平均值會被其主導（附錄 A.3）；中位數使 cell 值代表該 cell 多數 UE 之狀態。以 PDU 合併平均之版本作為敏感度另報【待定】。

**當窗無有效樣本**：$\Delta N_{\text{eff}} = 0$ 之 (UE, cell, 窗) 無延遲值，**視為未知，不視為 0**；cell 當窗無任何有效樣本即不提供 S_i 之上報值，亦不作為他人之 peer（3.3.2）。

`IMSI` 對應 UE 識別（跨 cell 一致、可追蹤；其角色類比於 E2SM-KPM UE ID 中可跨節點對應之識別，如 `amf_ue_ngap_id`，此為類比，非等同）。

> **吞吐量前處理注意**：`RxBytes`／`TxBytes` 為累積 counter，非每窗流量，須以視窗差分計算；吞吐量不用於三類證據（3.3.5）。
