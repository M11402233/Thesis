## 第五章　規則下限上之學習型偵測端：持續攻防演化、可證明之性質與穩健性（設計；結果待 D-50PH 執行）

> **狀態**：本章為設計；動態門檻偵測端（T、TL）、PSRO 之內外層資料分離與攻擊者環境已實作（5.8），**尚未於 D-50PH 上執行**，結果一律標【待定】。規格：E30（`docs/thesis/E30_coevolution_spec.md` v1.1，持續攻防演化之判準先於任何以該判準所做之計算定案）、E29（`E29_irregular_attack_spec.md`，不規則攻擊）、研究方法 v13（`research_method_v13_draft.md` v2，本章之資料、攻擊集、穩健性、形式化保證與 OAI 之範圍）。前版之 E19 設計屬修正前之量測，本章不列其結果。基準線 F 為第四章之規則版於 D-50PH 重跑後凍結之版本（4.0.3）。

### 5.1 動機：固定規則留下之問題

第四章之攻擊皆為**腳本**：每次模擬只有一種固定形狀與速率，且攻擊者不觀察判定。第四章之結果指出適應性攻擊者可得利之處，其數值於 D-50PH 重跑後填入：

| 第四章之結果 | 數值 | 章節 |
|---|---|---|
| 慢速漂移之偵測依賴同時態 peer 參照；以自身歷史為參照者之偵測率與其誤報水準之比較 | 【待定】 | 4.7.4 |
| 知道同秒 peer 中位數之手寫攻擊者（Q4 oracle）全程未觸發 $S_i$ 時之平均偏差 | 【待定】 | 4.7.8 |
| 繞過 peer 共識之比例過半所需之串謀節點數 | 【待定】 | 4.10 |
| 校準期中毒後之漂移偵測率 | 【待定】 | 4.7.8 |

規則本身亦固定：τ_S = 4、τ_H = 2／3、L_C = 2。能觀察自身報告之下場（是否被 steering 選中、是否被判 low-trust 或 rejected）之攻擊者，可學得規則觸發之位置並停留其下，且可隨時間改變攻擊形狀，而非遵循單一腳本。**第四章未測試此類攻擊者**；Q4 之值為手寫策略之對照點，並非證明之上界，且其 oracle 知識（上報前已知同秒 peer 中位數）於實際 O-DU 不可得。

本章回答 RQ4（1.4）之子題：（4a）偵測從何處開始、攻擊者於此前獲得多少；（4b）攻防反覆互動時，攻擊者是否持續找到新的有效攻擊，偵測端能否識別、恢復，並適應未見過之攻擊；（4c）token 隨信任狀態連動洩漏什麼；（4d）結果是否依賴單一設定；（4e）學習策略下仍可保證什麼；（4f）與既有偵測方法之同口徑比較。

### 5.2 規則版作為學習之基礎

DRL 方法本身不是本章之貢獻（1.5 C4）；可宣稱者在規則版提供之約束與參照。規則版之各元件於訓練中之角色如下：

| 規則版元件 | 在訓練中之角色 | 可宣稱之貢獻 |
|---|---|---|
| C_i、H_i-D2（L1 硬否決） | 不交給學習；任何動作下照常作用 | 攻擊者單點無法控制之參照 |
| S_i 參照（同窗 peer 中位數、凍結尺度 s） | 不交給學習；策略只看殘差 z | 學習端能從什麼學、不能學什麼（防校準中毒，4.7.8 Q6） |
| τ_S、τ_H 凍結值 | F 之門檻；T／TL 門檻格點之起點 | 規則版作為比較基準 |
| 嚴重度序融合 | TL 之 action mask 下限 | 規則下限之學習決策 |
| 證據可得性閘 | 證據不足者任何動作下皆不准入（5.3） | fail-closed |
| 腳本攻擊 $A_0$ | 攻擊者池之初始成員（5.2a） | — |
| 乾淨資料上之規則判定 | 偵測端獎勵之標籤；乾淨誤拒上限 ≤ F | 同口徑報 TPR 與乾淨誤拒 |
| RQ3 steering 回放 | 雙方獎勵中之後果 | 以 steering 後果評估信任註記 |

**參與者**：（一）**學習型攻擊者**：一個被攻陷之 O-DU（gNB k），身分合法、上報值皆在合法範圍內；（二）**學習型偵測端**：P2 Trust Assessment xApp 內之學習決策（5.3）。其餘 6 個 gNB 為誠實 peer，LTE 錨點為信任根。

**一個時間步**（1 秒）：攻擊者選擇乘數 $a_t$，上報「實際下行延遲 × $a_t$」（當窗無有效樣本之 UE 不可竄改）→ P1 計算證據並檢查 token（5.5）→ P2 依偵測端策略所選之門檻重算規則判定（T、TL；TL 再於此下限內選標籤）→ P3 依准入政策產生 policy-admitted KPM → 代理 steering 決策依准入之資料選擇 cell，其代價以原始 trace 中候選 cell 之真實延遲計算。此為離線 trace 回放：動作不改變下一秒之 UE 歸屬、負載或延遲，不含實際換手或閉迴路回饋。攻擊者觀察其結果（5.4），兩者各自依其獎勵更新策略。

**兩方各自之取捨**：

- **攻擊者：影響力對隱匿性**。謊報越多，越能誘導 steering，但越易觸發 $S_i$；獎勵直接表達此取捨（5.4）。
- **偵測端：偵測對誤拒（可用性）**。判定越嚴抓得越多，但誠實報告被拒，可用資源下降（4.12 之 $\rho_{\text{PRB}}$）；固定規則等於事先選定此曲線上之一點，且該點公開、不移動。
- **互相依賴**：攻擊者之最佳隱匿程度取決於偵測端於何處觸發；偵測端之最佳嚴格度取決於攻擊者如何進攻。此相依使問題成為賽局，而非兩個獨立之最佳化問題。

**訓練流程（PSRO）**：兩個學習者若只輪流訓練一次，可能互相追逐——偵測端學會新攻擊、卻忘記舊攻擊。故訓練採 PSRO（policy-space response oracles；Lanctot et al., 2017）；以 DRL 作最佳回應之 double oracle 於安全賽局之先例見 Eghtesad et al.（2020）；於假資料偵測，Eghtesad 等人（2026）已以 PSRO 求攻防之混合均衡，且防禦者 reward 含誤報成本。本章沿用此作法，不以 PSRO 或攻防 RL 本身為貢獻；與其差異在於：偵測端之輸入含攻擊者控制不到之場域參照、學習決策受規則下限約束，且賽局為一般和，並以 3 個訓練 seed 報告訓練變異。雙方各維持一個策略池：偵測端池之 $D_0$ 為 F，攻擊者池之初始成員為 $A_0$（5.2a）。每一輪：（一）池中每對策略對戰，以各 fold 之**訓練 seed** 填出雙方之報酬表（測試 seed 之報酬另存、只供評估）；（二）以 meta-solver（Lemke–Howson，初始 label 固定以確保決定性）求此一般和雙矩陣賽局之 Nash 混合；（三）偵測端以 MaskablePPO、攻擊者以 PPO，各對另一方之混合訓練一個新的最佳回應（每個至多 300,000 步、每 50,000 步存檔，以訓練 seed 驗證保留最佳；偵測端只在訓練 seed 上乾淨誤拒 ≤ F 之存檔中選）；（四）加入各自之池。當 NashConv 降至第 1 輪之 5 % 以下，或達最大輪數 12 時停止。PSRO 之作用為擴展策略池、產生新的攻防情境，而非求收斂。Round 0（$D_0$ 對 $A_0$）須重現第四章之數字（一致性檢查 G4、C-2）。

**資料分離**：內層（選擇）——meta-solver、混合策略、NashConv 與下一輪之訓練對手只讀訓練 seed 之報酬表；外層（評估）——測試 seed 之報酬表只供 J1–J6 與最終評估，程式中無任何選擇步驟讀取它（`psro.py --payoff-split train`）。

**主張之範圍**：NashConv 為近似最佳回應之改進量，作探索診斷與停止規則。近似訓練未找到改進，不代表精確最佳回應沒有改進，故 NashConv 不認證完整策略空間之均衡，亦不是可利用性（exploitability）之上界。此設定亦可視為防守方承諾策略、攻擊方最佳回應之安全賽局之推廣（Tambe, 2011）。賽局為一般和：偵測端之誤拒代價由系統可用性承擔，非攻擊者之得分。PSRO 於 O-full 與 O-outcome 兩種觀測層級各跑一次；token 洩漏於最終輪以 O-outcome+token 量測（5.5）。

#### 5.2a 訓練與測試之攻擊集

**訓練池與測試集分開**（E30 §0）：

| 用途 | 攻擊 | 出處 |
|---|---|---|
| **訓練池之初始 $A_0$** | ×0.6 階躍、×0.8 階躍、1 %/秒漂移（**只有調低**） | 第四章之腳本攻擊 |
| 訓練池之新增 | PSRO 各輪之攻擊者最佳回應 $A_1 \ldots A_k$（學習型，$a_t \in [0.5, 1.5]$） | 5.4 |
| **只用於測試（J5）** | E29：不規則調低／調高（單節點、多節點）、×1.2／×1.5 階躍、調高之漂移；文獻設定（固定 AF 1.2–1.5、隨機起點；4.0.4） | `E29_irregular_attack_spec.md` |

**J5 之結果依「與訓練池之差異」分類報告，不合併稱為「未見攻擊」**：

| 類別 | 屬於 | 意義 |
|---|---|---|
| 同類型、只換亂數種子 | E29 之亂數重複 $r = 0 \ldots 9$ | 只是重複抽樣，**不是**未見攻擊 |
| 已見方向、未見時序 | 不規則調低（單、多節點） | 方向與幅度範圍與 $A_0$ 之調低階躍重疊，差在開關時序與節點數 |
| 未見方向 | 不規則調高、×1.2／×1.5 階躍、調高之漂移、文獻設定 | $A_0$ 只有調低；學習型攻擊者雖可選 $a_t > 1$，但不保證池中出現 |

學習型攻擊者 $A_k$ 之實際行為方向以 E30 §4 之行為特徵（平均偏移等）事後確認；若池中出現調高之攻擊者，第三類改標為「池中有同方向之學習型攻擊者」。

**E29 不規則攻擊之產生方式**（`attack_generators.py`；只產生每秒倍數排程，不讀資料、不做判定）：起點 $t_0 \sim U\{30..150\}$ 秒；之後 ON／OFF 交替，ON = 3 + Geom（平均 10 秒）、OFF = 3 + Geom（平均 20 秒），即攻擊段之起點為位移後之 Poisson 過程；每段獨立抽倍數（調低 $U[0.6, 0.9]$、調高 $U[1.2, 1.5]$），段內固定；調低與調高分開，不混合。多節點模式下，第一個節點於 $t_0$ 被攻陷，其後以平均 60 秒（敏感度 30／120 秒）之幾何間隔陸續攻陷其他節點，至多 4 個、不放回、被攻陷後不復原，各自有獨立之 ON／OFF 與倍數。排程由（資料 seed、起始 cell、亂數重複 r、方向、模式）經雜湊決定，同參數重跑逐位相同。E29 之攻擊者不知道 τ_S、不看判定（一般攻擊者）。

### 5.3 學習型偵測端：位於 P2、於事先登錄之區間內調整門檻

**位置**：學習決策位於 P2 Trust Assessment xApp 內，取代第四章 L2 之固定決策（$S_i$ 與 $H_i$-D1 之情況）；$C_i$ 與 $H_i$-D2 維持 L1 規則式硬否決。$S_i$ 之參照（同窗 peer 中位數、凍結尺度 $s$）亦不由學習改變。

**三種偵測端（E30 §2）**：

| 代號 | 門檻 | 判定 | 動作空間 |
|---|---|---|---|
| F（固定） | 凍結值（τ_S = 4、τ_H^warn／τ_H^reject = 2／3） | 規則（＝第四章之規則版） | — |
| T（動態門檻） | 每秒由策略將 (τ_S, τ_H^reject) 各移 −1／0／+1 格，τ_H^warn = τ_H^reject − 1 | 依所選門檻重算規則判定，不另選標籤 | 9 |
| TL（動態門檻＋學習判定） | 同 T | 於「以所選門檻重算之規則判定」之下限內選標籤（action mask，Huang & Ontañón, 2022） | 27（9 × 3 種標籤） |

**門檻區間**（事先登錄）：τ_S ∈ [2, 6]（9 格）、τ_H^reject ∈ [2, 4]（5 格），0.5 一格，每秒至多變化一格；可到達之門檻狀態共 45 個。另報每節點每 100 秒之門檻變更次數與門檻之時間分佈。L1 硬否決（`R1_AUTHZ`、`R1_CI_VETO`、`R1_D2_VETO`）、L3（abstain）與 P3 之證據可得性閘不交給學習決策，於任何門檻下照常作用。

**誤拒上限**：偵測端最佳回應之存檔只在訓練 seed 上「乾淨誤拒率 ≤ F」者中選；無合格存檔則該輪之最佳回應為 F。測試 seed 上若超過，照實報告。T、TL 於 E9c 共模下之誤拒亦須 ≤ F。此上限為**訓練 seed 上之選擇條件，不是保證**（5.9）。

**證據不足之處理**（`zt_kpm_xapp.py` 之 `EVIDENCE_GATE`）：

| 情況 | 判定標籤 | 准入 |
|---|---|---|
| S_i 證據不可得，且無更高嚴重度之規則成立 | **abstain**（`R3_ABSTAIN`） | 任何准入政策下皆不准入 |
| S_i 證據不可得，但 L1 否決成立 | rejected（L1 優先） | 不准入 |
| S_i 證據不可得，D1 weak／strong | 依嚴重度序之判定（可為 low-trust） | **仍不准入**（閘依「證據不可得」判斷，不看最終標籤） |
| TL 之學習標籤 | 只能 ≥ 規則判定（trusted ≺ abstain ≺ low-trust ≺ rejected）；可將 abstain 升為 low-trust／rejected，**不可降為 trusted** | 依最終標籤，且受閘限制 |

證據不足時**判 abstain，不判 rejected**：rejected 表示有反證，abstain 表示無足夠證據；二者於 C_strict 下皆不准入，但語意不同（4.4.0）。

**狀態**：$z_j(t)$（$S_i$ 殘差）、peer 數、歸屬節點 j 之 D1 $z_d$ 最大值與證據強度、$C_i$ pending 旗標；上述各值之過去 $k = 5$ 秒，以及本決策過去之動作與當前門檻。**不含** peer 中位數與尺度 $s$ 本身——參照不由學習決定。

**獎勵**（主設定）：

| 真值 | 判 rejected | 判 low-trust | 判 trusted |
|---|---:|---:|---:|
| 竄改 | +1 | +λ（λ = 0.3） | −α ×（該秒 steering 錯誤成本，以 RQ3 regret 正規化）；α = 1 |
| 未竄改 | −β（β = 5） | −μ（μ = 0.05） | +μ |

β 為乾淨誤拒之代價，使「全部拒絕」不能得分；λ 為「只標記、不排除」之價值；α、μ 固定，不做敏感度。abstain 於 C_strict 下與 low-trust 同為不准入，獎勵同 low-trust；另對已訓練之模型以 abstain 獎勵 = 0 重算，只回答「排序是否隨計分改變」，不回答學習結果是否改變（E30 §2a）。β、λ 之敏感度見 5.10。標籤為「該 (節點, 秒) 之報告是否被竄改」；被攻陷節點於注入起點前標為未竄改。

**演算法**：MaskablePPO（sb3-contrib；PPO：Schulman et al., 2017；Stable-Baselines3：Raffin et al., 2021），訓練 seed 0、1、2，報 3 組中幾組成立。部署分凍結（frozen）與線上（online）兩種。

**目的與界定**：規則只看一個窗（$C_i$ 看 $L_C$ = 2 個窗）；學習型偵測端看 5 秒歷史，可對殘差逐窗爬升之節點提前收緊門檻，亦可於無攻擊跡象時放寬門檻以降低乾淨排除。允許雙向調整後，**學習決策可能比規則版更寬鬆**；可保證者為「不寬於區間最寬端之規則判定」（5.9 之 S3），乾淨誤拒 ≤ F 只是選擇條件。此設計與安全強化學習之 shielding 同一精神：由外部規則與區間限制學習者可採取之動作（Alshiekh et al., 2018）。凍結之策略仍為固定函數，可被試探；線上學習則重新打開校準中毒之風險（Q6）。

### 5.4 學習型攻擊者：模仿之攻擊

**攻擊**：traffic-steering 誘導，與 4.12（RQ3）同一威脅。被攻陷之 gNB k 上報較實際為低之下行延遲，使 RC xApp 將 UE 導向實際較差之 cell；數值在合法範圍、身分合法，僅數值為假。腳本版之誘導率見 4.12.4【待定】。

**動作**：每秒輸出 $u_t \in [-1, 1]$，乘數 $a_t = \text{clip}(a_{t-1} + \delta u_t, 0.5, 1.5)$，$\delta = 0.05$；即倍數每秒至多變 0.05，形狀由其自行學得（例如緩慢爬升、停於門檻下、被判 low-trust 後退回）。控制對象之第一步為 cell 上報之 delay；UE ID 集合（對 $C_i$）為第二步，另訂規格。多節點串謀由 4.10 之 m-sweep 與 E29 多節點（只測試）涵蓋，學習型攻擊者為單節點。

**觀測層級**（兩者皆做）：

| 層級 | 攻擊者可見（過去 $k$ 秒） |
|---|---|
| O-outcome | 自身上報相對於攻擊前基準之比值、自身所用之倍數、上一已評估秒之 peer 中位數（lag1）、是否被 steering 選中 |
| O-full（最壞情況） | O-outcome ＋ 偵測端對自身之過去判定 |
| O-outcome+token | O-outcome ＋ token 續發／撤銷事件（僅 5.5 之連動版） |
| 禁止 | 同秒 peer 中位數（即 Q4 oracle，僅作對照點） |

**獎勵**：被 steering 選中且非最佳 cell：+1；被判 low-trust：−0.1；被判 rejected：−1。

**演算法**：PPO（連續動作），於 PSRO 中作為攻擊者之最佳回應訓練器；訓練 seed 0、1、2。

**與既有攻擊之關係**：KPI poisoning（Alimohammadi et al., 2024）以固定倍數（×1.2–1.5）縮放 KPI；Rogue Cell（Aizikovich et al., 2025）以查詢對預測模型最佳化擾動；本章之攻擊者則依其觀測逐秒調整。

### 5.5 授權層：OAuth 2.0 與 `R1_AUTHZ`

**機制**：於 DU 與 CU／RIC 之間加入 OAuth 2.0（RFC 6749, Hardt, 2012）client credentials 之**邏輯層模擬**（不實作 HTTP；模組 `xapps/verification/authz/`）。token 之 scope 含 DU 身分、可上報之 cell ID、量測類型與請求種類。新規則 `R1_AUTHZ`：token 無效、過期或 scope 不符 → rejected，列於規則表之首（4.4.0（二））。SRCS v16 SEC-CTL-NEAR-RT-2 NOTE 指出 E2 之認證即授予授權、SCTP 無原生授權機制，此為逐請求授權之動機；本研究**不宣稱** O-RAN 規範要求於 E2 使用 OAuth。

**分工**：OAuth 限制 DU **能要求什麼**；一致性檢查質疑它**說了什麼**。

| 情況 | 由誰擋下 |
|---|---|
| 未登記或已撤銷之 DU | token 檢查 |
| 合法 DU 為非其所屬之 cell 上報或請求 | scope（`R1_AUTHZ`）；與 E2 Setup 之 cell 清單部分重疊 |
| 合法 DU 竄改自身 cell 之數值（主要威脅） | **OAuth 擋不住**（持有合法 token）；由 $C_i$、$S_i$、$H_i$ |
| 合法 DU 試探門檻 | 學習決策（5.3） |

**token 與信任連動**：連續 rejected ≥ N = 3 窗才撤銷或縮小 scope；撤銷生效加隨機延遲 U[0, D] 窗，D = 5；撤銷後重新申請之冷卻 T = 30 窗。因 token 被拒本身會透露判定，**必報資訊洩漏量測**：（i）攻擊者於 O-outcome+token 下推斷「自身是否被判 rejected」之準確度；（ii）連動版與不連動版（對照）之攻擊者可維持偏差差值；（iii）token 事件與判定之互資訊估計【待定】。

**目前實作**：授權伺服器之邏輯（發放、檢查、撤銷、連動參數、事件紀錄）已實作並通過單元測試（`test_oauth_sim.py`）；尚未接入回放管線與賽局環境。`R1_AUTHZ` 與 `R1_STAGE1` 皆尚未於 `fuse()` 實作（4.4.0（二））。負載：每個 DU 約每秒一次 token 檢查；接入後統計實際請求量。
