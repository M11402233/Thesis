## 4.8 H_i：跨小區成員轉移一致性驗證

> **定位**：H_i 負責**成員轉移可信度**之驗證，設計上用以補 C_i 之涵蓋邊界（4.6.6 守恆式串謀、4.6.5 單點虛減）。D1 以 Hampel identifier 之 robust z 量化證據強度，D2 為情境特定之規則斷言；二者之輸出經 4.4.0 之規則映射為信任狀態。定義見 3.3.3。

### 4.8.1 兩個維度與乾淨基線

| 維度 | 乾淨基線 | 判定型態 |
|---|---|---|
| **D1 成員消失** | UE 之連續 mmWave 缺席窗數（已連線但當窗無任何 mmWave 接收）之分布：停留事件數、分位數、最長值、是否集中於少數 UE【待定】 | 非參數（Hampel robust z） |
| **D2 成員瞬移**（情境特定之斷言） | serving mmWave cell 之改變次數、其中有對應成功換手事件者之比例、無對應者（即乾淨資料上之 D2 誤觸）【待定】 | 架構斷言 |

**PHY 層交叉驗證（mmWave 缺席與鏈路之關係）**：以換手事件與 attach 紀錄建立 (cell, RNTI) → IMSI 之逐時對應，逐秒比對 mmWave PHY 下行紀錄（`RxPacketTrace`）與 D1 之缺席狀態，報告缺席之 UE-秒與非缺席之 UE-秒之 SINR、TB 損壞比例與 mmWave PHY 位元組量【待定】。此為**支持性之相關，不是機制證明**；劣化之成因（遮蔽、距離、干擾）不逐一歸因。

### 4.8.2 D1：為何非參數

以卡方適合度檢定比對停留時間與幾何分布（參數以最大概似估計，$\hat p$ = 1／平均停留；分箱 {1, 2, 3, 4, 5, ≥ 6}，自由度 4）【待定】。同一 UE 之多個停留事件相依，有效樣本數小於事件數，χ² 之 p 值僅供參考。不論檢定結果，D1 採不依賴分布假設之非參數方法，使判定不因分布假設錯誤而失效；本檢定不涵蓋其他參數族。

### 4.8.3 D1：Hampel identifier

**（a）Hampel identifier**（Hampel, 1974；Leys et al., 2013）：

    z_d(x,t) = ( d(x,t) − median_x ) / ( 1.4826 · MAD_x )

$d(x,t)$ 為當前連續 mmWave 缺席窗數。**缺值語意**：UE 於某窗不在任何節點之 RRC 連線名單時，無法確認其仍為缺席，故中斷本段計數，再次觀測到缺席時自新段起算；中斷不代表正常或 trusted。基線估計採相同定義，被截斷之停留片段不列為完整停留事件（4.4.0（四）之 E11 揭露）。$z_d$ 即 robust z（與 S_i 同一統計量，門檻各自校準）。MAD = 0 時尺度取 1 窗之下限。

**基線**：採 **per-UE-index 基線**——跨 run 以 IMSI 編號彙整停留事件（同號 UE 於不同 run 之位置不同，故非部署意義下之個別裝置基線）；事件數 < 8 時退回 resident／edge 群層級經驗分布。基線由乾淨資料之訓練 seed 一次估計、**永不線上更新**——否則攻擊者可緩慢養高某 UE 之停留以撐大門檻，此即 4.7.3 所述滑動更新參照之同一弱點。此需 clean bootstrap（信任根）假設。

**（b）經驗 p 值**：

    p_emp(x,t) = ( 1 + |{ d' ∈ 乾淨停留(x) : d' ≥ d }| ) / ( n + 1 )

採 (1+·)/(n+1) 避免有限樣本得 0。$p_{\text{emp}}$ 作為事後解釋性統計，**不參與 4.8.5 之證據分級**；z 與 p 之聯合決策為實作已支援之設定，列為後續敏感度分析。

### 4.8.4 D2：以換手事件為準之瞬移斷言

```
moved(x,t)    := (x 於 t−1 之 mmWave serving cell 為 A) ∧ (x 於 t 之 mmWave serving cell 為 B ≠ A)
teleport(x,t) := moved(x,t) ∧ ¬∃ 成功換手事件 (x, A → B)，其完成時間落於 (t−1, t]
D2 violated ⟺ ∃x: teleport(x,t)
```

此判準類似身分安全領域之 impossible travel detection：同一身分於時間上不可能之位置轉移。**時間對齊**：換手事件與 1 秒報表之時點可能不同步；容許之對齊窗（例如 ± 1 窗）於看 D-50PH 之結果前寫定【待定】，並報其敏感度。**宣稱之範圍**：D2 為由本場景之換手機制導出之**情境特定斷言**，其前提於其他移動模型、觀測粒度或換手機制下未必成立；本研究不宣稱其為一般性之架構不變量。

**乾淨基線**：D-50PH 開啟合法換手，故 D2 首次有非 vacuous 之乾淨基線——合法換手是否全部有對應事件、乾淨資料上之誤觸數與其成因（事件遺失、時間未對齊、名單時點）【待定】。若乾淨資料上誤觸不為 0，D2 不得維持 L1 硬否決之地位而不加說明，處理方式須先報告再決定，不得自行調整。

**注入瞬移**：將 UE 之 serving cell 改為另一 mmWave cell 而不產生換手事件（目標 cell 以確定性公式指定）；其偵測屬**設計必然（by construction）**。該注入須同時改動來源與目的兩個 mmWave 節點之上報，故其檢驗的是規則是否如定義運作，**不是對單一受攻陷節點攻擊之偵測率**。另須討論：若受攻陷節點可同時偽造換手事件（例如自稱為 target 並回報成功換手），D2 之強度即受限；換手事件之來源與可信度見 4.8.7。

### 4.8.5 D1 與 D2 於融合規則中之角色

> 信任狀態之定義與判定條件見 4.4.0，此處不重複定義。

#### （一）證據強度與規則代碼之對應

$H_i$-D1 之輸出為**證據強度**，而非信任狀態：

| $H_i$ 輸出 | 條件 | 於 4.4.0 中觸發之規則 | 單獨成立時之狀態 |
|---|---|---|---|
| D2 violated | 存在無對應換手事件之 serving cell 改變 | `R1_D2_VETO`（L1） | rejected |
| D1 = strong | $z_d \geq \tau_H^{\text{reject}}$ | `R2_D1_STRONG`（L2） | low-trust |
| D1 = strong，且 $S_i$ 同窗違反並指向同一節點 | — | `R2_SI_D1_BOUND`（L2） | rejected |
| D1 = strong，且 $S_i$ 同窗違反但指向不同對象 | — | `R2_SI_D1_UNBOUND`（L2） | low-trust |
| D1 = warning | $\tau_H^{\text{warn}} \leq z_d < \tau_H^{\text{reject}}$ | `R2_D1_WEAK`（L2） | low-trust |
| D1 = none | $z_d < \tau_H^{\text{warn}}$ | 不觸發 | 由其他殘差決定 |

**D1 本身不產出信任狀態**。最右欄為該證據於其他殘差均無異常時經 4.4.0 所得之結果；同窗若另有 $C_i$ 違反或 D2 瞬移，則 L1 優先。D1 單獨成立時僅影響其所歸屬之節點（UE 綁定，4.9.6.5）；無節點可歸屬之 D1 證據留存為 UE 層級紀錄，不改變任何節點之信任狀態。

#### （二）D2 為硬否決、D1 不為硬否決之理由

**D2 為情境特定之斷言**：於本場景之換手機制下，合法之 serving cell 改變必伴隨成功換手事件，「改變而無事件」構成結構上不應出現之觀測，其判定不依賴可調門檻，故與 $C_i$ 同置於 L1（前提為乾淨資料上之誤觸可解釋，4.8.4）。

**D1 為統計推論**：判定結果依賴 $\tau_H$ 與基線品質。更關鍵者為裝置並非同質——結構性訊號較差之 UE 長時間缺席 mmWave 可能屬其正常行為。**若允許 D1 單獨硬否決，此類正常行為將直接導致誤拒。** 4.8.6 之 edge UE 誤報率即為此設計之檢驗【待定】。

#### （三）交叉佐證之綁定要求及其限制

`R2_SI_D1_BOUND` 要求兩項證據指向同一節點。然 D1 量測**連續 mmWave 缺席窗數**，觸發 D1 之 UE 於該窗不在任何 mmWave cell 上有接收。**若以「當窗掛載之 cell」為歸屬依據（window 對照政策），該規則不存在合法觸發路徑**（4.9.6.2）。定案之 uebound 政策以「UE 缺席前之 serving mmWave cell」為歸屬依據，同時適用於 D1 單獨成立與交叉佐證兩種情形；此修正使交叉佐證可觸發，其於乾淨資料上之誤拒【待定】（4.9.6.5）。

### 4.8.7 有效性威脅

- **D2 之時間粒度**：1 秒報表與換手事件之時間對齊會影響誤觸；對齊窗之敏感度須報告（4.8.4）。
- **換手事件之可信度**：D2 以換手事件為準；若事件由受攻陷之 source 或 target 節點產生，攻擊者可能同時偽造移動與事件。本研究之 ns-3 輸出中事件由模擬器記錄，不受注入影響；真實部署中事件之來源（CU-CP 或多方紀錄）決定此規則之強度，未評估。
- **per-UE-index 基線**：LOSO 下無法對齊 held-out seed 之 UE 個體身分，屬 LOSO 架構之固有限制；部署上宜於冷啟動時採群組基線、累積乾淨歷史後切換為裝置層級基線。
- **clean bootstrap 假設**。
- **edge UE 敏感度**：須交叉佐證；分群門檻之穩健性見 E15。
- **證據綁定粒度**：D1 證據以 UE 為單位，註記以 (節點, 窗) 為單位。本研究定案採 UE 綁定（4.9.6.5）；告警歸屬節點當窗無有效節點註記之比例、與交叉佐證之乾淨誤拒【待定】。
- **樣本規模與外部有效性**：8 個 seed；外部有效性限於封閉 NPN、固定拓樸、MC 架構。
- **規模效應**：D1 之逐 UE 誤報率不隨 UE 數下降，故每節點之 UE 越多，節點於任一窗綁有 D1 證據之機率越高，見 4.9.6.6。
