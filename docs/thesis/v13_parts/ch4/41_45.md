## 4.1 攻擊架構與注入點定位

本研究之威脅為一個**身分合法、但資料造假**的內部 O-DU 節點。攻擊者不破壞 E2 介面之 IPsec、不偽造 E2AP 格式、不碰無線層——竄改發生於**量測收集完成後、E2SM-KPM indication 編碼前**的資料組裝環節，使上報之數值或 IMSI 偏離物理真實。此威脅已由 O-RAN WG11 點名為 Key Issue #14「Malicious E2 Node」：惡意行為者可濫用已正確完成認證之被攻陷 E2 節點，送出變造與誤導性資料（xApp-TR §5.15）。E2 路徑上之傳輸與身分保護（IPsec ESP 與 IKEv2 憑證認證；E2GAP §7.3）對此無效，現行之單值範圍檢查（SRCS SEC-CTL-NEAR-RT-17）亦無法偵測落在合法範圍內之偽造值，此即需要跨來源一致性驗證之根本原因（呼應第一章）。

**注入點排除說明**：
- **O-RU／PHY 無線層**：研究範圍外。本研究驗證 E2 量測資料之可信度，而非真實無線訊號。
- **UPF／核網（N3/N6）**：研究範圍外。UPF 非 E2 節點、不參與 E2SM-KPM 通訊。
- **O-DU（E2 節點）KPM 組裝點**：**本研究攻擊面**。ns-O-RAN 單體 gNB 架構下 CU/DU 未實際物理切分，攻擊點準確描述為「E2 節點內、量測聚合完成至 E2SM-KPM indication 編碼之間」之資料層。

> 威脅模型之**概念注入點**位於 O-DU KPM 組裝點；**本章實驗以離線後處理修改該點可控欄位、等價模擬其輸出效果，尚未完成 runtime E2SM-KPM indication hook**（見 4.0.6）。本章所有攻擊實驗均屬此離線注入層級。

**完整攻擊流程**：

```
攻擊者取得邊緣節點控制權
  → 通過 IKEv2／IPsec 節點認證，並完成 E2 Setup（宣告 RAN function；E2AP 格式完好）
  → 選擇竄改注入點：O-DU KPM 組裝點（本研究攻擊面）
  → 注入攻擊型態（見 4.5.1）
  → 編碼為合法 E2SM-KPM indication（格式合規、身分合法、數值落於合法範圍）
  → 週期上報 Near-RT RIC
  → ① Detection xApp：計算三類一致性證據（C_i／S_i／H_i）
  → ② Trust Assessment xApp：階層式融合 → trusted / low-trust / rejected / abstain
  → ③ Policy Enforcement xApp：allow / restrict / exclude / defer → policy-admitted KPM
  → 合作之消費端（RC xApp）僅取用 policy-admitted KPM
```

## 4.2 工具鏈、資料集與實驗方法

### 4.2.1 平台與場景

**平台**：ns-O-RAN（ns-3.38，`wineslab/ns-o-ran-ns3-mmwave` commit 8c42089d；mmWave module + `oran-interface` E2 termination），以修正建置 r11 執行（3.3.1、附錄 A）。場景建立 **7 個 gNB + 1 個 LTE eNB** 之 MC 雙連結拓樸，提供跨節點空間驗證所需之多 cell 觀測。ns-O-RAN 具備 E2 termination 能力（RAN Function ID 2，ORAN-E2SM-KPM），惟**本研究之資料收集採其離線檔案記錄模式（`enableE2FileLogging=true`），未經由 Near-RT RIC 之 E2 indication 路徑**；E2 runtime 整合之嘗試與受阻點見 4.0.6。

**場景**：`scratch/scenario-three.cc`，`configuration=1`（3.5 GHz／20 MHz／isd = 1000 m／單天線）。本研究對場景程式僅作一項修改：新增 `--totalUes` 參數，以指定 UE 總數（原程式之 UE 數只能為 `ues` × 7）；參數為 0 時維持原行為。修改後之執行檔於原參數下之全部輸出與修改前逐位相同（校準紀錄）。另開啟 NR 間之合法換手（`--handoverMode=FixedTtt`）。UE 初始位置為以場域中心為圓心之均勻圓盤分布，不逐基地台分配，故 UE 總數不必為 7 之倍數。本場景之 NPN 屬性（固定且已登記之裝置母體、涵蓋全場域之可信錨點）為本研究之情境假設，模擬器本身不含 NPN 特有之機制（第二章「為何限定於非公眾網路」）。

> **註**：ns-O-RAN 將節點命名為「mmWave gNB」，係沿用其 MC 雙連結架構之命名慣例；於 `configuration=1` 下實體載波為 sub-6 GHz。S_i 建立於 delay 之跨節點一致性，與載波頻段無關，此命名不影響方法有效性。

### 4.2.2 觀測粒度

記錄週期與分析窗均為 **1 秒**（`indicationPeriodicity=1.0`），二者對齊，每模擬秒產生一個聚合窗。全章所有「窗」均指此 1 秒聚合窗。

**定案參數**（主資料集 D-50PH；D-S12 只改 UE 數）：

```bash

TOTAL_UES=50      # --totalUes=50，N_known = 50（D-S12：12）
SIMTIME=301       # 分析取 0–299 共 300 窗（見 4.2.3）
PERIOD=1.0        # 1 秒觀測窗
MINSPEED=3
MAXSPEED=10
HEURISTIC=-1      # 不啟用節能 heuristic
E2NR=true         # --e2nrEnabled=true：cell 2–8 輸出 E2SM-KPM DU 報表（含 RRU.PrbUsedDl）
HO=FixedTtt       # --handoverMode=FixedTtt：NR 間合法換手
SEEDS=4200–4207   # RngRun，8 個獨立 seed
```

### 4.2.3 資料集與 E2 NR 報表之技術細節

資料集 D-50PH 與 D-S12 之規模、收集、驗收與參數凍結見 **4.0.3**。以下為分析時須知之技術細節：

- **分析窗**：開啟 E2 NR 報表時，模擬結束之最後一窗不輸出 RLC 統計，故模擬 301 秒、分析取 0–299 窗；分析檔之前處理腳本（50 UE 與 12 UE 版）須內建缺窗、N_total 與 aux 一致性檢查【待定：尚未寫】。
- **E2 NR 報表之副作用**（前版校準時之實測，屬模擬器行為）：RLC 統計與 PHY trace 於開啟前後之共同窗逐位相同；PDCP 統計改為每次報表後歸零。本研究之分析不使用 PDCP 統計。
- **確定性**：同一二進位、同一 seed 重跑之輸出應逐位相同（實際時間戳欄除外）；D-50PH 與 D-S12 之檢查見 4.0.3。

## 4.3 資料前處理

### 4.3.1 資料源與欄位

資料源為依事件發生 cell 分帳之 **RLC 層統計**與有效延遲樣本、RRC 連線名單與換手事件（3.3.1、4.0.2）；不用 PDCP 層（PDCP 錨點在 MC 架構下全聚於 LTE eNB，無 per-gNB 資料，無法支撐跨節點比對）。前處理將累計之計數與延遲和逐窗差分，得每 (窗, cell, UE) 之有效延遲樣本數、區間平均延遲與接收事件數；當窗無有效樣本者記為未知（3.3.1）。

RLC 統計**不含 PRB 使用率與 CQI**。另開啟 ns-O-RAN 之 E2 NR 報表（`--e2nrEnabled=true`），由 cell 2–8 之 DU 報表取得原生 `RRU.PrbUsedDl`（定義與性質見 4.12.1）；`RRU.PrbUsedDl` 之原始定義見 3GPP TS 28.552 V20.4.0 §5.1.1.2.5（Mean DL PRB used for data traffic：量測期間 T 內下行資料傳輸所用 PRB 數之算術平均，為單一整數），E2SM-KPM 本身並未列舉 `RRU.PrbUsedDl`。CQI 仍未取得。

### 4.3.2 吞吐量的差分前處理

`RxBytes`／`TxBytes` 為累積 counter，非每窗區間流量，故 cell 級吞吐量須先做視窗差分：

$ΔRxBytes(u,t) = RxBytes(u,t) − RxBytes(u,t−1)$
$TP_j(t) = (8/Δt) · Σ_{u ∈ cell j} ΔRxBytes(u,t)$

第一窗、缺窗、cell change 或 counter reset 造成之不可比差分標為 missing、不納入計算。延遲和與有效延遲樣本數同為累計值，以相同方式差分（3.3.1）。

### 4.3.3 場域基數必含 LTE 錨點

C_i 之全域聯集**必須包含 LTE 錨點 cell（CellId=1）**：若只計 mmWave，N_total 會因 UE 正常之 mmWave 中斷或換手過渡而浮動（非攻擊訊號）。含 LTE 時 N_total(t) 於 D-50PH 與 D-S12 乾淨資料上是否每窗等於已知母體數【待定】。

## 4.4 驗證哲學與階層式證據融合

### 4.4.0 信任狀態之定義與判定規則

#### （一）信任狀態之語意

本研究之驗證層對每一個 (節點, 觀測窗) 產出一個信任狀態 $D_i(t) \in \{\text{trusted},\ \text{low-trust},\ \text{rejected},\ \text{abstain}\}$。四者之語意、對應之 Policy Enforcement 動作，以及**明確排除之誤解**定義如下：

| 狀態 | 語意 | Policy Enforcement 動作（4.9.3） | 明確不代表 |
|---|---|---|---|
| **trusted** | 本窗未觀察到任何反例，且驗證所需證據充足 | **allow**：納入 policy-admitted KPM | 不代表該量測已被證明為真；僅代表未發現反例（4.4.1） |
| **low-trust** | 存在至少一項需交叉佐證之證據，未達可直接採信之標準 | **restrict**：依准入政策限制其使用——附註記後納入，或自決策輸入排除（本章評估之兩種設定見 4.12.3） | **不代表該量測為偽造**；不應解讀為誤報率 |
| **rejected** | 存在確定性違反，或多項統計證據指向同一對象 | **exclude**：該筆量測不進入 policy-admitted KPM；寫入 execution record | **不代表該節點被判定為攻擊者**；拒絕對象為該筆 KPM，非該節點之身分 |
| **abstain** | 驗證所需證據不可得，無法作成判定 | **defer**：當窗不進入 policy-admitted KPM；fallback 政策另行定義，且不使該筆量測回到 admitted view（4.9.3） | **不代表可信**；證據不足永遠不等於證據支持 |

**嚴重度序**：$\text{trusted} \prec \text{abstain} \prec \text{low-trust} \prec \text{rejected}$。此序用於同窗多項證據並存時之彙總，以及跨節點之窗層級呈現。

**不繼承原則**：信任狀態並非節點之屬性，而是每個觀測窗針對每個 (節點, 窗) 重新產生之驗證狀態。前一窗之 trusted 不對後一窗構成任何預設；前一窗之 rejected 亦不使該節點於後續窗永久失信。過去狀態僅在明文定義之多窗持續性規則中作為證據（見下表 `R1_CI_VETO` 之持續窗條件）。由此導出之狀態轉移與恢復條件見（四）。

#### （二）階層式融合規則

三項殘差之性質互異——$C_i$ 為近確定性斷言、$H_i$-D2 為情境特定之規則斷言（二者皆不依賴可調門檻），$S_i$ 與 $H_i$-D1 為統計殘差。若以加權分數融合，確定性之違反將被正常之統計讀數稀釋（論證見 4.4.3）。故採**階層式規則融合**，依 NIST SP 800-207 §3.3.1 之分類屬 criteria-based 信任演算法。

**判定輸入**：本窗之證據組 $E_i(t) = \langle\, C_i,\ r_C,\ S_i,\ \text{D2},\ \text{D1},\ \text{ev}_{\text{D1}},\ j \,\rangle$，其中 $r_C$ 為 $C_i$ 連續違反窗數，$\text{ev}_{\text{D1}}$ 為 D1 證據之歸屬節點——於定案之 uebound 政策下為觸發該證據之 UE **消失前之 serving mmWave cell**；於 window 對照政策下為該 UE 當窗掛載之 cell 集合（4.9.6.5），$j$ 為受測節點。

**判定對象之範圍**：信任狀態僅對當窗有上報之 mmWave 節點產生。LTE 錨點（CellId 1）為驗證用之輔助輸入（$C_i$ 之聯集、$H_i$ 之過渡判定），不在本次准入政策之作用範圍內。當窗無任何活躍 mmWave 節點時，該窗之處理狀態記為 `n/a`（reason = `no_active_mmwave_node`），不產生節點信任註記、准入動作或准入量測；`n/a` 為窗之處理狀態，**不是第五種信任狀態**。

**規則表**（評估全部規則，由**嚴重度最高之符合規則**決定；同嚴重度時依層級 L1 ≺ L2 ≺ L3、再依表內順序決定 `rule_id`；其餘符合之規則記入 `also_matched`。此為**事後修正**，第四章原採「第一條符合即決定」，見（三））：

| 層 | 代碼 | 條件 | 狀態 |
|---|---|---|---|
| L1 | `R1_AUTHZ` | token 無效、過期或 scope 不符（OAuth 2.0 邏輯層授權；第五章新增，第四章之實驗未啟用，原型 `fuse()` 尚未實作；5.5） | **rejected** |
| L1 | `R1_CI_VETO` | $C_i$ violated 且 $r_C \geq L_C$ | **rejected** |
| L1 | `R1_CI_PENDING` | $C_i$ violated 且 $r_C < L_C$ | **low-trust** |
| L1 | `R1_D2_VETO` | $H_i$-D2 violated（serving cell 改變而無對應之成功換手事件，3.3.3） | **rejected** |
| L1 | `R1_STAGE1` | 身分前提不成立（節點身分認證由 RIC 平台以 IKEv2／IPsec 完成，E2 Setup 僅宣告 RAN function；本層僅取用其結果；原型 `fuse()` 未實作，身分前提於重放層恆成立） | **rejected** |
| L2 | `R2_SI_D1_BOUND` | $S_i$ violated 且 D1 = strong 且 $j \in \text{ev}_{\text{D1}}.\text{cells}$ | **rejected** |
| L2 | `R2_SI_D1_UNBOUND` | $S_i$ violated 且 D1 = strong 但 $j \notin \text{ev}_{\text{D1}}.\text{cells}$ | **low-trust** |
| L2 | `R2_SI_ALONE` | $S_i$ violated，D1 無 strong 證據 | **low-trust** |
| L2 | `R2_D1_STRONG` | D1 = strong（$z_d \geq \tau_H^{\text{reject}}$）且歸屬於節點 $j$，$S_i$ 未違反 | **low-trust** |
| L2 | `R2_D1_WEAK` | D1 = warning（$\tau_H^{\text{warn}} \leq z_d < \tau_H^{\text{reject}}$）且歸屬於節點 $j$ | **low-trust** |
| L3 | `R3_ABSTAIN` | $S_i$ unavailable（同窗 peer 數 < MIN_PEER）、LTE 錨點 KPM 遺失、或窗無法對齊 | **abstain** |
| L0 | `R0_CLEAN` | 以上皆不成立 | **trusted** |

#### （三）三項設計約束之說明

**約束一：硬違反優先，且不被統計證據稀釋。** L1 之 rejected 規則成立時，判定即為 rejected（嚴重度已為最高），L2 與 L3 不能使其減輕；`R1_CI_PENDING`（low-trust）則不再阻擋同窗之 rejected 證據（見本節末之事後修正）。$C_i$ 違反但持續窗數未達 $L_C$ 者降為 low-trust 而非 trusted——**違反之觀察與拒絕之執行為不同層級**，前者為 property 判定，後者為 enforcement 決策（4.6.1）。

**約束二：單一統計證據不構成硬否決；交叉佐證須指向同一對象。** $S_i$ 或 $H_i$-D1 單獨違反僅得 low-trust。二者同窗並存時，**須進一步檢查兩項證據是否指向同一節點**方可升級為 rejected（`R2_SI_D1_BOUND`）；若指向不同對象（`R2_SI_D1_UNBOUND`），則視為兩個無關告警同時出現，不構成互相印證。

此綁定要求源自實作稽核（4.9.6）。$H_i$-D1 依定義量測 UE 之連續 mmWave 缺席窗數，觸發 D1 之 UE 於該窗不在任何 mmWave cell 上有接收。**若以「當窗掛載之 cell」為歸屬依據（window 對照政策），D1 證據與 $S_i$ 受測之 mmWave 節點在結構上不相交，`R2_SI_D1_BOUND` 不存在合法觸發路徑。** 定案之 uebound 政策改以「該 UE 消失前之 serving mmWave cell」為歸屬依據，使此規則具有合法觸發路徑；其於乾淨資料上之觸發皆為誤拒事件，筆數於 D-50PH 與 D-S12 上量測【待定】（4.9.6.5）。

**約束三：證據不可得永不等同於證據支持（fail-closed）。** L3 成立時，該筆量測判為 abstain，且於任何准入政策下皆不准入（P3 之證據可得性閘，4.9.3；v12.3），避免攻擊者藉由壓制鄰居節點上報、或利用離峰空窗使 $S_i$ 無法取得比對對象而「預設通過」。

嚴重度序之一項後果：low-trust 之嚴重度高於 abstain，故當同窗另有 $H_i$-D1 證據時判為 low-trust，該窗雖屬 $S_i$ 證據不可得，卻不呈現為 abstain。**因此 abstain 之決策比例並非證據不可得率**，二者須分別陳述（實測見 4.9.6.4）。其理由為：abstain 較 low-trust 為輕，當已有其他證據足以降級時採較嚴之標籤。惟標籤較嚴不等於准入較嚴：`restrict_annotated` 准入 low-trust，故若只依標籤准入，「S_i 不可得＋D1 weak／strong」之量測會被附註記准入（外部審稿以函式反例指出）。故 v12.3 於 P3 加入**證據可得性閘**：只要該筆之 S_i 證據不可得（`R3_ABSTAIN` 為最終或同時符合之規則），任何准入政策皆不准入；判定標籤不變（4.9.3）。

**融合順序之事後修正**：第四章原採「依序評估，第一條符合者即決定」。`R1_CI_PENDING`（low-trust）排在 `R1_D2_VETO` 與 `R2_SI_D1_BOUND`（皆為 rejected）之前，故當同窗 $C_i$ 首次違反（$r_C < L_C$），而 $H_i$-D2 亦違反、或同節點之交叉佐證成立時，本應產出之 rejected 被遮蔽為 low-trust——攻擊者可藉 $C_i$ 之首次違反減輕原本會被拒絕之報告。本研究依事先寫定之規格（`docs/thesis/fusion_severity_order_spec.md`）改為上表之嚴重度序，並以四項檢查（原順序重跑逐位相同、乾淨註記不變、窮舉單元測試之差異皆為預期且皆更嚴、注入實驗只有預期者改變）決定採用。此為**事後修正**，係於前版資料上發現並檢查；程式預設仍為原順序以重現回歸基準，主結果以 `ZT_FUSION_ORDER=severity` 產生。兩種順序於 D-50PH 上之差異照報【待定】；嚴重度序之運算開銷於 4.9.5 量測【待定】。

#### （四）狀態轉移與恢復條件

因採不繼承原則，狀態之進入與離開均由當窗證據決定。由（二）之規則表可直接導出各狀態之離開條件：

| 進入之規則 | 進入條件 | 離開條件（次窗重新判定） |
|---|---|---|
| `R1_CI_PENDING` → `R1_CI_VETO` | $N_{\text{total}} \neq N_{\text{known}}$；連續達 $L_C$ 窗時升級為 rejected | 首個 $N_{\text{total}} = N_{\text{known}}$ 之窗，$r_C$ 歸零 |
| `R1_D2_VETO` | 當窗出現無對應換手事件之 serving cell 改變 | 瞬移為單窗事件；次窗若無新事件即離開 |
| `R2_SI_ALONE` | $z_j > \tau_S$ | 首個 $z_j \leq \tau_S$ 之 full-consensus 窗 |
| `R2_D1_STRONG`／`R2_D1_WEAK` | 歸屬於節點 $j$ 之 UE 其 $z_d \geq \tau_H$ | 該 UE 之連續 mmWave 缺席結束（回到 mmWave 接收，或因不在連線名單而中斷計數；$d$ 歸零） |
| `R3_ABSTAIN` | 證據不可得 | 證據恢復可得 |

此表為規則之邏輯後果，非實測結果。其兩項意涵須明言：

1. **不永久繼承前窗信任狀態**：信任狀態不跨窗沿用，觸發條件消失後，該節點之判定即依當窗證據重新產生，系統不保留「曾被拒絕」之狀態。惟部分證據本身使用歷史資訊——$C_i$ 之連續違反計數 $r_C$、D1 之連續 mmWave 缺席窗數、D2 之前窗 serving cell——故離開時點取決於這些證據何時歸零，未必為觸發條件消失之次窗（實測見下文 E11）。此與「拒絕對象為該筆量測而非節點」一致，但亦意謂間歇性攻擊者於每次停手後即可恢復。
2. **持續性升級僅有一條**：唯一之持續性升級為 $C_i$ 之 $L_C$。$S_i$ 之持續違反恆為 low-trust（`R2_SI_ALONE`）。統計證據升級為 rejected 之唯一路徑為同窗之交叉佐證（`R2_SI_D1_BOUND`），且僅於 uebound 政策下可觸發（約束二）；window 政策下統計證據不存在升級為 rejected 之路徑。其下游後果見 4.12.5（三）。

RQ2 所問之轉移延遲與恢復延遲之實測見下文 E11，重複短違反之效果見 4.6.7 之 E11b；統計證據之持續性升級規則（候選 `R2_SI_PERSIST`）之評估見下文 E12；該候選規則**不列入**（二）之規範性規則表。

**E11：轉移與恢復之實測**（規格 `docs/thesis/E11_E12_B4_spec.md` v2；腳本 `run_E11_transitions.py`；驗證層級：離線注入與規則回放，D-50PH 8 seed）

**設計**：每個 seed × 受測 mmWave cell × 六類攻擊 × 攻擊長度 T ∈ {10, 30} 秒，於 $[t_0, t_0+T)$ 注入（$t_0$ 為受測 cell full-consensus 序列中點之窗），攻擊結束後追蹤 60 秒；每個情境皆與同 seed 之乾淨回放逐窗配對，只計攻擊造成之差異。$C_i$ 灌水／虛減與 $S_i$ 漂移（1 %/秒）／階躍（×1.5）僅改動受測節點自身之報告；D1 超時消失須改動受信任之 LTE 錨點或多個節點之報告，D2 偽造關聯須同時改動兩個 mmWave 節點之報告，二者皆為**規則回放**，不宣稱符合單點 O-DU 攻陷模型。

**可追溯性**：以獨立實作（不呼叫 xApp 之判定與融合函式）由注入後之報告重算 P1 證據，並依（二）之規則表推得決策，須與 xApp 回放逐筆相同；乾淨回放須與 4.9.5 之 runtime 註記逐筆相同。筆數【待定】。

**定義之修訂（揭露）**：本實驗首版之檢查要求攻擊只觸發自身類別之規則；前版資料上檢視不符之情境後發現同一份上報會影響多個殘差，故改為可追溯性檢查；並將 D1 於 UE 缺報時之處理改為中斷計數（4.8.3）。v1 之規格、程式與診斷保存於 `data/results/E11_v1_diagnosis/`。

**報告項**（受測節點；延遲單位為秒，中位數〔範圍〕）：引發轉移之情境數、離開 trusted 之延遲、到達 rejected 之情境數與延遲、自攻擊結束起回到乾淨對照之延遲；受測 (節點, 窗) 之變化分為降級（新增非 trusted 或加重）、判定減輕、同狀態改規則、節點消失四類；全場域斷言（$C_i$、D2）對其他節點之影響另報（跨情境累計之 (節點, 窗) 比對次數，非獨立事件數，亦非乾淨誤報率）。

**結果**：【待定：D-50PH 重跑；D-S12 另列】。須特別報告：「引發轉移」不等於偵測成功（判定減輕之筆數與成因）；統計證據升級為 rejected 之路徑（`R2_SI_D1_BOUND` 之同窗重合，非持續性規則所致，4.9.6.6）；$C_i$ 虛減未升級之情境之成因（3.3.4 之條件）。

**E12：統計證據之持續性升級（候選規則，未採用）**（規格 `docs/thesis/E11_E12_B4_spec.md`；腳本 `run_E12_persist.py`；驗證層級：離線合成注入，D-50PH 8 seed）

**問題**：現行規則中 $S_i$ 之持續違反恆為 low-trust。若新增候選規則「$S_i$ 於同一節點連續違反 $L_S$ 個實際秒即升級為 rejected」（`R2_SI_PERSIST`），誤拒與偵測如何取捨？$L_S = \infty$ 即現行規則。三項內建檢查：$L_S = \infty$ 之註記等於 runtime 註記；連續計數之兩份實作逐筆相同；$L_S = \infty$ 之 RQ3 指標與 4.12 逐位相同【待定】。

**報告項**（$L_S$ ∈ {∞, 2, 3, 5, 10}）：乾淨資料新增誤拒（筆數與比例）；漂移 1 %/秒、階躍 ×1.3、×1.5 之到達 rejected 情境數與中位延遲；`C_notrej` 下 ×0.6 階躍、漂移 1 %、2 % 之誘導率；新增誤拒於 seed 間之分布。

**結果**：【待定】。**本研究不採用此候選規則作為主結果**：其操作點（$L_S$）須另行選定，而 D-50PH 依凍結聲明不用於選擇參數；第五章之學習型偵測端以 5 秒歷史可做類似之提前收緊，E12 為其固定規則版對照（5.7 之 B2）。

#### （五）本節與實作之關係

上表為**規範性定義**。驗證元件於實作中設置規則稽核儀器，逐筆記錄觸發規則代碼、各殘差原始判定與證據綁定對象，使實際判定可與本表直接對帳；稽核結果、前版實作與本表不符之處及修正後之決策分布見 4.9.6。門檻參數之取值與校準方式分別見 4.6.1、4.7.2、4.8.3；本節僅定義規則結構。

**動作層之界定**：信任狀態由 Policy Enforcement xApp 轉為對合作消費端 KPM 輸入之准入動作（allow／restrict／exclude／defer），而非以攔截 E2 資料流實現——驗證元件無權阻斷其他 xApp 之訂閱。各動作之精確語意與動作模式之比較見 4.9.3。

### 4.4.1 從認證到持續驗證

Near-RT RIC 現況隱含「認證即可信」之假設：E2 上認證即授權，SCTP 無原生授權方法（SRCS SEC-CTL-NEAR-RT-2 NOTE；ZTA-TR §7.3.4 NOTE 3），O-RAN 零信任研究亦將經 E2 傳送之資料判定為無缺口（ZTA-TR §7.3.4）。NIST SP 800-207 則明言，不應因主體通過基本認證即假設其後續請求同樣有效；O-RAN WG11 之研究報告亦指出，即使 E2 被視為具備機密性、完整性與雙向認證，RIC 仍不應假設收到之資料有效且可信（xApp-TR §6.17）。

    傳統：  measurement → authenticated? → trust
    本研究：measurement → authenticated? → VERIFY → trust decision

信任不是預設，而是**每個 granularity window 重新產生之驗證狀態**。本研究借用「**未發現反例不等於證明為真**」之共同判斷原則（統計證偽、runtime verification 與零信任共有），不宣稱四者具完全相同之認識論骨架。

### 4.4.2 三種驗證證據

| 殘差 | 驗證的問題 | 證偽的不變量 | 判定型態 |
|---|---|---|---|
| **C_i** 場域守恆 | 量測是否仍描述同一封閉母體？ | N_total = N_known | 近確定性斷言 |
| **S_i** 跨節點佐證 | 其他節點是否支持此節點觀測？ | delay 符合場域即時共識 | robust 統計殘差 |
| **H_i** 成員轉移 | UE 之報表歸屬序列是否符合場域約束？ | 成員轉移時空連續 | 非參數檢定 + 確定性斷言 |

三者取自不同觀測維度（空間聚合／空間並置／時間連續），**互補但非統計獨立**（皆依賴 IMSI/cell 上報，LTE 錨點缺報會同時影響 C_i 與 H_i）。其防禦價值在於：攻擊者要同時不被三者否證，需讓偽造資料同時滿足多種不同約束——此僅就竄改幅度超出各證據偵測邊界之攻擊而言，不構成完整性保證：幅度落在邊界以內之竄改，單一節點即可同時通過三者（4.10.4）。

此跨來源佐證之原則並非全新範式：3GPP 於假基站偵測中已載明，多個 UE 之量測報告可用於過濾單一惡意 UE 之錯誤報告（TS 33.501 Annex E §E.2）。本研究將其移植至 E2 介面與內部威脅方向。

### 4.4.3 融合結構之設計理由：為何不採線性加權

> 本節說明 4.4.0 規則結構之設計理由；規則本身見 4.4.0。

#### （一）加權平均會使確定性證據被稀釋

三項殘差之性質並不對等。$C_i$ 為布林斷言（Alpern & Schneider 意義下之 safety property）；$H_i$-D2 為由本場景移動行為導出之情境特定斷言（觀測層級）；$S_i$ 與 $H_i$-D1 則為統計殘差，其輸出為連續偏離量。

若以線性加權合成單一信任分數，某窗之 $C_i$ 確定違反（分數為 0）而 $S_i$ 與 $H_i$ 均正常（分數接近 1）時，合成分數仍可能落於可信區——**以最弱之證據稀釋最強之證據**。

此問題不能以調整權重解決。提高 $C_i$ 之權重至足以單獨主導判定時，該權重在數學上已等價於一條硬否決規則，惟表達較不明確、門檻與權重之交互作用難以稽核。**既然目標行為是一票否決，直接表達為規則較表達為權重更誠實且可驗證。**

#### （二）此選擇對應 criteria-based 信任演算法

NIST SP 800-207 將信任演算法區分為 criteria-based（一組合格條件全數滿足方予放行）與 score-based（加權信賴分數比門檻）。本研究屬前者。以 KPM 為輸入之零信任框架多採 score-based 設計——例如 i-ZTA 之信任評估引擎輸出 0 至 1 之連續信賴度量（Ramezanpour & Jagannath, 2022）。該架構以 E2 KPM 與 O1 KPI 作為信任評估與網路安全狀態分析之輸入，但未驗證 KPM 數值本身是否為真，亦未討論身分合法而遭攻陷之 E2 節點偽造資料之情形；其持續多因子認證檢查的是元件身分與軟體完整性，而非數值內容。就該文所述之設計而言，未見對 KPM 數值真實性之檢查。（該文為概念性架構，未含實作與量化評估。）該設計適用於證據性質同質之情形；當證據中同時包含確定性斷言與統計殘差時，分數化會抹除二者在認識論上之差異。

#### （三）三項行為承諾

1. **硬違反優先**：確定性證據一旦成立即直接產出判定。
2. **單一統計證據不冒進**：$S_i$ 或 $H_i$-D1 單獨違反僅得 low-trust，其必要性以 4.8.6 之 edge UE 誤報率檢驗【待定】。
3. **fail-closed**：證據不可得不得視為證據支持，且於任何准入政策下皆不准入（v12.3 起由 P3 之證據可得性閘保證，4.9.3）。

前兩項於 4.11 之規則回放中檢驗；fail-closed（`R3_ABSTAIN`）之規則層級行為見 4.4.0（三）之窮舉單元測試與 5.9 之 S2；其於 D-50PH 與 D-S12 上之實際窗數【待定】。

#### （四）拒絕採信，而非容錯聚合

拜占庭容錯框架之目標為在部分節點惡意之情形下**仍產出可用之聚合結果**；零信任之目標為**在採信前逐份驗證，證據不足時拒絕採信**。前者以可用性為優先並容忍受污染輸入，後者以正確性為優先並接受可用資料量之減少。本研究採後者，其代價（可直接採信之比例下降、可用資源減少）於 4.9.6 與 4.12 揭露。
