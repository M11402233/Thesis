## 4.10 對抗性分析：偽造信任證據所需之最小攻陷

### 4.10.1 方法論定位

採 **分析論證 + 單元件實測 + 多節點離線合成注入**，**非 N 節點端到端模擬**。多節點（m ≥ 2）為離線合成——將 active-cell set 中 m 個節點之 delay 設為同一偽造值以模擬協同上報，active cells < m 時該窗跳過。宣稱限定為組合下界。

### 4.10.2 攻擊者模型

控制 m 個 mmWave 節點（身分合法、可任意竄改），目標使偽造量測於 S_i fail-to-reject，白箱知識。**限制**：無法控制 LTE 錨點（信任根）、未攻陷節點與物理世界。定義：

$$m^*_{S,50} = \min\{\, m : P(\text{bypass} \mid \text{full consensus}) \geq 0.5 \,\}, \qquad m^*_{S,100} = \min\{\, m : P(\text{bypass} \mid \text{full consensus}) = 1 \,\}$$

### 4.10.3 抗串謀強度

攻擊者將 m 個節點之 delay 同步偽造為「場域共識 + 6σ」。以每個（窗, m-子集）為一次 trial，依受控目標 cell 之 peer 數分三層，分母嚴格分離；unavailable 屬證據不可得，不計入有效繞過：

| m | full-consensus trials (peer ≥ 2) | full-consensus bypass | weak (peer = 1) | unavailable (peer = 0) |
|---|---:|---:|---:|---:|
| 1 | 【待定】 | 【待定】 | 【待定】 | 【待定】 |
| 2 | 【待定】 | 【待定】 | 【待定】 | 【待定】 |
| 3 | 【待定】 | 【待定】 | 【待定】 | 【待定】 |
| 4 | 【待定】 | 【待定】 | 【待定】 | 【待定】 |

（τ_S = 4，LOSO 尺度；D-50PH 與 D-S12 各一表；`run_adversarial_msweep.py`。）表中之繞過率僅就固定偽造幅度（共識 + 6σ）而言；幅度低於 τ_S·s 之偏移，單一節點即可通過（4.7.8 Q4）。

**結果**：$m^*_{S,50}$、$m^*_{S,100}$【待定】。

**機制（分析性）**：單點（m = 1）僅控制受測 cell，無法改變由其他 cell 構成之中心 $c_j$，故於 full-consensus 窗幾乎無法繞過。攻擊者須控制受測節點之 peer 中約半數，方能將 median{其他} 拉向偽造值、使 $z$ 由 6σ 降至 τ_S 以下。故 $m^*$ 取決於每窗活躍之 mmWave cell 數（4.7.1）。

**與場域密度之關係**：抗串謀強度取決於同窗活躍之誠實 peer 數，**於離峰或低密度時段將退化**；D-S12 之 $m^*$ 即量測此退化【待定】。

### 4.10.4 收斂宣稱

在本文定義之攻擊類別、1 秒觀測粒度、LTE 錨點可信且持續可觀測之條件下，**竄改幅度超出各證據偵測邊界之單點攻擊**（淨變化不為零之基數增刪、足夠快之延遲漂移、固定 6σ 之延遲偽造）預期會被至少一項適用之證據標記，其比例以本章各節之結果為準【待定】。**惟單一 O-DU 可同時通過三類證據之路徑依構造存在**：（一）貼門檻之延遲偏移（4.7.8 Q4，依構造停在 τ_S·s 以內）；（二）較接近 τ_S 之小幅延遲階躍（4.12.4 之 ×0.8，其誘導率【待定】）；（三）守恆式替換——C_i 與 S_i 皆正常（4.6.6），H_i 是否補上以 D-50PH 之 D2 結果為準。本研究不宣稱「單一 O-DU 無法同時繞過三類證據」。

單點攻擊於不同類別下通常被至少一項**適用之**驗證證據否證，但不存在「任一單點攻擊必然被某驗證器抓到」之完整性保證——守恆式替換繞過 C_i、S_i 於證據不足窗無法判定、單窗脈衝不升級為 rejected、純吞吐量竄改不涵蓋。$m^*_{S,50}$ 與 $m^*_{S,100}$ 僅為繞過 S_i 之局部成本；同時通過三殘差之聯合下界 $m^*_{CSH}$ 尚未量化。面對會學習之攻擊者時之表現見第五章。

## 4.12 資源—政策評估：排除不可採信量測後之可用資源與決策品質

> **定位**：本節回答 RQ3。資源指標（准入輸入可用率、$\rho_{\text{PRB}}$、$V_{\text{PRB}}$）由**可用資源評估 xApp** 於同一回放迴圈中、每窗 P3 發布後逐窗產出；攻擊情境下，注入後之 trace 經同一管線重放：資源指標同樣由可用資源評估 xApp 逐窗產出（E18），保護效果與下游決策品質則搭配代理決策評估。二者皆為 trace replay 上之整合原型，未涉及 runtime 控制，亦無閉迴路。本節只評估准入政策下之可用資源，不做資源分配（下一篇之題目）。

### 4.12.1 問題與量之定義

RQ3 問：於排除被判定為不可採信之量測後，尚餘多少可用資源；此准入政策之可用性代價為何；驗證之運算開銷為何。運算開銷見 4.9.5；本節定義並評估前二者，另以一個代理決策評估下游決策之品質。

**資源准入遮罩（eligibility mask）**：對每個 (節點 $j$, 窗 $t$)，若 Policy Enforcement 之動作屬准入集合則 $m_j(t) = 1$，否則為 0。准入集合由准入政策決定（4.12.3）。

**保留可用容量比**：

$$\rho = \frac{\sum_t \sum_{j \in \mathcal{A}(t)} m_j(t)\, K_j}{\sum_t \sum_{j \in \mathcal{A}(t)} K_j}$$

其中 $K_j$ 為 cell $j$ 之容量參考，取自 **resource inventory（場域組態）**，而非受測節點上報之 KPM。須說明兩點：

1. 此量描述「其量測被准入、因而可供消費端納入決策之節點，其組態容量之佔比」。它不是量測到之頻譜使用量，亦不能用以驗證吞吐量上報——純吞吐量竄改仍未涵蓋（4.5.2）。
2. 本場景（configuration 1）之七個 mmWave gNB 採同一載波設定（中心頻率 3.5 GHz、頻寬 20 MHz，由 `scenario-three.cc` 之全域預設設定，無逐 cell 覆寫），故 $K_j$ 相同。分母 $\mathcal{A}(t)$ 取**當窗有上報之 mmWave 節點**；LTE 錨點為驗證用輔助輸入，不在准入範圍內；無活躍 mmWave 節點之窗（`n/a`）不產生註記，亦不在評估之窗內。$K_j$ 相同時，$\rho$ 於上式之彙總定義下即等於**可用量測產出率**（准入之註記佔全部註記之比例）。

**原生 PRB 之保留比例（主指標）**：以模擬器輸出之 E2SM-KPM `RRU.PrbUsedDl` 為資源量。令 $U_j(t)$ 為 cell $j$ 於第 $t$ 秒之 PRB 時間占用率（各 UE 之 `RRU.PrbUsedDl.UEID` 加總 ÷ 139，取自乾淨模擬、僅下行），則

$$\rho_{\text{PRB}} = \frac{\sum_t \sum_{j} m_j(t)\, U_j(t)}{\sum_t \sum_{j \in \mathcal{A}(t)} U_j(t)}, \qquad V_{\text{PRB}} = 1 - \rho_{\text{PRB}}$$

$\rho_{\text{PRB}}$ 為「已使用之 PRB 中，其 KPM 仍被准入決策採用之比例」；$V_{\text{PRB}}$ 稱為 **PRB 能見度損失**，即其 KPM 被排除、消費端決策時看不到之 PRB 負載比例。**$V_{\text{PRB}}$ 不是容量損失**：被排除之節點仍持續排程。$\rho$（組態容量版本，以下稱 $\rho_{\text{cap}}$）保留為輔助指標。

**原生 PRB 之性質**（依 ns-O-RAN 原始碼查證）：
1. 此模擬器之 MAC 為分時排程，每次配置佔滿整個頻寬，無頻域 PRB 配置；`RRU.PrbUsedDl.UEID` = 該 UE 於報告窗之排程 OFDM 符號數 ÷（報告窗之 slot 數 × 14）× 139。故原生 PRB 用量等於符號占用率乘以常數。此計算方式與 3GPP TS 28.552 V20.4.0 §5.1.1.2.5 之定義（期間內所用 PRB 數之算術平均、單一整數）不同：模擬器以時間占用比例近似、輸出為非整數。故本研究將其視為模擬器提供之資源用量代理，主表報告占用率與比值，不宣稱與實際設備依 TS 28.552 回報之值等價。
2. 常數 139 為原始碼寫死之值，等於 ceil(100 MHz ÷ 720 kHz)，即 configuration 2 之載波；configuration 1（20 MHz、numerology 2）實際為 28 RB。本節主表報占用率與比值（與此常數無關）；絕對 PRB 數另以 28 RB 尺度換算。
3. cell 層級之 `RRU.PrbUsedDl` 欄位於原始碼中以整數逐 UE 累加、每次截斷小數，系統性偏低，故不採用，改以 UE 層級值加總。
4. 每個 seed 均以 `RxPacketTrace` 之下行排程符號數重算並交叉驗證（`prb_reader.py`，容許差 0.5 PRB）。D-50PH 含換手，PRB 須依當秒之服務 cell 歸帳【待定：交叉驗證結果】。

**資源指標之區分**：

| 指標 | 意義 |
|---|---|
| PRB 使用量（usage） | 觀測窗內實際使用之資源 |
| PRB 配額（quota） | 設定之資源比例或分配上限，非量測值 |
| 分配成功率（allocation success） | 依各研究定義之成功服務之請求比例 |
| 保留可用容量（ρ_cap） | 准入政策下，可用量測所屬節點之組態容量佔比 |
| PRB 能見度損失（V_PRB） | 已使用之 PRB 中，其 KPM 未被准入決策採用之比例；非容量損失 |
| 吞吐量（throughput） | 實際送達之資料率；與資源分配相關，但不等同 PRB 數 |

**政策引致之可用性成本**：乾淨資料上之 $1 - \rho$，即無攻擊時因誤報與證據不可得而未被准入之比例。

### 4.12.2 代理決策

為評估准入政策對下游決策之影響，定義一個明確之消費端代理決策：於窗 $t$ 為一新流量選擇服務 cell，準則為**回報延遲最低者**：

$$j^*(t) = \arg\min_{j \in \mathcal{M}(t)} \widehat{\text{delay}}_j(t)$$

其中 $\mathcal{M}(t) = \{\, j \in \mathcal{A}(t) : m_j(t) = 1 \,\}$ 為准入後之候選集。

**關鍵設計**：攻擊者謊報延遲以吸引流量；本節之決策為代理 steering 決策，其代價以原始 trace 中候選 cell 之**真實延遲**計算。不實際移轉 UE，移轉後之負載、排程與延遲回饋不在模型內：

$$\text{regret}(t) = \text{delay}^{\text{true}}_{j^*(t)}(t) - \min_{j \in \mathcal{A}(t)} \text{delay}^{\text{true}}_j(t)$$

此評估方式與資訊物理系統中評估偽資料注入影響之慣例一致：攻擊影響的是決策，其代價須以真實狀態衡量。第五章之攻擊者報酬亦以此 steering 結果定義（5.4）。

### 4.12.5 判讀問題（結果待定）

以下四項為本節要回答之問題，答案以 4.12.4 之數字為準，不預設方向：

**（一）未經驗證時，延遲壓低攻擊之誘導率與真值代價為何。** 代理決策以回報延遲為唯一準則，高誘導率為其直接後果，不代表真實 RIC 決策受誘導之程度（4.12.6）【待定】。

**（二）嚴格准入對各幅度之攻擊之保護程度，與其於乾淨資料上之代價。** 須同時報告保護（誘導率、regret 之下降）與代價（乾淨資料上之 $V_{\text{PRB}}$、最佳候選被濾除率、引入之 regret 與誤選率）。較接近 $\tau_S$ 之 ×0.8 階躍預期保護較弱；若攻擊落於偵測門檻之下而誤報濾除最佳候選，regret 可能不降反升——此機制是否於 D-50PH 出現以結果為準【待定】。

**（三）僅排除 rejected 之准入政策是否提供保護，其來源為何。** S_i 違反單獨成立時產出 low-trust 而非 rejected，故 `C_restrict_annot` 與 `C_notrej` 之差異只在 abstain。若其誘導率下降，須分解是否來自 `R2_SI_D1_BOUND`（攻擊者節點之 S_i 違反恰與其綁有之 D1 證據同窗）；若是，此保護為 D1 證據之基準比例所附帶，**並非針對延遲攻擊之設計機制**【待定】。E12（S_i 持續窗 $L_S = 2$ 升級為 rejected）為候選、未採用，其誘導率與新增乾淨誤拒【待定】。

**（四）可用資源之多寡如何取決於證據綁定粒度。** window 政策為全有全無（整窗候選集要嘛完整、要嘛為空）；uebound 產生部分候選集，因而可能濾除真值最佳者。**細粒度換得可用性，代價為新增之誤排除成本**——此為構造上之取捨，其大小【待定】。

### 4.12.6 界定

- 導向策略為本研究定義之**代理決策**（單一新流、以延遲為唯一準則），非真實 RIC 排程器；未建模負載回饋與換手成本。
- **開迴路**：$U_j(t)$ 取自乾淨模擬；攻擊誘導之流量轉移不會改變 PRB 用量（未建模負載回饋）。故 $\rho_{\text{PRB}}$ 描述決策時可見之 PRB 負載，而非攻擊後之實際 PRB 分配。
- **PRB 本身未經驗證**：`RRU.PrbUsedDl` 亦可被受攻陷之 O-DU 竄改。本節以乾淨之 PRB 為權重，不以上報值為權重；竄改 PRB 之情境本研究未評估。
- 原生 PRB 之絕對數以寫死之常數 139 計算（4.12.1）；比值型指標不受影響。
- 若消費端之目標函數依賴未被驗證之量（如吞吐量，4.5.2 之 B2），C-ZT 無法提供保護。本實驗以延遲為準則，正因其為 S_i 所驗證之維度。
- 攻擊僅含延遲類；基數類與成員類攻擊對下游決策之影響未評估。
- 可用資源評估 xApp 之逐窗輸出為整合原型上之 trace replay：其 DB 與 Resource Termination 為行程內之抽象層，未經 live RIC 之 shared data service。消費端於閉迴路中之行為未評估。

（腳本 `run_RQ3_decision_replay.py`，註記與准入取自 `zt_kpm_xapp.py` 之 P1–P3；一致性檢查依賴 `run_E10_D1_policy_ablation.py`）

## 4.13 本章總結

本章提出 C-ZT 之規則版：以 Detection、Trust Assessment、Policy Enforcement 與可用資源評估四個 xApp（本原型以離線 trace 回放之邏輯模組實作），持續評估 E2 量測資料之可信度、對合作消費端執行准入，並逐窗回報准入政策下之可用資源。規則版同時為第五章學習端之下限與比較基準（F）。各研究問題之結果待 D-50PH 與 D-S12 之重跑完成後填入；本節先列各項要報告之內容與已能依構造陳述者。

**RQ1：上報值何時構成違反**

- **C_i**：乾淨資料之反例數與乾淨誤拒；灌水、虛減與守恆式替換之偵測【待定】。依構造：淨變化為零之替換繞過 C_i（配平容錯空間 0），持續窗政策下之單窗脈衝不升級為 rejected；單點虛減之可偵測性取決於錨點名單是否列出該 UE（4.6.5）。
- **S_i**：空間與時間參照於漂移與階躍下之偵測率及各自之乾淨誤報【待定】（4.7.4–4.7.5）；同條件比較（4.7.5.5）【待定】。**本研究不主張 peer 檢查之偵測力優於監督式方法**，其可主張者限於設計性質：無需攻擊樣本、不需事先知道攻擊方向。證據可用率與抗串謀之 $m^*$ 取決於 UE 密度，D-50PH 與 D-S12 各報【待定】。
- **H_i-D2**：D-50PH 開啟合法換手，D2 首次有非 vacuous 之乾淨基線，其誤觸數【待定】；注入之偵測屬設計必然。**H_i-D1**：逐 UE 誤報、edge／resident 差異與嚴重度–反應曲線【待定】（4.8.6）。

**RQ2：何時拒絕、依何證據、能否恢復**

- 本章**定義**四種信任狀態與階層式融合規則（4.4.0，嚴重度序），以規則稽核揭露交叉佐證之證據綁定缺口，並以規則回放檢驗其決策一致性；每筆判定攜帶其觸發規則與證據。證據不可得者於任何准入政策下皆不准入。
- D1 證據之節點歸屬定案採 UE 綁定；乾淨資料之決策分布、`R2_SI_D1_BOUND` 之乾淨誤拒與 L1 誤觸【待定】（4.9.6.5）。
- **D1 證據之規模效應**：預期隨每節點 UE 數上升，D-50PH 與 D-S12 之對照量測之【待定】（4.9.6.6）；凍結之門檻不因此修改。
- 信任狀態不永久繼承前窗；轉移與恢復延遲（E11）、重複單窗脈衝（E11b）與 S_i 持續性升級候選（E12）【待定】。

**RQ3：保留之可用資源與驗證開銷**

- 未經驗證與嚴格准入下之誘導率、regret，以及乾淨資料上之 $\rho_{\text{PRB}}$、$V_{\text{PRB}}$ 與決策可用率【待定】（4.12）。
- 驗證層與四個 xApp 合計之每窗運算開銷（離線重放微基準，不含傳輸、解碼與共享資料層）【待定】（4.9.5）。

尚未完成者：三類證據之聯合端到端效能、live E2 綁定與端到端延遲、各 xApp 之獨立部署與其間經 shared data service 之通訊、閉迴路下之決策保護效果、依部署規模校準 D1 門檻與交叉佐證強度，以及吞吐量竄改之驗證（須以資源量測為佐證，4.5.2）。
