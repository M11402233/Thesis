## 2. 方法（全部只用訓練 seed 校準；門檻 = 訓練 seed 乾淨序列後半段之逐窗誤報 1%，CUSUM 除外）

| 代號 | 方法 | 輸入 | 判定 |
|---|---|---|---|
| M1 | 範圍檢查 | 自身值 | 超出訓練 seed 全部乾淨 delay 之 [min, max] 即告警（最緊之可辯護範圍；不校準到 1%） |
| M2 | 自我參照 | 自身前 10 窗中位數 | \|o_t − med(o_{t−10..t−1})\| / s_T，s_T = 訓練殘差之 1.4826·MAD |
| M3 | peer 線性雙側（V0e） | 同窗 peer 中位數 | 同 B1 V0，門檻改 1% |
| M4 | peer 對數雙側（V2e） | 同窗 peer log 中位數 | 同 B1 V2 |
| M5 | peer 對數單側下界（V3e） | 同上 | 同 B1 V3 |
| M6 | peer＋CUSUM | 對數殘差 | 單邊下界、單邊上界各自 ARL0 ≈ 1000（k = 0.5）；兩者分列 |
| M7 | 前作類 LSTM | 自身 delay 長度 10（level 正規化，同 E9b level） | AF 1.2／1.3／1.4／1.5 階躍標籤訓練（設定同 R2） |
| M8 | 攻擊已知之監督式 LSTM | 自身 level ＋ peer 對數殘差（2 通道） | AF 0.6–0.9 與 1.2–1.5 階躍標籤訓練；K_ONSET 改 3（計算量），其餘同 M7 |

## 3. 攻擊（全部自 t0 起、至序列結束）

階躍 ×1.2、×1.3、×1.5（前作之族）；×0.9、×0.8、×0.6（本研究之報低）；漂移下行 1%/s（下限 0.5）、上行 1%/s（上限 2.0）。

## 4. 指標

- 乾淨：測試 seed 後半段之逐窗告警率（M6 另報 ARL0）。
- 攻擊：後半段逐窗偵測率、未偵測比例（後半段無任何告警之序列比例）、首次偵測延遲中位數（窗）。
- 皆報 56 條之平均與 seed 間範圍。

## 5. 檢查（失敗即停）

- C3-0：56 條樣本、8 fold。
- C3-1：M3、M5 之乾淨誤報與各攻擊偵測率逐位重現 B1 之 V0e、V3e（共有之攻擊）。
- C3-2：M7、M8 每個 fold 之訓練 balanced accuracy（機率 0.5）≥ 0.80（同 E9b 事先門檻）；未過之 fold 該方法不採計、只記錄。
- C3-3：確定性——固定種子、`torch.use_deterministic_algorithms(True)`。

## 6. 事先揭露之限制

1. M7 **不是前作之重現**：前作輸入為 per-UE 多項 KPM，本實作只有 per-cell delay；模型與訓練量不同。前作自報之 0.07% 誤報屬其資料與評估方式，本檔不宣稱可比。
2. M8 以與測試相同之攻擊倍率訓練，屬樂觀上界（防守方事先知道攻擊型態）。
3. M1 之範圍取自訓練資料之極值，比任何規格範圍都緊；實際部署之範圍檢查只會更寬、偵測更少。
4. CUSUM 之誤報以 ARL0 表示，與逐窗 1% 不完全同口徑，分列。
5. 同一序列之乾淨後半段亦可能告警（B2 之污染問題）；未偵測比例含此成分。
6. 輸出：`data/results/advisor_20261118/C3_comparison.json`、`.log`；腳本 `scripts/advisor_20261118/run_C3_comparison.py`。

## 7. v0 結果與事後修正 v1（2026-11-18，看過 v0 結果後才改，須揭露）

**v0**（`C3_comparison_v0.json`／`.log`；C3-0～C3-2 通過）：M7、M8 之測試乾淨誤報 **0.298／0.518**（目標 1%），未達「同誤報」，兩列不可與其他方法比較。原因：門檻取自訓練過之乾淨序列（模型已擬合，分數偏低）。M1–M6 誤報 0.0001–0.022。

**v1 修正**（只改下列三點，其餘不變）：
1. M7、M8：每個 fold 之 7 個訓練 seed 中，固定取「受測 seed 之下一個 seed」（循環）為校準 seed，不參與訓練；門檻 = 校準 seed 乾淨序列後半段之 99% 分位。訓練改用其餘 6 seed。M1–M6 不變（無學習成分；C3-1 仍須逐位重現 B1）。
2. 新增指標：`clean_any`（乾淨序列後半段至少告警一次之比例，作為「未偵測比例」之對照）；`lift`（攻擊後半段逐窗告警率 − 同序列乾淨後半段告警率）。
3. 修正輸出列印（無偵測時無延遲值）。

v0 輸出保留不覆蓋；v1 輸出 `C3_comparison.json`／`.log`。

**v1 結果**（2026-11-18，8,973 s；C3-1 ✓、C3-2 擬合 M7 0.996–0.998、M8 0.995–0.997 ✓）：M1–M6 與 v0 逐位相同（無學習成分，符合預期）。M7、M8 於 8 個 fold 之校準 seed 門檻**皆 = 1.0000**（v0 訓練內門檻 M7 ≈0.28、M8 ≈0.65）：未參與訓練之 seed 上超過 1% 之乾淨窗得到 float32 飽和分數 1.0，告警條件「> 門檻」從不成立 → 測試誤報 0、所有攻擊未偵測 1.00。此為**退化結果**，不得寫成「LSTM 偵測率 0」；可寫者：同資料、跨 seed、1% 誤報下，兩個 LSTM 皆無可用操作點（分數飽和），訓練內擬合與跨 seed 表現差距大。可能之修正（未執行，須使用者決定）：以 logit 取代 sigmoid 輸出排序取門檻，消除飽和並列。

**v2 修正**（2026-11-18，看過 v1 結果後由使用者同意之第二次事後修正，須揭露）：僅改 M7、M8 之門檻與告警所用之分數空間——由 sigmoid 機率改為 logit（sigmoid 前之值）；單調轉換，不改模型、訓練、校準 seed、99% 分位之定義，只消除 float32 飽和造成之並列。新增診斷欄位 `cal_frac_sigmoid_saturated_f32`（校準 seed 乾淨窗中 sigmoid 飽和為 1.0 之比例）。v1 輸出改名保留為 `C3_comparison_v1.json`／`.log`；v2 輸出 `C3_comparison.json`／`.log`。

**v2 結果**（2026-11-18，8,234 s；C3-1 ✓、C3-2 ✓；M1–M6 與 v0／v1 逐位相同）：M7、M8 logit 門檻 20.0–29.2／25.1–35.3；校準 seed 乾淨窗 sigmoid 飽和比例 0.015–0.065／0.052–0.143（解釋 v1 之門檻 1.0）。測試乾淨誤報 M7 0.0149（seed 0.0029–0.0356）、M8 0.0078（0.0010–0.0112）。lift：M7 ×1.2 0.319、×1.5 0.674、調低四種 −0.013～−0.008；M8 ×1.2 0.200、×1.5 0.498、×0.9 0.041、×0.8 0.260、×0.6 0.790、漂移↓ 0.686。peer 對數單側 ×0.6 0.103、漂移↓ 0.196；CUSUM 下 0.097／0.110。clean_any 0.02–0.66，故「未偵測比例」不作主指標，主報 lift。M8 之訓練攻擊與測試同產生器，為已知攻擊之樂觀上限。
