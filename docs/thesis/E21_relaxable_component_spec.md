# 規格 E21：可放寬之學習元件——在 strict 下放回「被 D1 單獨牽連」之乾淨報告（v0 設計草稿，2026-11-12）

> 狀態：**v0 設計草稿——未寫程式、未計算任何新數字**。使用者 2026-11-12 同意之目標：「在 strict 下，把被 D1 單獨牽連的好資料放回來，同時不讓假資料跟著漏進去」；並同意先設計（參照清單與設計同時提出，使用者一併審閱）。

**推論（待驗證，不得寫成結果）**：D1 單獨觸發之 low-trust 對延遲竄改之「保護」主要來自「擋得多」而非「擋得準」；其真正之用途是**成員關係攻擊**（超時消失、守恆式替換之成員面）。因此放寬 D1 單獨觸發之代價應以**成員關係攻擊之漏放**衡量，延遲攻擊之漏放只作為「放寬後失去之偶然保護」報告。

## 1. 放寬之範圍（硬性邊界；任何變體不得越界）

| 可放寬 | 不可放寬（維持規則判定） |
|---|---|
| 規則判定為 low-trust、**且觸發規則僅為** `R2_D1_STRONG` 或 `R2_D1_WEAK`（S_i normal、C_i conserved、D2 normal、無 also_matched 之其他規則）→ 可改為 trusted | L1 全部（`R1_CI_VETO`、`R1_CI_PENDING`、`R1_D2_VETO`、`R1_AUTHZ`、`R1_STAGE1`）；任何 rejected；`R2_SI_ALONE`、`R2_SI_D1_*`；abstain（fail-closed）；S_i unavailable |

- 放寬只能是 **low-trust → trusted**，不得 low-trust → 其他、不得跨窗繼承（不繼承原則照舊）。
- 每筆被放寬之判定記錄新規則代碼（暫名 `R2_D1_RELAXED`）與放寬依據（模型版本、分數），可追溯。
- 與 R7「學習只能更嚴」之關係：E21 是**另一個版本**（V-relax），不取代 V-escalate；正文須明寫兩者之約束不同與理由（F2）。

### 3.2 學習元件（V-relax）

- **決策對象**：§1 之可放寬 (節點, 窗)；輸出「放寬／維持」。
- **輸入特徵（只用 RIC 可見之 KPM 與既有證據；不得使用 PHY、真值或同窗 peer 中位數以外之未來資訊）**：該節點綁定之 D1 UE 數與各自 z_d、停留長度；各 UE 之歷史劣化佔比（訓練基線）；過去 K 窗之判定與 S_i z（連續值）；該 UE 於 LTE 錨點報表之 KPM（LTE 側延遲）；同節點其他 UE 之狀態。
- **模型**：先以**監督式分類器＋校準門檻**（標籤由注入構造給定），門檻依 X2 之風險控制在校準 fold 上選定，使成員攻擊漏放率 ≤ α；DRL 版本（與 E19 同框架、動作改為可放寬）列為選項（Q3）。
- **訓練／校準／測試**：LOSO（8 seed）：6 訓練、1 校準、1 測試，輪轉；Stage 3 為分布外測試（不參與任何選擇）。

## 6. 已知問題（設計定案前須回答）

1. **I9 之注入是否符合威脅模型**：`inject_overtime` 把 UE 由 mmWave 報表移到 **LTE 錨點報表**；但 LTE 錨點為信任根、被攻陷之 DU 不能改它。若 DU 只是把 UE 自自己報表刪除，LTE 錨點不會出現該 UE，表現為 UE 全域缺席（C_i 違反）或缺報中斷 D1 計數。**須先釐清 D1 單獨觸發在本威脅模型下實際防的是哪一種攻擊**；若答案是「幾乎沒有」，則 B-off 可能已是合理解，學習元件之必要性要重新評估。
2. 守恆式替換（I10）中被移除之真實 UE 於所有報表缺席——依缺值語意會中斷 D1 計數；D1 是否真能接住替換，須以現行程式重測。
3. 特徵中「UE 於 LTE 錨點報表之 KPM」在注入器中為搬移之 mmWave 延遲值，可能使模型學到注入之人工痕跡；須改注入方式或排除此特徵。

## 8. 第 0 步：D1 單獨觸發在本威脅模型下防什麼（2026-11-12，程式碼層級分析；尚未以資料驗證）

**威脅模型前提**：被攻陷之 DU j 只能改**自己**之報表；LTE 錨點報表為信任根，不可改（I1）。D-30 中錨點只回報「僅由錨點回報」之 UE，與 mmWave 集合從未重疊（30,477 anchor-only／41,523 mmWave-only／0 同窗雙掛）。

**參照（皆為現行程式）**
- R-a `zt_kpm_xapp.py:524–538`：`dwell_runs[i]` 僅於 UE 當窗**只**出現在錨點時 +1；同窗出現於任一 mmWave 報表即歸零；當窗未出現於任何報表亦歸零（缺報中斷）。`last_serving[i]` = 當窗所在 mmWave cell 之最小者。
- R-b `zt_kpm_xapp.py:336–347` `d1_ue_levels`：只對 `anchor.dwell` 有基線之 IMSI 計算（基線需 ≥ 8 段停留，`:256–260`）。
- R-c `zt_kpm_xapp.py:350–362` `verify_hi_d1_uebound`：證據歸屬於 `last_serving == target` 之節點。
- R-d `zt_kpm_xapp.py:268–280` `verify_ci`：只比計數；未登記 ID 只填 `candidate_cells`。
- R-e `run_E10_D1_policy_ablation.py:90–104` `inject_overtime`：把 UE 自 mmWave 報表**搬到錨點報表**——須改錨點，超出威脅模型（§6 問題 1）。E10／E14／E11（`run_E11_transitions.py:94`）之 D1 偵測結果皆用此注入。

**DU j 只改自身報表時，對 D1 之影響（逐一推導）**

| 成員關係攻擊（只改 j 之報表） | dwell_runs（R-a） | 對 D1 之效果 | 由誰接住 |
|---|---|---|---|
| 刪除 j 真實服務之 UE（虛減） | 該 UE 全域缺席 → 歸零 | **不產生** D1 證據 | C_i（計數下降，R-d） |
| k-for-k 替換（刪真 ID、加假 ID） | 真 UE 缺席歸零；假 ID 無基線（R-b） | **不產生** | 無（C_i 盲點，§6 問題 2 由程式確認） |
| 宣稱一個實際只在錨點之真 UE（灌入他處之 UE） | 出現於 j → 歸零 | **消除**該 UE 之 D1 證據 | C_i 不變（聯集不變）；目前無規則接住「同窗雙掛」 |
| 宣稱 peer k 之 UE | `last_serving` 可能改為 j（取最小 cell id） | 改變 D1 證據之**歸屬**，不新增證據 | D2 不觸發（兩者皆 mmWave 且有交集）；C_i 不變 |
| 只改延遲值（E19 之攻擊者） | 不變 | 與乾淨相同（F2） | S_i |

**推論（待資料驗證，不得寫成結果）**
1. 在本威脅模型內，D1 證據是由**錨點之真實觀測**產生；DU j 改自己的報表**無法使自己被 D1 綁定之證據增加**，只能使其減少（宣稱錨點 UE）或轉移（宣稱 peer 之 UE）。因此 D1 單獨觸發之 low-trust **不偵測任何「只改自身報表」之竄改**；它標記的是「最近由 j 服務之 UE 正處於 mmWave 鏈路劣化」，屬於**資料品質／情境**訊號，而非竄改證據。
2. 推論 1 若成立，則 B-off（D1 單獨不降級）在「竄改偵測」口徑下沒有漏放代價；唯一失去的是 F2 之「偶然保護」（隨機擋掉一半，使延遲攻擊之 MF 下降）。學習元件之必要性須重新評估：若 B-off 已是合理解，E21 改為**說明為何放寬**而非**學習放寬**。
3. 推論 1 揭露一個**反向缺口**：DU j 可把一個只在錨點之真 UE 加進自己的報表，造成「同窗雙掛」；乾淨 D-30 中雙掛為 0，但目前沒有規則使用此事實（C_i 只比計數）。此為**新發現之未覆蓋攻擊面**，不屬 E21 範圍，另列待辦。
4. 既有之 D1 偵測數字（E10、E14、E16、E11）皆基於 R-e 之注入，代表「若錨點觀測到超時停留」之偵測能力，**不代表被攻陷 DU 可造成之情境**；正文引用時須註明。

**建議之資料驗證（E21-S0，待使用者確認後才執行）**：於 D-30 8 seed，對每個 mmWave 節點 j 注入上表前四種**只改 j 報表**之攻擊（k = 1, 3；起點與 E10 相同之抽樣），以現行 `verify_hi_d1_uebound`／`fuse_detail` 回放，報告：j 之 D1 證據（strong/weak）相對乾淨之變化量、C_i／D2 觸發率、最終判定分布。預期（推論 1）：D1 證據增加量 = 0。若不為 0，推論 1 不成立，E21 依原設計進行。

### 8.1 E21-S0 規格 v1（2026-11-12 使用者同意執行；本節先於任何執行 commit）

**設定**：`ZT_DATASET=d30`、`ZT_FUSION_ORDER=severity`、uebound、strict；8 seed，LOSO 信任根（與 E20 相同：`TrustAnchor(其餘 7 seed)`）；舊機器執行。

**注入**（只改被攻陷節點 j 之報表；LTE 錨點與其他節點逐位不變）
- j ∈ 每個 mmWave cell（CellId ≠ 1）；起點 t0 ∈ {50, 100, 150, 200, 250}（窗索引）；持續 L = 10 窗；k ∈ {1, 3}。
- 每窗挑選對象：沿用上一窗仍合格之 UE，不足者以合格 UE 中 IMSI 最小者補足（確定性）；合格 UE 不足 k 時能改幾個改幾個，記錄實際筆數；episode 內實際修改 0 筆者排除並計數。
  - **A1 刪除**：自 j 之報表移除 k 個 j 當窗回報之 UE。
  - **A2 k-for-k 替換**：同 A1 移除，另加 k 個假 ID（9001 起，episode 內固定），延遲值沿用被移除者。
  - **A3 宣稱錨點 UE**：把 k 個當窗**只**出現於錨點之 UE 加入 j 之報表，延遲值 = j 當窗原始延遲之平均（不改 j 之平均）。
  - **A4 宣稱 peer 之 UE**：把 k 個當窗出現於其他 mmWave cell、未出現於 j 之 UE 加入 j 之報表，延遲值同 A3。
- 量測區間：[t0, t0 + L + 10)（含攻擊結束後 10 窗，因停留計數之效果可能延後出現）。

**指標**
- **主預測 P1（UE 層級）**：D1 證據事件數 = 量測區間內 Σ_窗 |{UE : `d1_ue_levels` 之 level ≥ 1}|（另報 level 加權：weak 1、strong 2）。ΔUE = 注入 − 乾淨。**預測：所有 episode ΔUE ≤ 0**（攻擊者只能重設停留計數，不能延長）。
- **歸屬（描述）**：Δ_j = 節點 j 之註記中 `H_i_D1 ∈ {strong, weak}` 之 (節點, 窗) 數變化；Δ_others = 其他節點合計。A4 預期可能 Δ_j ≠ 0（`last_serving` 取最小 cell id），此為歸屬轉移，不違反 P1。

### 8.9 E21-S4 規格 v1（2026-11-12 使用者同意；本節先於任何實作與執行 commit）：對學習型攻擊者之驗證（§8.6 之 (ii)）
