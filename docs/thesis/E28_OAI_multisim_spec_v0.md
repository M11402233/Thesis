## 1. 目標（由弱到強，逐級）
| 級 | 要回答的問題 | 需要 |
|---|---|---|
| L1 語意 | OAI 之 KPM 時間語意（起訖點、窗口、重置、缺值、多訂閱）逐項釐清，與 ns-O-RAN、3GPP 對照 | 1 DU、1–2 UE（已部分完成） |
| L2 C_i 前提 | 無流量 UE 是否列入、訂閱條件是否只回部分 UE、缺報與不存在能否區分、換手後 UE 識別碼能否跨節點對應 | 1 CU＋2 DU、≥2 UE、手動 F1 換手 |
| L3 S_i 可行性 | 同時段多個 cell 之延遲能否形成 peer 比較；乾淨誤報與竄改偵測是否與 ns-O-RAN 同方向 | 1 CU＋≥3 DU、每 DU ≥2 UE、延遲語意對齊（1 s 窗內 SDU 平均） |

**主張上限**：L1／L2 可支持「方法所需資訊可由實作產生」；L3 才可能支持「第二個實作上同方向」。任何一級都**不**等於「OAI 已驗證 C_i／S_i」，除非該級之驗收全部通過。

## 2. 已知限制（本地 OAI `1d479b2aa9` 之文件與原始碼）
- **換手只支援 F1（同一 CU、不同 DU）**，而且 OAI UE **不做量測回報**，無法自行觸發換手，只能經 telnet **手動觸發**（`doc/handover-tutorial.md:24–28`）。所以 H_i 類的「成員轉移」在 OAI 上只能由人為排程，不是由移動產生。
- **rfsim 不要求即時**（無線時間可以比實際時間慢），但 E2 報告週期是**實際時間**計時（`period_ms = 1000`）。CPU 不足時，兩者會脫鉤，「1 秒窗」的意義就改變了。須以 CPU 足夠為前提，或在報告中記錄無線時間。
- **延遲語意不同**：OAI 是最近 100 ms 平均，ns-O-RAN 是 MAC 交付到 UE 收到之累計平均，3GPP 是 RLC 內排隊時間（見 `report_semantics_spec_v0.md` §5.5）。L3 之前須先改 OAI E2 agent，把延遲改為「1 s 窗內 SDU 平均」並附樣本數，**否則不可比**。
- **多訂閱瓜分增量**（T2）：每個節點只能有一個 KPM 訂閱者，或改 agent 改成依訂閱各自相減。
