## 2. 不規則攻擊（IRR）之規則

| 項目 | 規則 | 依據／理由 |
|---|---|---|
| 起點 | t0 ~ 均勻整數 U{30, …, 150} | Q1-c；前 30 s 保留為乾淨段；最晚 150 s 起，與既有 t0 = 150 對齊上限 |
| 開／關 | 自 t0 起 ON、OFF 交替；ON = 3 + Geom(平均 7) ⇒ 平均 10 s；OFF = 3 + Geom(平均 17) ⇒ 平均 20 s；最後一段截於 299 s | Q1-b；幾何分布為指數分布之離散版本 ⇒ **攻擊段之起點為（位移後之）Poisson 過程**；最短 3 s 使每段長於 L_C = 2（R9），不只測已知之 D = 1 盲點 |
| 幅度 | 每段獨立抽倍數，段內固定：down ~ U[0.6, 0.9]；up ~ U[1.2, 1.5] | Q2-b；範圍同既有階躍（R1、R3） |
| 方向 | down、up 兩族分開，**各自一張圖** | Q3 |
| 欄位 | 只改受攻擊 cell 之每個 UE delay（× f），C_i／H_i 欄位不動 | 同 R3 |
| 知識 | 不知道 τ_S、不看判定、不看 peer 中位數 ⇒ 一般攻擊者 | Q5-a |
| 重複 | 亂數 seed r = 0…9；排程由 SHA-256(資料 seed, 起始 cell, r, 族, 模式) 決定性產生 | Q7 |

**節點數（Q4 a、b 都做）**

| 模式 | 規則 | 每族 episode 數 |
|---|---|---|
| a. single | 1 個被攻陷節點；cell 2–8 輪流 | 8 seed × 7 cell × 10 r = 560 |
| b. multi | 第一個節點於 t0 被攻陷，之後到達間隔 = 1 + Geom（平均 60 s）⇒ Poisson 到達；至多 4 個（= R4 之 m 上限）；cell 自 2–8 不放回均勻抽；被攻陷後不復原；各節點獨立 ON／OFF 與倍數、方向相同。敏感度：平均到達間隔 30／60／120 s | 每個到達間隔 560 |

**時間尺度之限制（須寫入正文）**：一個 run 只有 300 s，「兩天一個、五分鐘一個」之真實頻率無法模擬；b 之 30／60／120 s 為**壓縮時間尺度之壓力測試**，不是對真實被攻陷頻率之主張。真實頻率之依據【待補文獻】。

自我檢查（不調參數，僅報告）：未截斷 ON 平均 9.7 s、OFF 平均 18.6 s（最後一段截斷使樣本偏短）；t0 平均 91.7 s；t0 後攻擊時間占比平均 0.354（範圍 0.093–0.773）。multi 達 4 個節點之比例：30 s 1,075／1,120、60 s 770／1,120、120 s 286／1,120。

## 3. 學習型攻擊者須「懂門檻」（Q5）

- E19 之 O-full 每秒取得**自身判定**（R6），加上自身上報與上一秒 peer 中位數，可由回饋學到門檻位置 ⇒ 以 **O-full 為「懂門檻」之學習型攻擊者**；O-outcome 為不懂者之對照。
- 不給同秒 peer 中位數（R8）。
- **使用者決定（2026-11-19）：先用 O-full 代表「懂門檻」之學習型攻擊者**；白箱變體（觀測中明示 τ_S 與尺度 s，須重新訓練）不做，除非老師要求「明確知道門檻」。

## 4. 評估（Q6 = c）

防守固定：P1 證據、P3 政策、P4 評估不變，只換 P2（Rule = B1 嚴重度序；Rule + DRL = 只能更嚴之 DRL）。兩者於乾淨資料之誤拒率一併報告。

| 指標 | 定義 |
|---|---|
| **偵測增量 ΔDR（主，使用者 2026-11-19 選 a）** | 配對：同一 (seed, node, s) 被竄改時判為 low-trust／rejected 之比例 − 乾淨時之比例（同 anchor）。原因：乾淨資料本身即有 53.5% 判為 low-trust／rejected（開發試跑，§7），未扣除則各列皆貼近底量 |
| ΔDR_rej（輔，b） | 同上，只算 rejected |
| DR（並列） | 未扣乾淨之原始比例 |
| 攻擊者得利（down） | 被竄改之秒中 lured 之比例（R7；C_strict） |
| 攻擊者得利（up） | 被竄改之秒中，乾淨時最佳 cell 為攻擊 cell、但 steering 改選他者之比例 |
| 傷害 | regret（同 RQ3 口徑） |

只報 DR 不夠：攻擊越少，被抓次數自然越少；得利與 regret 用來抵銷此效果。

## 7. 開發試跑（2026-11-19；**不得引用**）

- 條件：D-30、`ZT_DELAY_SOURCE=reconstructed`（第一階段區間延遲，cell 歸屬仍為最後 PDU 所在 cell）、severity、uebound、10 r × 8 seed；`run_E29_irregular.py --dev`，輸出 `data/results/phase2/E29/dev_d30/`（654 s）。
- 流程檢查：乾淨資料 rejected 844／15,534、trusted 46.5%，與 v12.1 第一階段 xApp 重跑逐數相同 ✓。
- 觀察（僅供設計討論）：(1) 乾淨 flag 率 0.535，階躍與不規則之 DR_flag 0.53–0.60 幾乎等於乾淨水準，只有漂移明顯較高（0.76–0.90）⇒ DR_flag 主要反映 D1 綁定之 low-trust 底量，須改報「相對乾淨之增量」或以 rejected／S_i 證據為主；(2) 調高攻擊在嚴格准入下攻擊者得利反而上升（被排除正合攻擊者「把流量推走」之目的）；(3) 除漂移外，嚴格准入之 regret 高於不驗證（乾淨誤排除之代價大於攻擊傷害）。
- 改用配對 ΔDR 後重跑（`dev_d30_v2/`，不得引用）：調低之階躍與不規則 ΔDR −0.015～+0.001（等於或低於乾淨），漂移 ↓ 0.25／0.35；調高之不規則 +0.045～0.050、×1.5 +0.092、漂移 ↑ 0.216。即開發資料上規則版對「調低」之階躍與不規則攻擊幾乎無偵測力。
