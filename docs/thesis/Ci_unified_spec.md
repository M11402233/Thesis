# C_i 實驗統一規格（v1，2026-10-06，事前登記）

## 目的

第四章改用單一資料集 D-28（28 UE × 4 seed × 300 s）後，C_i 之實驗須與 S_i／H_i／xApp 使用**同一判定規則、同一資料載入、同一注入時點定義、同一彙總方式**。本規格於 D-28 資料產出前登記；D-28 之結果不得回頭修改本規格（若須修改，另立 v2 並揭露）。

## 現況差異（修訂前）

| 項目 | 修訂前之 C_i 腳本 | S_i／H_i／xApp |
|---|---|---|
| 判定規則 | `run_Ci_experiments.py`（E1–E5）：`cardinality.py` 之 5 % 容忍帶 + 高斯衰減分數 + 分級門檻；`run_Ci_extended_E6E8.py`、`make_fig_Ci_final.py`：各自之嚴格相等 | `zt_kpm_xapp.verify_ci`（嚴格相等）+ `fuse`（`R1_CI_VETO`／`R1_CI_PENDING`，L_C = 2） |
| 資料載入 | 三種各自實作之解析器 | `zt_kpm_xapp.TraceReplaySource` |
| N_known | 各腳本寫死 7 | xApp 寫死 7 |
| 注入時點 | 「後半段窗」、`len//2`、或固定第 30 窗（僅適用 60 s 資料） | 序列中點（實際秒） |
| 資料路徑 | 寫死 D-C | 寫死 D-SH |

**容忍帶之問題**：5 % 容忍帶於 N = 7 時下界為 6.65，少 1 個 UE 即出界，等同嚴格相等（正文 4.6.1 依此宣稱布林斷言）；於 N = 28 時下界為 26.6，**少 1 個 UE 仍在帶內**，將使 E2 之 −1 虛減不被偵測。故統一採嚴格相等，與正文 4.6.1 及 xApp 一致。

## 統一定義

1. **規則**：唯一實作為 `zt_kpm_xapp.verify_ci`（N_total ≠ N_known 即違反）與 `fuse` 之 C_i 分支（連續違反 run ≥ L_C → `R1_CI_VETO`／rejected；否則 `R1_CI_PENDING`／low-trust）。實驗腳本不得另行實作判定。
2. **載入**：`zt_kpm_xapp.TraceReplaySource`；窗 = 實際秒。
3. **N_known**：命令列參數；預設由資料推得（檔案中相異之已登記 IMSI 數，IMSI < 9000）；若同時給 `--ues`，須等於 7 × ues，否則停止。執行時同步設定 `zt_kpm_xapp.N_KNOWN`。
4. **LTE 錨點**：CellId 1；mmWave cell 由資料推得（≠ 1 者）。
5. **注入時點**：序列中點 w_mid = 窗序列之第 ⌊n/2⌋ 個實際秒；「後半段」= 所有 ≥ w_mid 之窗。E4 之 early／mid／late 為窗序列三等分。
6. **偽造 IMSI**：9001 起；替換時被刪之真 IMSI 取當窗編號最小者（與修訂前相同，確定性）。
7. **彙總**：主表為合併計數（偵測數／測試數）；另列逐 seed 範圍。樣本單位明示為 (seed, 窗) 或 (seed, 起點)。

## 實驗（編號沿用正文）

| 代號 | 內容 | 單位 |
|---|---|---|
| E0 | 乾淨資料逐窗 N_total 分布、違反數 | (seed, 窗) |
| E1 | 灌水 +k（k = 1…6），後半段每窗；違反率；自 w_mid 起至首次違反、首次 rejected 之延遲 | (seed, 窗)；延遲以 seed 為單位 |
| E2a | 全域壓制 −k（k = 1…4），後半段每窗 | (seed, 窗) |
| E3 | 守恆式替換 +2／−2，後半段每窗 | (seed, 窗) |
| E4 | 灌水 +3 於 early／mid／late 三段 | (seed, 窗) |
| E5 | 乾淨／+1 灌水／全域 −1／守恆式替換，全部窗逐一注入 | (seed, 窗) |
| E6 | 持續 D ∈ {1, 2, 3, 5} 窗之 +1 灌水，起點 = 後半段每一秒（起點後須有 D 窗且其前一窗 C_i 正常）；是否升級 rejected | (seed, 起點) |
| E7 | 不精確替換（同修訂前之 10 組 (假, 真)），全部窗 | (seed, 窗) |
| E8 | 單一 O-DU 虛減之攻擊面：(窗, UE) 掛載型態、逐 cell 每窗可抹除 UE 數與無目標窗比例；單點抹除之條件偵測率 | (seed, 窗, UE)／(seed, 窗, cell) |

E6 由「每 seed 一個起點」改為「每 seed 後半段每一秒為起點」，以使 4 seed 之資料仍有足夠之測試數；此為**設計變更**，正文須揭露。

## 內建檢查

1. **舊版重現（legacy 模式，D-C、N = 7）**：以修訂前之注入點重跑，須重現 `Ci_experiment_results.json`（E0 600 窗、全 7；E1–E4 之違反與否與舊分數 < 1 一致；E5 300 攻擊窗全偵測）與 `Ci_extended_E6E8.json`（E6、E7、E8 全部數值）逐項相同。
2. **載入一致**：每個檔案、每個窗，`TraceReplaySource` 之 IMSI 聯集與修訂前解析器相同。
3. **規則一致**：所有判定經 `zt_kpm_xapp.verify_ci`／`fuse`；以獨立之 `len(union) != N_known` 重算，逐窗相同。
4. **N_known 一致**：推得之 N_known 於每個 seed 相同；若給 `--ues`，= 7 × ues。
5. **容忍帶揭露**：輸出記錄 5 % 帶於該 N 下可容忍之缺漏 UE 數（N = 7：0；N = 28：1），不作為判定依據。

任一檢查不符即停止、不寫檔。

## 不變之處

- C_i 之定義（4.6.1）、L_C = 2、LTE 錨點必含。
- 舊腳本與舊輸出保留不動，僅供附錄對照。
